# Repository orientation

This is a research and architecture repository with a working controller app for bounded, subscription-only runs of several official AI CLIs (today Codex and Claude Code in WSL). General reliability and quality improvement are not established. What has been observed changes often, so the current state lives in [NEXT-SESSION.md](NEXT-SESSION.md); this file holds rules. It is the one rule file for every agent: Claude Code loads it through [CLAUDE.md](CLAUDE.md), Codex reads it directly, and any other assistant should be given it.

## Several sessions share this repository

The user works with several AI sessions (Claude, Codex, ChatGPT and others) that cannot see each other's conversations. The repository is the only thing they share, so every session follows [docs/COLLABORATION.md](docs/COLLABORATION.md). In short:

- **GitHub is the only shared surface.** Web-chat sessions (ChatGPT on the web, for one) see GitHub and nothing on the user's PC; plugins can widen that, and such a session states its surface and follows the PC rules ([collaboration rules](docs/COLLABORATION.md) §1). Push every commit's branch right away, merge finished CI-green work into `main` without delay, and move PC-only observations into repository files.
- **Inside the Claude desktop app on Windows** (a Microsoft Store/MSIX package), a new folder you create under `%LOCALAPPDATA%` can land in the app's private store and stay invisible to the user's own terminal. Install outside AppData, run CLIs through `tools/v04-01/fresh-shell.ps1`, and check with `tools/v04-01/check-versions.ps1`. [docs/SETUP.md](docs/SETUP.md) lists the other traps (stale PATH, Git Bash rewriting paths, codex waiting on stdin).
- **Start:** `git fetch --all --prune`, then check open pull requests and unmerged remote branches (`git branch -r --no-merged origin/main`) before trusting [NEXT-SESSION.md](NEXT-SESSION.md). If the handoff does not list an open PR you can see, the handoff is stale.
- **Branch and PR:** work on `<agent>/<topic>-<YYYYMMDD>` (`claude`, `codex`, `chatgpt`, `agy`, `human`) and propose through a pull request. Do not push to `main` unless the user says so in that session; the one standing exception is a Claude session merging finished CI-green work, which the user has allowed ([NEXT-SESSION.md](NEXT-SESSION.md) §2 item 8). Do not push to another session's branch; build on it or wait, and open the pull request against `main` even then (a PR that targets another PR's branch can be closed when that branch is deleted on merge).
- **Say what you could reach:** your PR states whether you worked on the user's PC (which one), in a web container, or on GitHub only, and whether you saw the CLIs yourself. Record environment facts only when you observed them there; otherwise write "not checked" and leave earlier records alone.
- **Correct at the source:** fix a wrong statement in the file that makes it, and say what was wrong and why in the commit and the relevant record. Do not edit dated records (`docs/reviews/`, `docs/handoff/`, `docs/experiments/`, FINAL_REVIEW, VALIDATION); annotate them from their index.
- **No restated counts:** living documents do not state test, source or commit counts. The CI log and the registries hold them; CI rejects restated counts and stale `F01–F<n>` ranges.
- **Keep it from piling up:** living documents say only what is true now (history belongs to pull requests, git and dated records), a rule file holds rules rather than status, each fact has one home that others link to, and a tool stays only while something current uses it — its own tests and README do not count. Before adding a rule or a check, go through [collaboration rules](docs/COLLABORATION.md) §7. CI holds the handoff, this file and the collaboration rules to size budgets and checks every tool's users ([`tests/test_accumulation.py`](tests/test_accumulation.py)); when a budget trips, remove history, finished items and duplicates instead of raising it.
- **Finish:** update `NEXT-SESSION.md` in the same PR (its section layout is checked by CI; §3 keeps only work in progress and the PR that brought this version, worded so it stays true before and after the merge), fill the [PR template](.github/pull_request_template.md), and do not call anything passing before you have seen the pull request's CI green. The user merges, or a Claude session does once CI is green (the handoff's §2 item 8). GitHub deletes a merged pull request's branch by itself; never pass `--delete-branch` to `gh pr merge` for another session's pull request, because gh then removes that session's worktree ([collaboration rules](docs/COLLABORATION.md) §5).

## Project rules

- **Start with [NEXT-SESSION.md](NEXT-SESSION.md).** It carries the current state, what the user has settled, work in progress and the next task. On a computer that has not run this repository before, follow [docs/SETUP.md](docs/SETUP.md) first. Live runs use only observation records registered on this machine ([`app/registration.py`](app/registration.py)); never register a record observed on another machine.
- Current architecture: [v0.4](docs/architecture/v0.4/README.md). It adds frontier-model independent reasoning, bounded cross-review and evidence-based synthesis alongside economy routing. Difficult planning and evaluation may also use strong models. The [v0.4 HANDOFF](docs/architecture/v0.4/HANDOFF.md) is a 2026-09-22 snapshot, not the current state.
- Preserve [v0.3](docs/architecture/v0.3/README.md) native-harness/accounting foundations and [v0.2](contracts/v0.2/README.md) contracts. Architecture v0.4 is not a production wire-schema upgrade.
- Official native subscription CLIs first; paid API/extra-credit fallback requires opt-in. Antigravity agy is not Gemini CLI. Jev-like components remain optional.
- D10-D18 map to F01–F31 in [new sources](docs/architecture/v0.4/sources.json); D01-D09 and E01-E31 remain in v0.3. Distinguish primary-source inspection, vendor reports, abstract-only evidence and project proposals. Add a registry entry only after reading the primary source yourself; review-local IDs such as `R01` are not registry entries. The [evidence follow-up](docs/architecture/v0.4/EVIDENCE_FOLLOWUP.md) holds the PAL correction and newly screened research.
- Check [validation scope](docs/architecture/v0.4/VALIDATION.md), the [final review](docs/architecture/v0.4/FINAL_REVIEW.md), the [external review fixes](docs/architecture/v0.4/REVIEW_FIXES.md) and the [review index](docs/reviews/README.md). Passing offline tests does not establish model quality, citation truth, actual entitlement, sandbox safety or runtime budget enforcement. `check_frontier_protocol.validate()` checks a recorded disposition; it does not compute one.
- [`core/`](core/README.md) holds the execution pieces (shell-free CLI runner, read-only discussant adapters, environment and isolation policies, membership decisions); [`app/`](app/README.md) holds the controller, the ledger, mock mode and the explicit `--live-cli` / `--live-config` connections. Keep these invariants: neither exit 0 nor an answer is success by itself; a timeout, an unconfirmed tree, or an exit 0 with commands rejected on stderr is not success. `core.adapters.interpret` supplies the CLI outcome; the controller separately enforces input delivery, whole-tree termination (`tree_confirmed_empty` — `unit_confirmed_empty` is not enough, and a plain POSIX process group cannot confirm it) and its acceptance/reveal rules. Context-unverified opt-in never counts toward independent quorum. Model synthesis runs only after reveal, and its verbatim quote check is neither semantic agreement nor factual verification. What has been observed live, and on which machine, is in [NEXT-SESSION.md](NEXT-SESSION.md) §1.
- The user treats every model call, install and fix the task needs as approved (merging stays as in Branch and PR above) ([NEXT-SESSION.md](NEXT-SESSION.md) §2 item 22), so do not stop to ask; stay subscription-only, give each call a new ledger and cap, record the result, and stop any server or process you started because the user cannot see the terminal.
- Run checks from the repository root: `python -m unittest discover -s tests -v`. Without `jsonschema` the schema-dependent tests skip rather than fail; a skip is not a pass. [CI](.github/workflows/checks.yml) runs every check on each pull request and on `main`, and by hand from the Actions tab.
- **Never bulk-edit these documents through PowerShell `Get-Content`/`Set-Content`.** On Windows PowerShell 5.1 that round trip reads BOM-less UTF-8 as the ANSI codepage and writes a BOM, replacing Korean text with `?`. It has already destroyed three documents here. Use your editing tool, or `[IO.File]::ReadAllText`/`WriteAllText` with an explicit `[Text.UTF8Encoding]::new($false)`. Install the guard once with `git config core.hooksPath .githooks`; [`tools/check_encoding.py`](tools/check_encoding.py) also runs in CI, and neither catches plausible-but-wrong Hangul from a CP949 misread.
- Evidence registries obey [contracts/sources.schema.json](contracts/sources.schema.json). Every entry needs a non-empty `limits`/`limitations` and a dating field; write `"published": null` when the date is unknown instead of omitting it.
- The shell's design system lives in [design/](design/README.md) and mirrors a published artifact one file at a time; change the source here, run `python tools/validate_design_tokens.py`, then publish. Only a Claude session can publish that artifact; any other session that changes `design/` marks "artifact not synced" in its PR and in the handoff. Never leave the two sides diverged without saying so.
- Recheck installed versions, effective permissions, authentication/funding and model availability before wiring adapters; the [V04-01 runbook](docs/experiments/v04-01-inventory/README.md) is the procedure. Never copy credentials, environment values or sensitive raw traces into research artifacts.
- Preserve blind first drafts, unresolved counterevidence and explicit call/quorum limits. Agreement is not verification. Save bounded progress and next steps in commits; do not feed the whole archive into each agent prompt.
