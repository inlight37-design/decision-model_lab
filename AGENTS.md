# Repository orientation

This is a research and architecture repository with offline synthetic checks and an explicit single-CLI live pilot, not a validated multi-provider orchestrator. It is the one rule file for every agent: Claude Code loads it through [CLAUDE.md](CLAUDE.md), Codex reads it directly, and any other assistant should be given it.

## Several sessions share this repository

The user works with several AI sessions (Claude, Codex, ChatGPT and others) that cannot see each other's conversations. The repository is the only thing they share, so every session follows [docs/COLLABORATION.md](docs/COLLABORATION.md). In short:

- **GitHub is the only shared surface.** Web-chat sessions (ChatGPT on the web, for one) see GitHub and nothing on the user's PC. Push every commit's branch right away, merge finished CI-green work into `main` without delay, and move PC-only observations into repository files.
- **Inside the Claude desktop app on Windows** (a Microsoft Store/MSIX package), a new folder you create under `%LOCALAPPDATA%` can land in the app's private store and stay invisible to the user's own terminal. Install outside AppData, run CLIs through `tools/v04-01/fresh-shell.ps1`, and check with `tools/v04-01/check-versions.ps1`. The V04-01 runbook lists the other traps (stale PATH, Git Bash eating backslashes, codex waiting on stdin).
- **Start:** `git fetch --all --prune`, then check open pull requests and unmerged remote branches (`git branch -r --no-merged origin/main`) before trusting [NEXT-SESSION.md](NEXT-SESSION.md). If the handoff does not list an open PR you can see, the handoff is stale.
- **Branch and PR:** work on `<agent>/<topic>-<YYYYMMDD>` (`claude`, `codex`, `chatgpt`, `agy`, `human`) and propose through a pull request. Do not push to `main` unless the user says so in that session; the one standing exception is a Claude session merging finished CI-green work, which the user has allowed ([NEXT-SESSION.md](NEXT-SESSION.md) §2 item 8). Do not push to another session's branch; build on it or wait, and open the pull request against `main` even then (a PR that targets another PR's branch can be closed when that branch is deleted on merge).
- **Say what you could reach:** your PR states whether you worked on the user's PC (which one), in a web container, or on GitHub only, and whether you saw the CLIs yourself. Record environment facts only when you observed them there; otherwise write "not checked" and leave earlier records alone.
- **Correct at the source:** fix a wrong statement in the file that makes it, and say what was wrong and why in the commit and the relevant record. Do not edit dated records (`docs/reviews/`, `docs/handoff/`, `docs/experiments/`, FINAL_REVIEW, VALIDATION); annotate them from their index.
- **No restated counts:** living documents do not state test, source or commit counts. The CI log and the registries hold them; CI rejects restated counts and stale `F01–F<n>` ranges.
- **Finish:** update `NEXT-SESSION.md` in the same PR (its section layout is checked by CI), fill the [PR template](.github/pull_request_template.md), and do not call anything passing before you have seen CI green. The user merges, or a Claude session does once CI is green (the handoff's §2 item 8). Whoever merges deletes the merged branch; a session that can push only its own branch runs the manual `prune-merged-branches` workflow instead, which deletes only branches fully merged into `main`, and says so in the handoff if it cannot ([collaboration rules](docs/COLLABORATION.md) §5).

## Project rules

- **Start with [NEXT-SESSION.md](NEXT-SESSION.md).** It carries the current state, what the user has settled, work in progress and the next task. The per-version [v0.4 HANDOFF](docs/architecture/v0.4/HANDOFF.md) is the next stop.
- Current architecture: [v0.4](docs/architecture/v0.4/README.md). It adds frontier-model independent reasoning, bounded cross-review and evidence-based synthesis alongside economy routing. Difficult planning and evaluation may also use strong models.
- Preserve [v0.3](docs/architecture/v0.3/README.md) native-harness/accounting foundations and [v0.2](contracts/v0.2/README.md) contracts. Architecture v0.4 is not a production wire-schema upgrade.
- Official native subscription CLIs first; paid API/extra-credit fallback requires opt-in. Antigravity agy is not Gemini CLI. Jev-like components remain optional.
- D10-D18 map to F01–F31 in [new sources](docs/architecture/v0.4/sources.json); D01-D09 and E01-E31 remain in v0.3. Distinguish primary-source inspection, vendor reports, abstract-only evidence and project proposals. Add a registry entry only after reading the primary source yourself; review-local IDs such as `R01` are not registry entries.
- Read the [evidence follow-up](docs/architecture/v0.4/EVIDENCE_FOLLOWUP.md) for the PAL correction and newly screened research.
- Check [validation scope](docs/architecture/v0.4/VALIDATION.md), the [final review](docs/architecture/v0.4/FINAL_REVIEW.md), the [external review fixes](docs/architecture/v0.4/REVIEW_FIXES.md) and the [review index](docs/reviews/README.md). Passing offline tests does not establish model quality, citation truth, actual entitlement, sandbox safety or runtime budget enforcement. `check_frontier_protocol.validate()` checks a recorded disposition; it does not compute one.
- [`core/`](core/README.md) holds the execution pieces: a shell-free CLI runner, read-only discussant adapters, environment and isolation policies, and membership decisions. The runner reports tracked-unit termination (`unit_confirmed_empty`) separately from whole-tree termination (`tree_confirmed_empty`); a plain POSIX process group cannot confirm the latter. [`app/`](app/README.md) contains the controller, mock mode and explicit `--live-cli` / `--live-config` provider connections with inventory checks and journal-backed launch budgets. A [bounded Codex/Claude parallel run and account-limit UI](docs/reviews/2026-09-24-windows-live-completion/README.md) were observed on the user’s local WSL; the exact Claude Read/input revision now has active permission-denial evidence, while context independence remains unverified. Context-unverified opt-in never counts toward independent quorum. The [first live Codex server response](docs/reviews/2026-09-24-live-cli-pilot/README.md) was accepted and revealed on aux-pc WSL; independence and the served model remain unverified. A claude session [reproduced it](docs/reviews/2026-09-24-live-pilot-replication/README.md) with its own ledger; both one-call budgets are spent. Offline extractive synthesis, source comparison and qualified decision cards are available, while real model synthesis and factual verification are not. A timeout, an unconfirmed tree, or an exit 0 with commands rejected on stderr is not success. `core.adapters.interpret` supplies the CLI outcome; the controller must separately enforce input delivery, whole-tree termination and its acceptance/reveal rules. The user treats every model call, install and fix the task needs as approved (merging stays as in Branch and PR above) ([NEXT-SESSION.md](NEXT-SESSION.md) §2 item 22), so do not stop to ask; stay subscription-only, give each call a new ledger and cap, record the result, and stop any server or process you started because the user cannot see the terminal.
- Run checks from the repository root: `python -m unittest discover -s tests -v`. Without `jsonschema` the schema-dependent tests skip rather than fail; a skip is not a pass. [CI](.github/workflows/checks.yml) runs every check on push and pull request.
- **Never bulk-edit these documents through PowerShell `Get-Content`/`Set-Content`.** On Windows PowerShell 5.1 that round trip reads BOM-less UTF-8 as the ANSI codepage and writes a BOM, replacing Korean text with `?`. It has already destroyed three documents here. Use your editing tool, or `[IO.File]::ReadAllText`/`WriteAllText` with an explicit `[Text.UTF8Encoding]::new($false)`. Install the guard once with `git config core.hooksPath .githooks`; [`tools/check_encoding.py`](tools/check_encoding.py) also runs in CI, and neither catches plausible-but-wrong Hangul from a CP949 misread.
- Evidence registries obey [contracts/sources.schema.json](contracts/sources.schema.json). Every entry needs a non-empty `limits`/`limitations` and a dating field; write `"published": null` when the date is unknown instead of omitting it.
- The shell's design system lives in [design/](design/README.md) and mirrors a published artifact one file at a time; change the source here, run `python tools/validate_design_tokens.py`, then publish. Only a Claude session can publish that artifact; any other session that changes `design/` marks "artifact not synced" in its PR and in the handoff. Never leave the two sides diverged without saying so.
- Recheck installed versions, effective permissions, authentication/funding and model availability before wiring adapters; the [V04-01 runbook](docs/experiments/v04-01-inventory/README.md) is the procedure. Never copy credentials, environment values or sensitive raw traces into research artifacts.
- Preserve blind first drafts, unresolved counterevidence and explicit call/quorum limits. Agreement is not verification. Save bounded progress and next steps in commits; do not feed the whole archive into each agent prompt.
