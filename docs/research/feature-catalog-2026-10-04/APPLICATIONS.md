# 우리 앱으로 묶어 볼 적용안

[목록 입구](README.md) · [Hermes](HERMES.md) · [다른 프로젝트](OTHER-PROJECTS.md)

2026-10-04 기준 제안이다. 아래 모두를 만들기로 결정한 것은 아니다. 사용자가 “그때 본 기능을 써볼까”라고 했을 때 바로 작은 작업으로 바꿀 수 있도록 묶었다. 노력은 상대적이며, 실제 모델 효과를 주장하지 않는다.

## 1. 자주 쓰는 팀과 작업 양식

**사용 모습:** 홈에서 “논문 비교”를 고르면 팀원·역할·기억 켜기·자료 요구·출력 형식이 채워진다. 사용자는 질문과 자료만 바꾸고 입력 확인 뒤 실행한다. 프리셋을 복제해 “빠르게”와 “자세히”를 따로 둔다.

- 후보: H02·H19·H20·H32, O26·O32.
- 기존 접점: `app/roles.py`, `app/static/role-board.js`, `app/store.py`. 현재 역할 계약·입력 확인을 재사용한다.
- 첫 조각: 사용자 저장/복제/이름 변경/삭제가 가능한 팀 프리셋. 모델 대신 ID를 저장하고, 사용 불가 모델은 명시한다. 추론 강도 연결은 따로 한다.
- 클라우드 확인: 저장→재로드→미리보기, 이전 설정과 현재 허용 모델 차이, 자료가 빠진 경우. 추가 모델 호출 0.
- 뒤에 할 일: 스킬 묶음과 단계 실행. 프리셋 저장 자체가 모델 호출 승인은 아니다.

## 2. 검색 가능한 작업·결과·기억 서랍

**사용 모습:** “지난번 비교 결과”를 제목·날짜·모델·상태로 찾는다. 기억에 쓰인 발췌에서 원 답과 미해결 지적으로 이동한다. 다운로드와 검색 결과는 원 작업으로 돌아갈 수 있다.

- 후보: H01·H07·H13·H14·H16, O01–O04·O21.
- 기존 접점: `app/memory.py`, `app/store.py`, `app/server.py`, `app/static/role-board.js`, `app/report.py`.
- 첫 조각: 사람용 공개 실행 검색·필터·원문 링크. 모델에게 새 검색 도구를 주는 일과 분리한다.
- 클라우드 확인: 한글 조사·코드명·날짜·중복 실행·빈 결과·봉인 제외·잘림·대량 원장 fixture. 원본을 보존하고 검색 index는 재생성 가능하게 한다.
- 뒤에 할 일: FTS/형태소/RRF, 여러 작업으로 범위 확대, 기억 pin/제외. 먼저 O09의 평가 자료를 만든다.

## 3. 나를 기다리는 일과 완료 수신함

**사용 모습:** 홈에서 “확인 필요”, “끝남”, “문제 있음”만 먼저 본다. 항목에는 현재 상황·다음 행동·관련 결과가 있다. 브라우저를 닫았다 열어도 확인하지 않은 결과를 찾는다.

- 후보: H06·H29·H37, O14·O17·O20·O23.
- 기존 접점: `app/controller.py`의 상태/사건, `app/server.py`, `app/static/role-board.js`.
- 첫 조각: 읽음 상태와 작업 링크가 있는 로컬 수신함. 알림 문구는 규칙으로 만들고 모델을 부르지 않는다.
- 클라우드 확인: 성공·형식 실패·취소·종료 미확인·입력 대기, 새로고침·재연결·중복 사건. 봉인 답의 내용은 알림에 넣지 않는다.
- 뒤에 할 일: browser notification, 외부 메신저, 예약 실행. 외부 전달은 사용자가 고른 목적지와 별도 설정이 필요하다.

## 4. 자료 넣기와 결과 받기를 쉽게

**사용 모습:** PDF·문서·표·URL을 넣으면 추출 미리보기와 빠진 페이지가 보인다. 문서 일부만 선택할 수 있고, 끝나면 보고서·표를 바로 내려받는다.

- 후보: H03·H07·H45–H47·H49·H50, O02.
- 기존 접점: `app/controller.py`의 source snapshot, `app/static/role-board.js`의 파일 입력, `app/report.py`.
- 첫 조각: 파일 일부 선택·크기 표시·변환 미리보기. PDF/DOCX 등은 변환 결과를 UTF-8 자료로 고정하고 원본/변환본을 구분한다.
- 클라우드 확인: 공개 fixture로 표·한국어·스캔 PDF·깨진 파일·대용량·URL 실패. 성공한 텍스트 추출을 원문 전체를 이해한 것으로 표시하지 않는다.
- 뒤에 할 일: OCR·이미지·음성. 외부 처리 여부와 PC 장치 확인은 단계별로 남긴다.

## 5. 기억에서 반복 절차로

**사용 모습:** 잘 끝난 작업에서 “이 방식을 다음에도 쓰기”를 누른다. 목표·입력·단계·완료 기준이 초안으로 나오고 사용자가 고쳐 저장한다. 다음 작업에서 필요한 절차만 고른다.

- 후보: H12·H19–H23, O05–O08·O16·O19.
- 기존 접점: `app/memory.py`, `app/report.py`, 기존 문서함. 실행 이력은 그대로 두고 절차는 별도 판본을 가진다.
- 첫 조각: AI 생성 없이 사람이 쓰는 절차 카드, 출처 실행 링크·pin·보관·복원. 절차 편집은 다음 실행부터 적용한다.
- 클라우드 확인: 본문/참조 파일/허용 역할/판본/길이·실행 중 변경·보관 복원. 격리 팀원에게는 자동 주입하지 않는다.
- 뒤에 할 일: 절차 초안 생성·사용 피드백·중복 추천. 자동 회고·통합은 호출 상한과 원문 복원 가능성을 갖춘 뒤 선택한다.

## 6. 교차검토에서 수정 답변까지

**사용 모습:** 지적마다 수용/반박/보류를 정하고, 수용한 지적을 넣어 새 답을 받는다. 옛 답·새 답·변경점·아직 남은 문제를 나란히 본다.

- 후보: H05·H28, O11–O15.
- 기존 접점: `app/cross_review.py`, `app/controller.py`, `app/report.py`, 검토 처분 원장.
- 첫 조각: “수정 답변 요청”의 입력·출력·원본 판 연결과 모의 화면. 새 답은 새 판이며 기존 수용 답을 덮지 않는다.
- 클라우드 확인: 수정 실패·잘못된 원문 인용·기존 지적의 소실·새 판에 옛 검토 재사용 방지·호출 예약/취소.
- PC 확인: 같은 범위의 지적을 실제 모델이 반영하는지, 새 오류·반례 소실이 생기는지. 실제 효과는 그 뒤 판단한다.

## 7. 반복 일을 맡기되 상태 확인은 코드로

**사용 모습:** “매주 이 자료 비교”, “자료가 바뀌면 검토”를 저장한다. 다음 실행 시각·호출 상한·마지막 결과가 보이고 언제든 멈춘다. 모델 없는 CI/만료 확인은 별도 종류로 표시한다.

- 후보: H24·H27·H33–H37, O25·O27.
- 기존 접점: `app/run.py`, 준비 조회·원장 예약. scheduler를 controller와 별개 성공 판정자로 만들지 않는다.
- 첫 조각: 예약 설정·대기/blocked 상태와 fake clock 모의 흐름. 실제 daemon을 상시 켜는 것은 후속 작업이다.
- 클라우드 확인: 시간대·중복 tick·실행 중 재시작·기기 관측 만료·작업 삭제·기존 실행 소유권·총 호출 상한.
- 뒤에 할 일: 실제 구독 CLI 예약, PC가 꺼졌을 때 처리, 원격 executor. goal/loop/cron 모두를 동시에 만들 필요는 없다.

## 8. 앱 밖에서도 이어 보기

**사용 모습:** 다른 기기에서는 상태·보고서만 열고, 실행 기기는 따로 표시한다. 장기 실행을 명시적으로 유지할 때만 창을 닫아도 계속한다.

- 후보: H38–H44·H57, O15·O22.
- 첫 조각: API 계약·가짜 remote executor·읽기 전용 결과 조회. 사용자 PC 연결이나 인증 복사는 이번 문서 작업에 포함하지 않는다.
- 클라우드 확인: 연결 끊김·중복 요청·다른 원장·기기 ID·봉인·취소·재접속. 화면 연결 상태와 실제 실행 상태를 나눈다.
- 뒤에 할 일: 공식 통로의 실제 연결·기기별 관측·인증과 권한. 현재 자동 서버 종료 방침과 달라지는 부분은 구현 카드에서 명시한다.
