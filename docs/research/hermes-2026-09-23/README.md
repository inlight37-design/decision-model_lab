## 결론

**Hermes를 우리 앱의 기반으로 갈아타기보다, 실행기 신뢰성·필요 시 불러오는 스킬·범위가 명확한 기억과 실행 기록을 선별해 가져오는 편이 맞다.** 상급 모델의 독립 초안, 주장별 근거 대조, 반례·미합의 보존은 우리 v0.4 설계를 유지한다. Hermes의 MoA나 subagent를 연결했다는 사실만으로 이 조건이 충족되지는 않는다. 근거: [프로젝트 기준 P01–P06](EVIDENCE.md#project), [Hermes 위임 H07](EVIDENCE.md#h07), [MoA H11–H12](EVIDENCE.md#h11).

특히 **“Hermes는 API만 쓰므로 native 하네스를 참고할 곳이 없다”는 결론도 틀리다.** 검토한 판본에는 실제 `codex app-server`를 구동하고 thread/turn·승인·취소·재개를 다루는 코드가 있다. 이 코드는 참고 가치가 높다. 다만 이미 확정한 **exec 우선**을 바꿀 이유는 아니며, 권한 기본값·이벤트 호환 처리·환경변수 상속을 그대로 복사해서도 안 된다. [H08–H09](EVIDENCE.md#h08)

## 가장 중요한 발견과 오해 방지

### 1. 자동 기억을 켜는 것이 곧 협업 품질 향상은 아니다

Hermes는 세션 시작의 기억 snapshot과 프로필 분리를 제공하고, 자식 agent 생성 시 `skip_memory=True`, `skip_context_files=True`를 사용한다. 따라서 “Hermes 자식은 무조건 부모 기억을 모두 받는다”는 설명은 부정확하다. 그러나 같은 생성 코드가 부모의 `prefill_messages`를 전달하고 goal/context를 별도로 받는다. 공유 workspace·검색·MCP까지 포함한 **우리 방식의 blind 독립성은 추가로 검증해야 한다.** [H04](EVIDENCE.md#h04), [H07](EVIDENCE.md#h07)

### 2. 스킬을 만드는 ‘학습’과 모델 가중치 학습을 구분해야 한다

여기서 참고하는 `/learn`·skill 관리 경로는 절차 문서를 만들어 다시 쓰는 것이다. 모델 재학습의 성과를 입증하는 자료가 아니다. 성공한 것처럼 보인 한 번의 실행을 곧바로 전역 지침으로 승격하지 말고, 실패 조건과 원문 근거를 포함한 **검토 가능한 절차 자산**으로 바꾸는 부분을 가져온다. 저장소의 별도 학습·trajectory 기능 전체가 없다는 뜻은 아니다. [H01](EVIDENCE.md#h01), [H03](EVIDENCE.md#h03)

### 3. 문서와 코드가 어긋나는 부분이 실제로 있다

README는 대화 검색에 LLM 요약을 쓴다고 소개하지만, 검토한 `session_search_tool.py`는 LLM 호출 없이 DB 메시지를 반환한다. 반대로 memory 안내의 ‘잘리지 않는 원문’ 설명과 달리, 코드에는 긴 메시지의 잘림 표시가 있다. **‘검색에 별도 LLM 호출이 없다’와 ‘검색 결과 전체가 무손실이며 토큰 비용이 없다’는 다른 주장이다.** [H01](EVIDENCE.md#h01), [H04–H05](EVIDENCE.md#h04)

### 4. MoA는 우리 `cross_check`의 완성품이 아니다

Hermes MoA에서는 합성 모델이 실제 도구 실행 루프를 맡고, 조언 모델은 별도로 호출된다. 기본 조언 주기는 `user_turn`이며 구성에 따라 더 잦아질 수 있다. 일부 조언 실패를 표시하고 계속할 수 있다는 동작은 우리 정족수·구성 축소 정책과 다시 결합해야 한다. 제작자 benchmark를 우리 프로젝트의 품질 개선률로 옮기지 않는다. [H11–H12](EVIDENCE.md#h11)

### 5. 가져올 가치가 가장 큰 것은 화려한 팀 화면보다 실패 처리다

프로세스가 죽기 전에 자식 프로세스를 추적하는 처리, 잘못된 thread/turn의 이벤트를 구분하는 처리, 재개와 새 실행을 구별하는 처리, 실패를 정상 완료로 포장하지 않는 결과 구조가 실제 구현의 좋은 참고점이다. 그래도 코드 존재가 운영 안전성의 증명은 아니므로 mock과 실제 CLI로 확인한다. [H07–H09](EVIDENCE.md#h07)

## 지금 바로 이어갈 작업

**기존 V04-03 준비를 계속한다.** `HP-01 → HP-02 → HP-03`을 mock runner 및 native 문맥·권한 conformance 시험에 반영하고, 실제 독립 답변 pilot을 먼저 통과시킨다. 스킬 저장소·DB·MoA·메신저를 한꺼번에 만들지 않는다. [적용 계획](ADOPTION_PLAN.md)의 통과 조건을 충족한 후보만 차례로 붙인다.

이 조사는 사용자가 별도로 요청한 Hermes 검토다. 기존의 ‘실측 전에 설계 문서만 계속 늘리지 않는다’는 방침을 변경하지 않으며, D01–D18이나 E/F 근거 원장을 새 판으로 승격하지 않는다. 이 조사 안의 `H` 참조는 원장 등록 번호가 아니다.
