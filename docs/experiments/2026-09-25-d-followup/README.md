## 묻는 것

[D 파일럿](../2026-09-24-comparison-pilot/RESULTS.md)이 남긴 세 한계를 푼다.

1. **합성자 교체(L1).** D의 합성자는 Claude였고, 두 초안이 갈린 T1에서 맞힌 쪽도 Claude였다. 합성자를 Codex로 바꿔도 맞는 초안을 고르는가 — 특히 Codex 자신의 초안이 틀렸을 때.
2. **충돌 과제(L2).** D의 설계 과제(T3)는 네 답이 모두 같은 선택·만점이라 조건을 가르지 못했다. 조건끼리 충돌해 모두 지킬 수 없는 설계 과제(T4)에서 답이 갈리는가, 합성이 초안보다 나은가·못한가.
3. **blind 채점(L3).** D의 채점자는 어느 모델의 답인지 알았다. 조건 이름을 가린 채 세 채점자(이 세션, Codex, Claude)가 따로 채점하면 얼마나 일치하는가, 모델 채점자가 제 계열의 답에 더 후한 신호가 있는가.

## 과제와 채점 기준

정확한 질문 글은 [questions.json](questions.json), 채점 기준은 [rubric.md](rubric.md)다. rubric.md는 모델 채점자에게 그대로 준다.

- **T1 계산**(D와 같음): x² + y² = 2026의 양의 정수 순서쌍 수. 정답 2. 판정 `conclusion`·`correct`.
- **T2 코드 결함**(D와 같음): 마지막 창의 평균이 빠진다. 판정 `defect_ok`·`fix_ok`는 D와 같고, 새로 `explanation_ok`를 본다 — 앞의 출력이 틀리거나 한 칸씩 밀린다는 식의 틀린 설명이 없는가(D의 합성이 받아들였던 흠).
- **T4 충돌하는 설계**(새 과제): 12 TB 파일 서버를 매일 밤 00:00–06:00에 1 Gbps 한 줄로 외부에 전체 복사하라는 감사 규정, 예산 0원·운영자 1명·장비 추가 없음, 8시간 복원. 12 TB는 1 Gbps로 약 26.7시간이라 6시간은커녕 하루에도 못 보내고, 외부에서 되받는 복원도 8시간을 넘는다. 여섯 조건을 모두 지키는 방법은 없다. 어느 조건을 바꾸자고 하는지는 채점하지 않고 기록한다. `C1` 전송 불가능, `C2` 복원, `C3` 조용한 위반 없음, `C4` 바꿀 조건 명시, `C5` 뒤집을 조건을 0/1로 매긴다(합 0–5). C1–C3을 객관 항목으로 본다.

## blind 채점 절차

1. 과제 실행이 모두 끝나면 [blind_pack.py](blind_pack.py)가 답을 모은다. 초안은 원문 그대로 둔다. X는 합성의 권고·주장·갈리는 점·반례·미해결을 한 편의 글로 옮기고, 인용(초안 원문)은 넣지 않는다. 모델·회사 이름(Codex, Claude, GPT, OpenAI, Anthropic, Sonnet 등)만 `[가림]`으로 바꾼다. 과제마다 무작위 이름(`T1-xxxx.md`)을 붙이고, 대응표 `key.json`은 묶음 폴더 밖에 둔다.
2. **이 세션이 먼저 채점한다.** 묶음 파일만 읽는다 — 대응표·원장·보고서·드라이버 요약 파일을 열지 않는다. 드라이버가 화면에 찍는 사본에는 초안 길이를 짐작하게 하는 시간·토큰 수가 없다. rubric.md의 출력 모양대로 `grades-session.json`을 쓰고 저장소에 커밋·push한 뒤에야 대응표를 연다.
3. **모델 채점자 둘.** 묶음(답안 파일과 rubric.md)을 공통 자료로 붙인 strict 실행 하나에서 Codex와 Claude가 서로 보지 않고 채점한다. 질문은 questions.json의 `grade`. 채점 원문은 원장에만 두고, [analyze.py](analyze.py)가 JSON만 읽어 점수를 옮긴다. JSON을 읽지 못한 채점자는 "읽지 못함"으로 두고 사람이 옮기지 않는다.
4. **판정은 항목마다 읽힌 채점자의 과반**이다. 과반이 없으면 "갈림"으로 적는다. 채점자별 점수도 모두 싣는다.

## 판정과 결정 규칙

[analyze.py](analyze.py)가 과반 판정에서 아래를 낸다.

- **맞는 초안이 있었는가(oracle):** T1은 P 초안의 `correct`. T2는 `defect_ok`. T4는 C1–C3 항목별로 P 초안 가운데 하나라도.
- **합성 손실:** 맞는 초안이 있었는데 X가 틀림(T1), X가 `defect_ok`를 잃음(T2), P 초안에 있던 C1–C3 항목을 X가 잃음(T4). X의 설명 흠(T2 `explanation_ok` 거짓)은 따로 적고, 같은 흠이 P 초안에 있었는지 함께 적는다. X가 없으면 손실이 아니라 "X 없음"이다.
- **L1(T1):** 두 초안이 갈리고 하나만 맞았을 때 Codex 합성자가 맞는 쪽을 골랐는지와 그 초안의 제공자. 맞힌 쪽이 Claude이고 X가 맞으면 "제 계열 초안이 틀렸는데도 다른 쪽을 골랐다"는 관측 한 건이다. 두 초안이 같으면 "이번 표본으로는 판단할 수 없음"이다.
- **L2(T4):** 다섯 답이 C1–C3 가운데 하나라도 갈렸는가. 안 갈리면 "이번에도 갈리지 않음"만 적는다.
- **L3:** 항목별 채점자 전원 일치 비율, 채점자마다 과반과 다른 수. 제 계열 신호 — T4 합계에서 Claude 채점자와 Codex 채점자가 Claude 답·Codex 답(S·P만, X 제외)에 준 평균의 차이. 표본이 작아 서술만 한다.

결정 규칙:

- **이번 PR에서는 앱 코드를 바꾸지 않고 상한 밖으로 부르지 않는다.** 결과만 기록한다.
- 합성 손실이 하나라도 있으면 지금 권고(실제 합성은 실행마다 켜는 선택, 기본 끔, 원문 대조표와 함께 본다)를 유지할 근거로 적는다. 손실이 없어도 "합성이 낫다"로 일반화하지 않는다.
- 모델 채점자끼리 객관 항목(T1 `correct`, T2 `defect_ok`, T4 C1–C3)에서 갈리거나 제 계열 신호가 보이면, 다음 비교에서 채점자를 두 계열로 두는 것을 기본으로 하자는 후보를 올린다.
- 합성 이름표 순서(D1 = Claude 고정)는 결과와 상관없이 "실행마다 순서를 섞고 기록하기" 후보로 올린다. 앱 변경은 따로 카드로 한다.

- Codex는 답한 모델을 보고하지 않는다(K32). 두 참여자의 문맥 독립성은 [E2](../../reviews/2026-09-25-context-independence/README.md)의 범위다.
- D의 답은 다시 채점하지 않는다.
