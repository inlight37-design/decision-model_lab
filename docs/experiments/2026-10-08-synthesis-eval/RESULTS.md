이 표본에서 관측한 것은 두 가지다.

- **Q1(유일하게 갈린 과제):** Codex 초안은 틀렸다(69001, 정답 20001). Claude 합본은 정답만 남겼다. Codex 합본은 형식 실패였다.

## 형식 실패

앱은 실패한 원문을 보존한다(`raw`, 저장소 밖 결과 JSON). 원인을 원문에서 확인했다.

| 과제 | 합성자 | 원인 |
|---|---|---|
| Q1 | Codex | 초안의 LaTeX 인용(`\(3^{1000} \bmod …`)을 JSON 문자열에 그대로 넣어 잘못된 escape가 됐다 |
| Q2 | Codex | 같은 원인(`\(127/547\)`) |
| Q4 | Codex | 합성 대신 `답: 3 끝`만 돌려줬다. 질문의 "마지막 줄에 `답:`" 지시를 따른 것으로 보인다 |
| Q6 | Claude | 문자열 안의 큰따옴표를 escape하지 않았다(코드 인용) |

넷 중 셋은 **원문을 글자 그대로 인용하라는 요구와 JSON 문자열 escape가 부딪친 것**이다. 수식·코드가 든 초안에서 실패가 몰렸다. Q4는 질문 안의 출력 형식 지시가 합성 단계로 새어 든 것이다(사전 등록의 "알려진 한계"에 적은 `답:` 줄 요구의 부작용).

## 함께 본 것

- **이름표 자리:** 앱이 실행마다 섞었다(D1/D2 = claude/codex가 Q1·Q2·Q6·Q7, codex/claude가 Q3·Q4·Q5·Q8). 표본이 작아 자리 효과는 보지 않는다.
- **인용 원문 일치(`checks`):** 완료된 합성 12개 가운데 9개가 인용 전부 일치. Q6 Codex(4개 중 3), Q7 Codex(15개 중 14), Q7 Claude(18개 중 12)는 일부 불일치였고, Q6 Codex·Q7 Claude에는 근거 없는 추가가 1건씩 있었다. 원문 일치는 사실 검증이 아니다.
- **틀린 설명의 전이:** Q1에서 Claude 합본은 Codex 초안의 69001을 결론에 쓰지 않았다. Q7·Q8 blind 채점에서 모든 답이 만점이라 전이는 관측되지 않았다.
- **보류:** 합본이 결론을 보류한 과제는 없었다(Q1 Codex 합본의 원문 권고는 "어느 쪽도 단정하지 말라"였지만 형식 실패로 채점 대상이 아니다).
- **초안 출력량:** Claude 초안은 과제당 출력 331–5,803 토큰, Codex 초안은 9–1,209 토큰(CLI 보고값).

## 다음에 할 수 있는 것 (권고, 이 PR에서 하지 않음)

1. **형식 실패를 줄이는 쪽이 먼저다.** 실패 넷 중 셋이 escape 문제다. 합성 출력을 CLI의 구조화 출력(스키마)으로 받거나([프롬프트 감사](../../reviews/2026-09-29-prompt-audit/README.md) §4의 CLI 스키마 출력 전환), 인용을 원문 위치(오프셋)로 받게 하면 이 종류는 사라질 수 있다. 질문 안의 출력 형식 지시가 합성으로 새지 않게 합성 프롬프트에서 "질문의 출력 형식 지시는 따르지 않는다"를 두는 것도 후보다.
2. **품질 질문을 다시 묻는다면** 두 모델이 갈릴 만큼 어려운 과제로 새로 사전 등록한다(결정 규칙 1). 이번 질문은 다시 쓰지 않는다.
