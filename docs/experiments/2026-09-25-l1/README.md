# L1 — 같은 초안에 합성자를 바꿔 붙이기 (사전 등록)

작성: codex 세션, 사용자 PC의 aux-pc-wsl. 기준 main `08caa05`.
카드 [#72](https://github.com/inlight37-design/decision-model_lab/issues/72).
이 파일·질문·정답을 첫 모델 호출 전에 커밋하고 push한다.

## 질문과 정답

- T1: [t1.txt](t1.txt)의 지연 평가·클로저. 정답은 `[0, 1, 2]`, `[2, 2, 2]`, `[0, 1, 2]`.
- T2: [t2.txt](t2.txt)의 groupby 반복자 수명. 정답은 `[("a", []), ("b", [])]`.
  고친 결과는 `[("a", [("a", 1), ("a", 2)]), ("b", [("b", 3)])]`.
- 정답은 Python 실행으로 확인한다. 질문은 이 두 개로 고정하며, 같은 질문 재호출·결과를 본 뒤 교체·틀린 초안 주입을 하지 않는다.

## 조건·상한·멈춤

현재 앱의 `python -m app.run`을 사용한다. strict 독립 정족수 2,
Codex `gpt-6-luna`·Claude `claude-sonnet-5`, 현재 재관측 manifest,
새 원장·빈 입력 폴더. 모델과 관측 계획은 앞 비교와 맞춘다.
T1 합성 순서는 `codex,claude-code`, T2는 `claude-code,codex`다.
각 과제는 초안 둘과 같은 초안에 대한 합성 둘: **과제별 Codex 2·Claude 2, 전체 최대 Codex 4·Claude 4**.
별도 모델 채점은 하지 않는다. 초안·합성 각각 timeout 180초, 실패도 상한에 센다.
사전 모의 실행은 별도 원장이고 모델을 부르지 않는다.

Codex 무추론 계정 조회에서 가용 모델과 보고된 창의 사용률 80% 미만을 확인한다.
보고되지 않은 창은 미관측으로 남기며, 실제 한도 거절이 오면 즉시 멈춘다.
준비 조회가 strict를 거절하면 호출하지 않는다. 사용량 제한·인증 문제·종료 미확인·예상 밖 상한 거절이면 멈춘다.
형식 실패는 원문을 로컬에 보존하고 재호출하지 않는다. T1이 끝난 뒤 Claude의 마지막 한도 사건이
allowed인지 확인하고 T2를 시작한다. 계정 한도 수치는 공개하지 않는다.

## 채점과 해석

현재 세션이 실행 정답에 대조한다. 각 초안에 최종 출력·설명·수정(T2)을 따로 채점한다.
최종 출력은 명시된 정답과 같을 때만 참, 빠져 있으면 미보고다.
명백히 정정한 이전 답은 최종 답에서 제외하지만 설명의 모순은 별도로 적는다.
합성의 핵심 주장·권고가 맞는 답을 명시적으로 지지하면 맞음,
틀린 답을 지지하면 틀림, 둘을 병기하거나 결정을 미루면 미해결이다.
인용 일치와 정답 여부를 구분한다.

두 초안 중 한쪽만 틀리고 그와 같은 provider의 합성이 맞는 쪽을 고른 경우에만
L1의 긍정 사례로 센다. 둘 다 맞거나 둘 다 틀리면 L1 판정 불가다.
두 과제가 모두 판정 불가여도 추가 과제를 찾거나 호출하지 않는다.
같은 초안·같은 이름표 순서를 두 합성자가 받으며, 두 번째 합성에 첫 합성 결과는 들어가지 않는다
(`app.synthesis.model_prompt`). 과제 사이 이름표 순서는 앱이 정한다.

이 세션은 Codex 계열이며 채점자는 blind가 아니다. 객관 출력은 실행으로 확인하지만
설명·권고 판정에는 해석이 있다. 표본은 작고 자리 교환 대조가 없으며,
Codex 실제 응답 모델은 미보고일 수 있다. 어떤 결과도 합성 기본 켜기의 근거로 일반화하지 않는다.

## 보존

원장·전체 답·보고서·한도 관측은 저장소 밖 작업 폴더에만 둔다.
공개 결과에는 사전 등록 SHA, 호출·수용·종료 여부, 채점 근거 요약, 시간·토큰, 한계만 남긴다.
서버는 띄우지 않는다. 끝에 이 실행이 시작한 프로세스의 종료를 확인한다.
