# 공통 자료 합계 1 MiB — 사전 등록 (2026-09-25)

[카드 #61](https://github.com/inlight37-design/decision-model_lab/issues/61). 작성: claude 세션, 사용자 PC(`aux-pc`의 Claude 데스크톱 앱, WSL `aux-pc-wsl`에서 실행). 기준 main `fc0733c`. **첫 모델 호출 전에 커밋하고 push한다.** 결과를 본 뒤 이 파일의 자료·질문·판정 기준·결정 규칙을 바꾸지 않는다. 결과는 같은 폴더의 `RESULTS.md`에 따로 적는다.

## 묻는 것

앱이 허락하는 공통 자료의 합계 한도(1 MiB = 1,048,576바이트, `app/controller.py`의 `MAX_SOURCES_TOTAL`) 가까이를 주면 두 참여자가 제한 시간 180초 안에 끝까지 쓰는가.

1. **시간 안에 끝나는가**: 참여자별 수용·거절(시간 초과 포함)과 걸린 시간.
2. **앞·가운데·끝**: 긴 파일 넷에서 40번째 줄·가운데 줄·끝에서 세 번째 줄의 값을 찾는가.
3. **파일 수**: 작은 파일 16개의 표식을 모두 찾는가.
4. **못 읽은 것을 밝히는가**: 놓친 값이 있을 때 그 파일·부분을 읽지 못했다고 적는가.
5. 곁들여: CLI가 보고한 토큰 사용량.

예상(호출 전에 적는다): [긴 자료 실험](../2026-09-25-long-sources/RESULTS.md)에서 약 490 KB에 Codex는 검색으로 32초, Claude는 처음부터 끝까지 읽어 104초를 썼다. 같은 방식이면 약 1,043 KB에서 Claude는 180초를 넘길 수 있고, Codex는 시간 안에 끝날 것이다. 이 예상은 판정 기준을 바꾸지 않는다.

- 헤드리스 실행 `python -m app.run`([app 안내](../../../app/README.md)), 지금 계획 `codex@5bed42d05320`·`claude-code@a35129c5a1dc`와 [재관측 기록](../../reviews/2026-09-25-reobserve/manifest.v2.json)(이 기기에 등록됨). 모델 `gpt-6-luna`·`claude-sonnet-5`, 참여자 제한 시간 180초(앱의 최대).
- 새 원장 `~/.local/state/dml-live-1mib-20260925`, **상한 Codex 1·Claude 1(전체 2)**. 실패·시간 초과도 상한에 센다. 두 번째 호출은 없다.
- 먼저 같은 자료로 모의 실행(`--mock`, 별도 원장, 모델 호출 없음)이 자료를 받아 공개까지 가는지 본다.
- 자료는 [make_sources.py](make_sources.py)가 이번에 새 값으로 만든다. 값 대응표는 원장 폴더 옆 파일에만 둔다.

자료(20개, 합계 약 1,043,000바이트 — 한도의 99%를 넘는다. 시험 생성에서 1,042,771바이트. 값은 모두 서로 독립인 무작위 8자리 16진수):

| 파일 | 내용 |
|---|---|
| `long-a.md` … `long-d.md` | 번호 붙은 영어 채움 줄 약 2,900개(각 약 261,000바이트, 파일당 한도 262,144 아래). 파일마다 40번째 줄·가운데 줄·끝에서 세 번째 줄에 "`FACT <이름>: the recorded value is <값>.`" — a: harbor·lantern·quartz, b: meadow·cobalt·violet, c: ember·falcon·garnet, d: juniper·kestrel·saffron |
| `part-01.md` … `part-16.md` | 각 한 줄 "`marker: <값>`" |

질문은 [question.txt](question.txt) 그대로다: (1) part 파일 16개의 표식, (2) 긴 파일 넷의 FACT 이름·값·파일, (3) 끝까지 읽지 못했거나 건너뛴 자료.

## 판정(참여자별, 공개된 초안에 대한 문자열 비교)

판정 코드는 [analyze.py](analyze.py)다. 값의 정확한 문자열이 초안에 있으면 찾은 것이다.

| 판정 | 기준 |
|---|---|
| 실행 | 수용·거절(이유), 걸린 시간, 제한 시간 안인가, 토큰 사용량 |
| 앞·가운데·끝 | FACT 12개 중 찾은 수, 위치별(앞 4·가운데 4·끝 4) |
| 파일 수 | `part-*` 표식 16개 중 찾은 수 |
| 밝힘 — 사람이 가름 | 놓친 값이 있으면 초안을 읽고, 그 파일·부분을 읽지 못했거나 건너뛰었다고 적었으면 "밝힘", 아니면 "조용한 누락" |

## 결정 규칙

- **이번 PR에서는 앱 코드(자료 한도)를 바꾸지 않고 두 번째 호출도 하지 않는다.** 결과와 권고만 적는다.
- 어느 참여자라도 시간 초과로 거절되면: 앱 안내의 합계 한도를 "참여자가 제한 시간 안에 실제로 쓸 수 있는 크기"로 낮추거나, 화면에서 큰 자료에 경고를 띄우는 것을 다음 카드 후보로 올린다(한도를 얼마로 할지는 이 표본 하나로 정하지 않는다).
- 수용됐지만 값을 조용히 누락하면: 긴 자료 실험의 M1(자료 목록에 줄 수·"끝까지 읽고 못 읽은 부분은 밝힌다" 안내)을 후보로 올린다.
- 둘 다 시간 안에 모두 찾으면 "이번 표본에서 둘 다 찾았다"만 적는다. 한 질문·한 번 호출이다.

## 멈춤 조건

- 준비 조회(모델 호출 없음)가 strict 허가를 주지 않으면 부르지 않는다.
- 모의 실행에서 자료가 거절되면 생성기를 고치고 앱 한도는 바꾸지 않는다.
- 사용량이 막혔다는 신호가 오면 멈춘다(이 실험은 어차피 한 번이다).

답 원문·원장·값 대응표는 저장소 밖에만 둔다. 저장소에는 판정과 개수만 옮긴다. 끝에 이 실행이 시작한 프로세스가 남지 않았는지 확인한다.
