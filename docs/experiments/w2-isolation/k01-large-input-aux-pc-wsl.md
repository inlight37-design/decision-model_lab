# K01 — 큰 stdin 질문이 끝까지 읽히는지, `aux-pc-wsl`

2026-09-24 · claude 세션(Claude Opus 5.5, aux-pc의 로컬 checkout, `wsl.exe`로 배포판의 로그인 셸에서 실행). **모델 호출: Claude 1회.** 도구: [`tools/w2/observe.py`](../../../tools/w2/observe.py) `call b1 claude-sonnet-5 --pad-kb 96`. Claude Code 2.1.280.

## 승인

- 세션이 K01 호출(Claude 1회)과 K46 호출(Codex 1회)의 명시적 승인을 요청했다. 사용자는 "병합하고 할거하고 정리해"라고 답했다(2026-09-24).
- 세션은 이것을 K01에만 적용해 `observe.py approve --claude 1 --codex 0 --timeout 300`으로 적었다. K46 호출은 adapter를 먼저 고쳐야 해서 다음 세션으로 넘겼다.
- 규칙은 2026-09-23과 같다: 실패도 센다, 호출당 300초, 기대와 다르면 멈춘다, 한도 메시지면 모두 멈춘다.
- 이 기록 전의 시도(2026-09-24 "3번은 알아서 해도 돼"를 승인으로 적으려 한 것)는 이 세션의 자동 권한 확인이 거절했다([후속 기록](stage2-followup-aux-pc-wsl.md)).

## 왜

2단계 `b1`은 784바이트만 보냈다(실수, [2단계 리뷰 요청서](../../reviews/2026-09-23-stage2-request/README.md) S01). "CLI가 입력 일부만 읽고 닫음"은 입력이 파이프 버퍼(64 KiB)보다 클 때만 쓰는 쪽에서 드러난다. 쓰기가 끝났다는 것만으로는 CLI가 다 읽었다는 증거도 아니다. 그래서 큰 입력을 보내고, 보고된 입력 토큰이 입력 크기만큼 늘었는지 함께 본다.

|---|---|---|

| 자손 종료 | 확인 | 확인 |

- 채움 글은 한글 음절과 공백 32,768자다. 캐시 생성 토큰이 약 32,800 늘었다 — 채움 글 전체만큼이다. 일부만 읽었다면 이만큼 늘 수 없다.
- 쓰기가 끝났다(`complete`)는 것은 파이프 버퍼 64 KiB를 넘는 나머지(약 29 KB)를 CLI가 읽었다는 뜻이기도 하다. 토큰 증가와 함께 보면 **Claude CLI는 약 95 KB의 stdin 질문을 끝까지 읽었다.**
- 모델은 채움 글을 무시하라는 지시대로 네 항목에 답했다. 금지 파일은 `--restricted`가 거절했고, 지시문 표식은 없다고 보고했다.
- 설정 폴더(`config_changes`, 이름은 도구가 가림):
  - `~/.claude.json`과 모델 목록 캐시가 바뀌었다. 캐시 파일 이름의 조직 UUID는 `<uuid>`로 가려졌다.
  - `backups`에 새 백업이 하나 생기고 오래된 백업 하나가 지워졌다 — Claude가 백업 수를 줄인다.
  - `.credentials.json`은 이번에도 바뀌지 않았다(토큰 갱신 없음).

## 한계

- 원 출력은 WSL의 `~/.local/state/dml-observe/results/006-b1.json`에만 있다.
