## 과제와 채점 기준

### T1 — 계산(정답 있음)

> x² + y² = 2026을 만족하는 양의 정수 순서쌍 (x, y)는 모두 몇 개인가? 순서가 다르면 다른 쌍으로 센다.

정답: **2개** — (1, 45), (45, 1). 2026 = 2 × 1013, 1013은 4로 나눈 나머지가 1인 소수라 두 제곱수의 합 표현이 부호·순서를 빼면 하나다. 채점: 결론이 2이고 다른 쌍을 더하지 않으면 맞음.

### T2 — 코드 결함(정답 있음)

> 다음 함수에 결함이 있다면 무엇이고, 어떤 입력에서 드러나며, 어떻게 고치는가?
>
> ```python
> def moving_average(values, k):
>     """길이 k인 연속 창의 평균을 앞에서부터 차례로 돌려준다. len(values) < k면 빈 목록."""
>     if k <= 0:
>         raise ValueError("k must be positive")
>     out = []
>     total = sum(values[:k])
>     for i in range(k, len(values)):
>         out.append(total / k)
>         total += values[i] - values[i - k]
>     return out
> ```

정답: **마지막 창의 평균이 빠진다.** `len(values) >= k`이면 `len(values) - k + 1`개가 나와야 하는데 하나 적다. 예: `[1, 2, 3, 4]`, `k=2` → `[1.5, 2.5]`(3.5 누락), `[1, 2, 3]`, `k=3` → `[]`(2.0이어야 함). 채점: 결함 식별(마지막 창 누락·하나 적음)이 맞으면 맞음. 따로 `fix_ok`를 적는다 — 고친 코드가 `len(values) < k`에서 빈 목록을 지키면 참(루프 뒤에 조건 없이 `append`하면 짧은 입력에서 틀린다).

### T3 — 제약이 정해진 설계 선택(하나의 정답 없음)

> 사내 위키 검색을 개선하려 한다. 조건: 문서 약 2천 개(한국어·영어 혼합), 주당 약 50건 수정, 서버 1대, 추가 예산 0원, 운영자 1명, 검색 응답 1초 안. 지금 할 일로 (가) 벡터 DB를 도입해 의미 검색으로 바꾸기와 (나) 기존 키워드(BM25) 검색을 개선하기(형태소 분석·동의어 사전·필드 가중치) 중 하나를 고르고, 이유와 결론을 뒤집을 조건을 써라.

선호가 갈릴 수 있으므로 고른 쪽을 맞고 틀림으로 채점하지 않는다([03 §3](../../architecture/v0.4/03-evaluation-and-roadmap.md)). 루브릭 0–3점: (a) 여섯 조건 중 셋 이상을 명시적으로 근거에 씀, (b) 결론을 뒤집을 조건이 구체적임(측정값·상황), (c) 고른 쪽의 위험을 하나 이상 적음. 고른 쪽은 기록만 한다.
