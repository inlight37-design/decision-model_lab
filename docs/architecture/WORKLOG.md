## 1. 요청 범위

Jev 계열의 저비용 판단 모델, 로컬·저비용 생성 모델, 프론티어 AI, Antigravity 등의 에이전트 하네스를 조합하여 토큰 사용을 줄이고 큰 프로젝트를 지속적으로 수행할 수 있는 현실적인 뼈대를 정리했다. 기존 저장소를 실제로 읽은 뒤 공개 자료를 조사했고, 다음 작업이 중단 없이 이어질 수 있도록 단계별 커밋을 남겼다.

기존 출처 중심 노트는 보존하고, 확인한 사실·제작자 주장·커뮤니티 경험·설계 제안·미검증 항목을 새 문서에 분리했다. 특정 모델이나 제품의 최종 채택은 확정하지 않았다.

## 4. 중요한 조사 결과와 설계 경계

**Jev는 좁은 typed 판단을 위한 부품으로 취급한다.** 전체 프로젝트 설계나 최종 승인까지 맡기지 않는다. 높은 분류 확률·공급자 confidence가 실제 작은 워커의 성공 확률과 같다는 가정도 하지 않는다.

**JSON 출력 옵션은 비용 절감 자체가 아니다.** 문맥 선별, 로그의 코드 처리, artifact 참조, 불필요한 도구·반복 대화 제거를 별도 설계했다.

**기존 제품을 실제 비교 대상으로 포함했다.** LangChain의 Jev 통합과 LiteLLM의 최신 라우팅 실험, Gas Town/Beads, Agent Mail, OpenHands를 조사했다. 전부 새로 만들거나 전부 동시에 도입하는 방향은 제안하지 않는다.

**Antigravity 외부 호출과 내부 교체를 구별했다.** 공식 CLI/SDK/Teamwork 기능은 확인했지만 Jev로 내부 조정자 판단을 전면 교체하는 공개 계약은 확보하지 못했다. 먼저 외부 task 배정 경계에서 연결하는 구조다.

**단일 워커를 기준으로 출발한다.** 코드로 가능한 규칙을 먼저 분리하고, Jev/로컬 router를 shadow 평가한 뒤 좁게 적용한다. 독립 병렬 작업은 그다음이다.

**품질이 맞지 않는 절감은 성공으로 보지 않는다.** 실패·재시도·검증·사람 재작업·캐시를 포함한 수용 작업당 총비용을 목표 지표로 둔다.

## 6. 실제 확인한 것

합성 계약 검사 25개를 실행·재실행하여 통과했다. 검사한 schema/fixture/validator와 원격에 커밋된 파일의 Git blob SHA가 일치함도 확인했다. 비용 문서의 산술 예제를 Python으로 확인했다.

이 결과는 실제 모델 성능, CLI 연결, 보안 격리, 장애 복구, 로컬 메모리 사용, 비용 절감의 검증이 아니다.

## 7. 확보하지 못한 자료와 미실시 작업

사용자 제공 haejoe 원문은 확보하지 못했다. 관련 X 게시물은 검색으로 식별했지만 본문 접근 실패가 있어 확정 근거로 사용하지 않았다. Reddit 사례는 사용자 경험 수준으로 표시했다. Antigravity 관련 기술 사실은 공식 문서로 별도 확인했다.

유료 API 호출, 사용자 PC 설치·설정 변경, Jev/로컬 모델 추론, Antigravity/Codex/Claude의 실제 자동 실행, 사용자 저장소의 성능 실험은 하지 않았다. 절감률·권장 최종 모델·최적 병렬 수는 미측정이다.

## 8. 다음 구현의 시작점

1. 시험할 실제 저장소와 수용 기준, 허용 권한·인증 경로·예산을 명시한다.
2. 기존 coding CLI 하나를 선택해 `probe/start/events/cancel/inspect/collect`의 지원 범위를 확인한다.
3. 단일 작업의 영속 원장·독립 verifier·usage 기록을 먼저 연결한다.
4. 동일 기준선에서 규칙-only와 Jev/로컬 shadow 판단을 비교한다.
5. 통과한 좁은 작업군에만 실제 routing을 적용하고 이후 병렬화한다.

기존 문서의 가정·후보·예시 숫자를 사용자 확정 요구로 취급하지 않는다. 연구 문서 전체를 자동 로딩 프롬프트에 넣지 말고 현재 작업에 필요한 부분만 읽는다. 다음 작업에서 실제 구현을 시작하더라도 원래 source-only 노트를 임의로 최신 결과처럼 수정하지 않는다.
