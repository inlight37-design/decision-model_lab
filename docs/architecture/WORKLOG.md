# 협업 시스템 아키텍처 조사 — 작업 기록

기준일: 2026-09-21. 상태: 조사 진행 중 / 최초 체크포인트.

## 이번 요청과 보존 사항

사용자는 Jev 계열의 저비용 판단 모델, 로컬·저비용 생성 모델, 프론티어 AI, Antigravity 등의 에이전트 하네스를 조합하여 토큰 사용을 줄이고 큰 프로젝트를 지속적으로 수행할 수 있는 시스템의 현실적인 뼈대를 요청했다. 구현 전에 근거와 아키텍처를 정리하고 중간 Git 커밋을 남긴다.

기존 `docs/research-notes-2026-09-21.md`는 출처 중심의 원래 조사 기록으로 보존한다. 이번 설계 제안은 별도 문서에 기록하며, 관측 사실·제작자 주장·설계 가정·미검증 사항을 구분한다. 현재 저장소 초기 파일과 원래 조사 내용을 실제로 읽었다.

## 조사 순서

1. Jev 및 로컬 대안의 공식 인터페이스, 비용, 검증 범위 재확인.
2. 사용자가 제시한 Antigravity teamwork-preview 글과 공식 CLI/SDK/Teamwork 문서 대조.
3. GitHub 구현, Reddit/X의 직접 사용 사례, 라우팅·다중 에이전트·컨텍스트 관리 연구 비교.
4. 코드 기반 제어부, 선택적 저비용 판단부, 프론티어 설계·검토부, 격리된 실행부의 경계 설계.
5. 메시지 계약, 상태 저장·재시작, 변경 충돌, 보안·예산·평가 및 단계적 도입 계획 정리.
6. 문서 간 모순·링크·예제 점검 후 최종 인덱스와 인수인계 갱신.

## 초기 확인

- TypeSafe 공식 문서는 `state`와 typed questions를 입력하고 `choice`, `score`, `noul`을 반환하는 인터페이스 및 atomic question 원칙을 설명한다. 복잡한 장기 계획 전체를 그대로 대체한다는 근거로 해석하지 않는다.
  - https://docs.typesafe.ai/introduction
- LangChain은 2026-09-17 Jev를 이용한 모델 라우팅과 middleware 예제를 공개했다. 통합 예제의 존재와 실운영에서의 절감 검증은 구분한다.
  - https://www.langchain.com/blog/building-a-harness-with-jev
- Google Antigravity 공식 홈페이지에서 2.0, CLI, SDK 및 2026-08-27 Teamwork 글의 존재를 확인했다. teamwork-preview의 자세한 구현은 후속 조사 대상이다.
  - https://antigravity.google/
- 사용자가 준 haejoe 원문은 웹 도구에서 초기 접근 오류가 발생했다. 원문 재확보와 출처 대조를 계속하며, 읽지 못한 내용을 읽었다고 기록하지 않는다.

## 설계 시 검증할 가정

- JSON은 구조와 검증을 제공하지만 항상 자연어보다 적은 토큰이라는 뜻은 아니다.
- 토큰 절감, 청구액 절감, 구독 한도 절감, 처리 지연은 각각 별도 지표다.
- Jev/소형 모델의 높은 확신 또는 유효한 출력 형식은 판단의 정답을 보장하지 않는다.
- 다중 에이전트는 단일 에이전트보다 비쌀 수 있다. 단일 에이전트 기준선과 품질을 맞춰 평가한다.
- 사용자의 원래 PC(RTX 5070 Ti, RAM 64GB)와 임시 PC(RTX 2070 SUPER, VRAM 8GB, RAM 16GB)를 구분하고, 로컬 실행 가능성을 실측 없이 보장하지 않는다.
