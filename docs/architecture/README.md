# 저비용·장기 AI 협업 시스템 — 아키텍처 안내

**기준일: 2026-09-21 / 제안 v0.1.** 이 문서 묶음은 무엇을 만들지, 어떤 기존 도구를 재사용할지, 무엇으로 성과를 검증할지를 정리한 설계입니다. 실제 유료 모델·코딩 하네스·로컬 GPU를 연결해 운영한 결과는 아닙니다.

## 1. 설계의 중심

> 프론티어 모델이 잘하는 설계·추론·검토는 남기고, 코드로 할 수 있는 운영 판단과 불필요한 문맥 전달을 먼저 제거한다. Jev류 판단 모델과 여러 워커는 추가 이득이 검증되는 곳에만 사용한다.

```text
사용자 목표 / 승인된 수용 기준
              ↓
코드 제어부: 작업 원장·의존성·권한·예산
              ↓
현재 작업에 필요한 문맥만 구성
              ↓
규칙으로 배정 / 필요할 때 Jev류 판단 / 복잡하면 프론티어
              ↓
격리된 단일 워커 또는 제한된 독립 병렬 작업
              ↓
독립 검증 → 최신 통합 버전에서 재검증
              ↓
수용된 증분 + Git 기록 + 실행 상태 체크포인트
```

Jev의 판단이 틀려도 권한·예산·검증 정책이 우회되지 않아야 합니다. 워커가 ‘완료’라고 답한 것과 사용자의 요구가 실제 충족된 것은 다릅니다.

## 3. 주요 결론 — 확정한 제품 선택이 아니라 설계 방향

**전체 지휘와 좁은 판단을 분리합니다.** Jev류는 작업 분류나 배정 추천에 사용하고, 아키텍처를 만들고 코드의 의미를 검토하는 모델의 역할과 섞지 않습니다.

**JSON 통신과 토큰 절약을 분리합니다.** 전송/저장에는 엄격한 계약을 쓰되, 모델에게 보여 줄 정보는 코드가 따로 선택합니다. 긴 원본 로그를 짧은 JSON 문자열 안에 넣는 것만으로 문제가 해결되지는 않습니다.

**작업 하나의 안정적인 실행을 먼저 만듭니다.** 초기 제안은 기존 coding CLI 하나와 작은 제어부입니다. 별도의 AI 관리자 여러 명, 자동 파인튜닝, 전면 분산 인프라는 시작 조건이 아닙니다.

**현재 존재하는 구현을 비교 기준으로 둡니다.** LiteLLM의 단계별·하네스별 라우팅, Gas Town/Beads의 작업 관리, Agent Mail의 협업, OpenHands의 SDK를 재사용 후보로 조사했습니다. 도구를 전부 함께 설치하자는 뜻은 아닙니다. [05](05-tooling-and-roadmap.md)에 책임 중복과 적용 조건을 정리했습니다.

**Antigravity는 우선 외부 worker adapter로 봅니다.** 공식 CLI/SDK/Teamwork 기능은 확인했지만 Jev가 Teamwork 내부 조정자의 모든 판단을 직접 대체하는 공개 연결 계약은 확인하지 못했습니다. 가능한 외부 배정과 미확인 내부 교체를 구분합니다.

**확신은 승인권이 아닙니다.** 확률이 높아도 틀릴 수 있으므로 보류·상향 경로와 독립 검증이 필요합니다. 배포·삭제·외부 영향은 별도 승인 정책을 따릅니다.

## 4. 첫 구현의 제안 범위

```text
하나의 저장소 + 하나의 worker adapter
+ 영속 작업/시도 원장
+ 최소 문맥 구성
+ 신뢰된 수용 테스트
+ 비용·실패·산출물 기록
```

그다음 Jev 또는 로컬 판단 모델이 배정에 영향을 주지 않는 shadow mode에서 비교합니다. 실제 이득이 확인된 작업군에만 적용하고, 그 후에 독립된 두 작업의 병렬화를 시험합니다.

운영 원장은 단일 소유자로 둡니다. SQLite, LangGraph checkpoint, Beads를 같은 task 상태의 경쟁하는 진실 원천으로 함께 사용하지 않습니다. 무엇을 선택할지는 구현 규모와 재사용 실험으로 결정합니다.

## 5. 지금 있는 것과 없는 것

| 있는 것 | 아직 없는 것 |
|---|---|
| 출처와 한계를 기록한 조사 지도 | 사용자 작업에서의 종단간 비용·성능 실험 |
| 책임 경계·상태 전이·복구·보안·통합 설계 | 실제 scheduler/adapter/verifier 런타임 |
| 기존 도구 비교와 단계별 진입 조건 | 인증·구독 quota·취소·재개 호환성 검증 |
| 최소 JSON 계약과 합성 예제 | 실제 artifact resolver·권한·lease·budget 구현 |
| 실행한 오프라인 검사 25개 | 로컬 모델의 VRAM·한국어 품질·속도 측정 |

완료 범위를 넘겨 해석하지 않도록 [검증 기록](VALIDATION.md)을 함께 보세요. 실제 자동 실행을 시작하기 전에는 시험 저장소, 수용 기준, 인증 경로, 허용 권한, 예산을 명시해야 합니다.

## 6. 이어서 읽는 AI/개발자를 위한 주의

이 묶음은 설계 자료이지 매 호출의 프롬프트에 통째로 넣을 메모리가 아닙니다. 현재 task와 관련된 문서만 읽고 원문 근거를 필요할 때 확인하세요. 후보·가정·ADR을 사용자 확정 요구로 바꾸지 말고, 새 증거가 생기면 이유와 함께 갱신하세요.
