## 1. 접근 범위와 기준

GitHub 연결과 격리된 Linux 분석 컨테이너를 사용했다. aux-pc, aux-pc-wsl, 운용 PC, 설치·로그인된 provider CLI에는 접근하지 않았다. 모델 호출·사용자 인증 파일 연결·유료 API·PC 설치 변경은 하지 않았다. 기존 manifest의 관측 상태, CLI argv/spec_revision, K46·C3 판정, Q4, TM 채택, 디자인 토큰·발행 아티팩트는 바꾸지 않았다.

시작 시 GitHub에는 열린 PR이 없었고 main만 있었다. 직접 clone은 분석 컨테이너의 DNS 제한으로 실패했다. 그래서 **공개 저장소에 추적된 소스만** `git archive`하는 읽기 전용·작업 브랜치 전용 임시 Actions 작업으로 사본을 받았다. 환경/자격증명/추적되지 않은 파일은 수집하지 않았다. 작업은 소스 확보 직후 삭제했다. 기존 CI 설정에 최종 변경은 없다. 최종 source tree를 로컬과 GitHub에서 동일하게 맞췄다.

이 검토는 현재 실행 경로와 회귀 시험을 중심으로 한 저장소 검토다. 원장에 실린 모든 외부 링크의 최신 재조사, 모든 과거 보고서의 전면 재심, Windows 내부 API의 실기기 재검증은 아니다. 기존 PC 관측을 단지 전달받은 추측으로 격하하지 않는다. **기존 관측은 그 파일이 기준이고, 이번 세션이 재관측하지 않았다는 뜻이다.**

## 3. 재현하고 고친 것

### AI-01 — 거래 시작 실패가 스레드 잠금을 남김

`_Tx.__enter__()`가 RLock을 잡은 다음 `BEGIN IMMEDIATE`에서 예외가 나면 Python은 `__exit__()`를 호출하지 않는다. 이전 코드는 잠금을 풀지 않아 이후 다른 HTTP 스레드의 원장 접근이 막힐 수 있었다.

회귀 시험은 SQLite가 지원하지 않는 중첩 BEGIN으로 예외를 만들고, 바깥 거래 종료 뒤 다른 스레드가 잠금을 얻는지 확인한다. 수정은 BEGIN 실패에서 그 진입이 얻은 잠금만 해제하는 것이다. 임의의 SQL 오류가 반드시 서비스 교착을 만든다고 일반화하지 않고, **BEGIN 실패 경로의 정리 누락**으로 한정한다.

### AI-02 — COMMIT 실패 뒤 열린 거래가 남음

지연 외래 키 위반을 넣어 COMMIT이 실패하게 하면 원래 연결의 `in_transaction`이 참으로 남는다. 다음 BEGIN은 실패한다. 수정은 COMMIT/ROLLBACK 예외 경로에서 열린 거래를 rollback하고, finally로 잠금을 푸는 것이다. 시험은 실패한 child 삽입이 남지 않고 다음 정상 거래가 가능한지 확인한다. 현재 journal이 이 지연 제약을 사용한다는 주장이 아니라, 저장소의 일반 거래 래퍼가 실패 시 정리해야 하는 계약을 시험했다.

### AI-03 — 잘못된 HTTP 입력을 적절히 거절하지 못함

기존 API는 비객체 JSON의 `.get()` 오류로 연결이 끊기거나, `null`/숫자 질문을 문자열로 바꾸고, boolean/float/string 정족수를 정수로 바꿔 받을 수 있었다. 음수 Content-Length는 제한 읽기 대신 EOF 대기로 이어질 수 있었다.

수정은 상태 변경 전에 입력을 확인한다. 단일 ASCII 십진 Content-Length·크기 상한, Transfer-Encoding/중복 길이 거절, JSON Content-Type과 객체 본문, 문자열 질문/수동 답, 엄격한 정수 정족수를 요구한다. 없는 길이 411, 너무 큰 본문 413, 잘못된 타입 415, 미완성 본문의 소켓 유휴 timeout 408, 나머지 잘못된 요청 400을 시험했다. Host/Authorization 중복도 거절한다.

Origin이 있으면 정확히 해당 localhost origin이어야 한다. frame 삽입을 거절하는 헤더와 no-store 등 기존 방어를 함께 보낸다. 연결을 닫아 거절한 잔여 본문을 다음 요청으로 해석하지 않는다. **5초는 소켓 유휴 제한이지 전체 요청 시간/동시 연결/CPU·메모리 상한이 아니다.** Origin 없는 비브라우저 클라이언트는 기존 Bearer 토큰으로 계속 동작한다.

### AI-04 — 입력 영역과 좁은 화면 잘림

오프라인 Chromium 화면에서 긴 CLI 모의 행동 select가 같은 행의 참여자 이름을 밀어 잘리는 것을 확인했다. 선택칸을 해당 참여자의 다음 행으로 배치하고, grid 자식 최소 너비와 긴 초안/제목 줄바꿈을 조정했다. 정족수 정책 선택도 좁은 폭에서 넘치지 않게 했다. 수동 참여를 포함하는 정책에서도 맞는 용어인 “최소 정족수”로 라벨을 고쳤다. 토큰 색·디자인 시스템·Q4 기본 화면은 바꾸지 않았다.

## 4. NEXT에서 실제로 진행한 것

공개 후 **“합성 없는 보고 저장(JSON · 원문 포함)”**을 누르면 인증된 `GET /api/runs/<id>/report`가 `a1-draft-report/1`을 반환한다.

- controller가 `revealed`로 판정했고 참여자가 모두 settled일 때만 가능하다. 공개 전/축소 승인 전/정족수 미달에 보고 모듈이 새 공개 권한을 만들지 않는다.
- 고정 질문·프롬프트, 입력 해시/크기, **수용된 초안 원문 그대로**, 초안 해시, 참여자 출처/독립성, 탈락·실패, 선택한 정족수 정책과 축소 승인 여부를 보존한다. 실패한 참여자를 보고서에서 지워 성공한 것처럼 만들지 않는다.
- 수동 답은 `unverified`, 합성은 `not_implemented`, 사실 검증은 `not_performed`, 계정 전체 잔여는 `unknown`이다. 보고서 생성의 추가 모델 호출은 0이다. 해시는 진실성·저자·독립성의 증명이 아니다.
- 허용한 필드만 깊은 사본으로 내보낸다. 다른 실행의 질문, 향후 자유 메타데이터, 원장/토큰 전체를 통째로 복제하지 않는다. 고정 입력의 해시/크기가 맞지 않거나 공개된 수용 초안이 없으면 실패한다.
- report 모듈은 DB를 열지 않고 상태/사건을 쓰지 않으며 실행기를 부르지 않는다. 다운로드는 사용자의 명시적 버튼 동작이고 파일에는 민감한 원문이 포함된다. 서버가 저장소나 외부 서비스에 자동 게시하지 않는다.

이것은 **합성자가 아직 없는 A1의 종료 산출물**이다. 실제 합성자 실패 시 자동 복구, 주장 사실 검증, 결정 카드, 품질 향상을 이미 구현했다고 읽으면 안 된다. 향후 합성 결과를 만들더라도 원문·미합의와 이 구분을 보존해야 한다.

### 브라우저 한계

실제 `page.goto(http://127.0.0.1:...)`는 관리 정책의 `ERR_BLOCKED_BY_ADMINISTRATOR`로 막혔다. 정책을 우회하지 않았다. 그 대신 **네트워크를 전부 abort한 오프라인 DOM 시험**에서 실제 HTML/JS를 로드하고, token bootstrap/fetch만 controller fixture로 대체했다. 그러므로 이 결과는 HTTP 인증·fragment 토큰·Origin/CORS·실제 브라우저 연결 시험이 아니다. HTTP는 별도의 실제 소켓 시험에서 검증했다. 두 층의 시험이 각각 성공한 것을 브라우저 종단 간 성공으로 합치지 않는다.

재실행은 저장소의 전체 unittest와 [DOM fixture](browser_smoke.py)로 한다. fixture는 선택적 Playwright/Chromium이 설치된 분석 환경용이며 제품/CI 의존성에 추가하지 않았다. 실행 결과의 [관측 요약](validation.json)을 함께 보존한다. 사용자 PC의 화면 연결, Firefox/Safari, 키보드/스크린리더 전체 접근성, 실제 provider CLI, 장시간 운용은 미검증이다.
