# 2026-09-27 — Codex 사용자 훅이 참여자 실행 중에 실제로 도는지: 실제 로그인으로 한 번

작성: claude 세션(Claude Opus 5.5), 사용자 PC `DESKTOP-T0UDE01`의 WSL `Ubuntu-24.04`. [합성 HOME 관측](../2026-09-27-codex-hooks/README.md)(모델 호출 0)의 후속이다. 그 관측은 참여자 옵션으로도 `~/.codex/hooks.json`을 **읽는다**는 것까지 보였고, 실행되는지는 미확인으로 남겼다. 카드 #111은 "실제 로그인 HOME을 쓰는 진단은 사용자 허락 뒤에만"이라고 했고, 사용자가 2026-09-27 허락했다. **모델 호출 1회**(Codex, 구독)다.

## 어떻게 했나

[`probe_live.py`](probe_live.py)를 저장소 루트에서 WSL 로그인 셸로 돌렸다. 결과 요약은 [`result.json`](result.json)이다.

1. 사용자의 실제 `~/.codex`에 `hooks.json`·`AGENTS.md`·`AGENTS.override.md`가 없는지 확인했다(셋 다 없음). 돌고 있는 Codex 프로세스와 앱 서버도 없었다.
2. 없을 때만 만드는 방식(`O_EXCL`)으로 표식 훅 파일을 새로 만들었다. 다섯 사건(`SessionStart`·`UserPromptSubmit`·`PreToolUse`·`PostToolUse`·`Stop`)마다 이번 호출의 빈 작업 폴더에 빈 파일을 만드는 명령 훅이다.
3. **참여자와 같은 argv**(`build_spec`: `--ignore-user-config`·`--ignore-rules`·`--ephemeral`, 권한 profile, 연결 앱·플러그인 끄기)와 **같은 격리**(bubblewrap, `participant_mounts`)로 실제 로그인 HOME에서 `codex exec`를 한 번 불렀다. 질문은 "OK 한 단어로 답하라"였다.
4. 호출이 끝나자마자(실패해도 지우도록 `finally`) 훅 파일을 지우고, 지워졌는지 확인했다(지워짐). 로그인 파일은 읽거나 옮기지 않았다.

## 읽는 법

- **확인한 것.** 이 모양의 훅 파일을 둔 채로 참여자와 같은 argv·격리·실제 로그인으로 호출했지만, 훅은 실행되지 않았고 호출은 정상으로 끝났다.
- **확인하지 못한 것 — 왜 안 돌았는지.** 세 가지가 모두 가능하고, 이 한 번으로는 가를 수 없다.
  - 훅 모양이 Codex가 알아보는 모양이 아니었을 수 있다. 모양은 바이너리 문자열에서 짐작한 것이고, 모르는 칸은 오류 없이 무시됐을 수 있다.
  - 신뢰하지 않은 훅은 건너뛰는 장치(`trusted_hash`)가 있을 수 있다.
  - 참여자 옵션이 훅 실행을 막을 수 있다.
- **그래서 방어는 그대로 둔다.** Codex는 이 파일을 참여자 옵션으로도 읽는다(합성 HOME 관측). 사용자가 신뢰한 훅이 참여자 실행 중에 돌지 않는다고 볼 근거는 아직 없다. `hooks.json`이 있으면 참여자 계획을 거절하는 S4 검사를 유지한다.
- 설정 안의 훅, 프로젝트·플러그인·관리형 훅 층은 이번에도 보지 않았다.
