## 7. 아쉬웠던 것

### 일하는 방식

1. **같은 외부 도구를 여러 번 분석했다.** ChatGPT(#102), 독립 리뷰 B, claude(#105)가 각각 codex-peek를 해체했고, 그것을 비교(#103)하고 다시 통합(#106)했다. 결론은 첫 리뷰와 같았고, 뒤로 갈수록 새로 나온 사실은 리뷰마다 한두 개였다. 외부 도구 검토는 한 번의 분석과 한 번의 반박 검토로 충분하다. 더 할 때는 앞 리뷰가 답하지 못한 질문을 먼저 적는다.
2. **끝난 기능 PR 위에 리뷰가 쌓였다.** #101은 2026-09-26에 CI가 녹색이 됐지만 병합되지 않았고, 인계·색인을 함께 고치는 리뷰 PR 넷이 협업 규칙(같은 파일을 고치면 그 브랜치 위에서 시작)대로 그 위에 차례로 쌓였다. 모두 제품 코드를 품은 초안이 됐고, main에서 따로 난 #105와는 인계·색인이 충돌했다. 끝난 기능 PR은 리뷰를 쌓기 전에 병합을 요청하는 편이 낫다.
3. **새 화면을 아무도 눈으로 보지 않았다.** 구현 세션(웹 컨테이너, 브라우저 없음)도, 리뷰 넷도 화면을 띄우지 않았다. 처음 눌러 본 이 세션이 몇 분 만에 글자 버그 둘을 봤다. S3 카드의 완료 조건에 "모의 서버를 브라우저로 한 번 눌러 보기"를 넣었다.
4. **증거 파일이 무겁다.** 전체 시험 로그(약 105 KB), 바이너리 zip(약 67 KB), 빈 로그 파일이 날짜 기록에 들어갔다. 날짜 기록이라 지우지 않는다. 요약·해시·CI 링크면 충분했다. 규칙으로 만들지는 않았다 — 협업 규칙 7절의 다섯 질문을 거칠 일이다.
5. **문서가 길고 같은 단서가 되풀이된다.** "합의는 검증이 아니다", "CI 성공은 수정 완료가 아니다" 같은 단서가 문서마다 여러 번 나온다. 사용자가 읽을 짧은 요약이 없었다. 이 기록 1절이 그 자리다.
