## 범위와 결론

작성: ChatGPT 웹 세션. 브랜치 `chatgpt/deep-review-20260925`, [PR #52](https://github.com/inlight37-design/decision-model_lab/pull/52). 기준 main: `6cd13633ee41ebc26acff7fa71d62953f3bbd43f`(PR #51까지 병합). 시작 시 다른 열린 PR은 없었다.

**방향은 유지할 만하다. 그러나 인용 무결성·원장 복원·정상 종료의 경계조건에 실제 결함이 있었다.** 새 실행 프레임워크로 갈아엎지 않고 기존 책임 경계 안에서 수정했다. 코드가 짧다는 이유만으로 안전하다고 평가하지 않았고, 파일 길이를 줄이기 위한 형식적인 분할도 하지 않았다.

GitHub 연결로 코드·인계·CI를 읽고 수정했고, 실행 검증은 기존 GitHub Actions를 사용했다. 웹 컨테이너에서 저장소를 실행하지 못했으며 사용자 PC·설치 CLI·실제 계정 상태를 직접 관측하지 않았다. 실제 모델 호출은 없었다. 기존 실험 원장, 인증 자료, main 보호, 구독 정책, 호출 상한을 바꾸지 않았다.

검토 중심: `app/controller.py`, `app/state.py`, `app/store.py`, `app/server.py`, `app/synthesis.py`, 보고서·실행 계약과 관련 회귀 테스트. 기존 전체 CI도 실행했다. 모든 소스 줄의 독립 감사나 모든 결함 부재를 주장하지 않는다.

## 재현한 문제와 수정

| 항목 | 조건과 영향 | 수정·검증 |
|---|---|---|
| R1 — 인용 공백 손실 | 합성자의 인용을 `strip()`한 뒤 비교했다. 원문에 없는 경계 공백을 붙인 인용이 일치로 판정되거나 실제 인용의 공백·개행과 위치가 바뀌었다. | 유효성 검사만 하고 원래 인용 문자열로 검색·위치 대조한다. 실제 경계 공백·개행·한글·이모지 및 불일치 사례를 검사한다. |
| R2 — 잘못된 Unicode로 합성 결과 저장 실패 | JSON이 허용하는 고립 surrogate가 결과에 들어가면 UTF-8/SQLite 저장에서 실패할 수 있었다. 종료 사건 없이 시작 사건만 남으면 합성이 종료 미확인으로 남는다. | 저장되는 합성 텍스트·인용·이름표의 UTF-8 유효성을 검사하고 `SynthesisError`로 거절한다. controller 통합 테스트에서 실패 사건, 자리 해제, 원문 보존, 재호출 금지를 함께 확인한다. 정상 surrogate 쌍은 받는다. |
| R3 — 중복 JSON 키의 조용한 덮어쓰기 | JSON 객체에 `claims`나 인용 이름표 등 같은 키가 중복되면 마지막 값만 남아 앞의 근거·소수 의견이 사라질 수 있었다. | `object_pairs_hook`으로 중첩 객체까지 중복 키를 거절한다. 통째 JSON·코드 울타리·앞 설명이 붙은 응답 모두 검사한다. 모호한 객체를 다른 후보로 조용히 구제하지 않는다. |
| R4 — 저장된 호출 상한을 무검사 복원 | 처음 설정할 때의 검사는 있었지만 저장된 전체·provider 상한을 다시 읽을 때 형식을 검사하지 않았다. SQLite의 양의 실수와 JSON `null`·배열·잘못된 값이 정책 판정을 흐리거나 시작을 깨뜨릴 수 있었다. | 전체 상한은 양의 정수, provider 상한은 비어 있지 않은 문자열 키와 양의 정수 값의 객체인지 재검사한다. 손상은 `StoreError`로 거절하고 원장·예약은 보존한다. 유효한 이전 원장과 설정 생략 시 복원도 검사한다. |
| R5 — 사건 종류 조회의 불필요한 전체 검색 | 호출 예약·합성 사건 조회를 위해 무관한 사건 행까지 탐색했다. 반복 화면 조회와 원장 성장에 불리하다. | `events(kind, run_id, seq)` 인덱스 하나를 추가했다. `EXPLAIN QUERY PLAN`의 검색 사용, 사건 순서, 반복 열기, 이전 원장 보존과 미래 스키마 거절을 검사한다. 캐시나 새 상태 테이블은 만들지 않았다. |
| R6 — 서버 정상 종료의 정리 누락 | 기존 main의 `Ctrl+C` 처리는 진행 중인 실행기에 취소를 알리거나 결과 저장을 기다리지 않고 반환했다. daemon 작업은 기록을 마무리하지 못할 수 있었다. | 새 호출 차단 → 실행기 취소 신호 → HTTP handler 회수 → worker 결과 저장 대기 → 원장 닫기 순서로 정리한다. 종료 미확인이 남으면 정상 종료로 표시하지 않는다. 대기 시도·공개 원문·예약을 보존하고 재시작 뒤에는 명시적인 resume을 요구한다. |

R1–R3은 인용의 **문자열 대조 무결성**을 고친 것이다. 인용이 주장을 의미적으로 뒷받침한다거나, 소수 의견이 모두 포함된다거나, 최종 판단이 참이라는 검증은 아니다. R2도 모든 CLI 메타데이터·모든 외부 입력에 대한 포괄적인 Unicode 감사는 아니다.

### 종료 처리의 중요한 구분

`Controller.shutdown()`의 반환값은 이 controller가 소유한 worker가 반환했는지 뜻한다. 자손 프로세스가 모두 사라졌다는 증거가 아니다. `unknown`과 runner의 미정리 자손은 별도로 확인하고, 자리·예약을 자동 환불하지 않는다. 살아 있는 writer가 남으면 Store를 먼저 닫지 않는다. 같은 `serve_forever()` 스레드에서 `server.shutdown()`을 호출하지 않아 교착을 피한다.

`wait_idle(0)`은 즉시 현재 상태를 검사하며, 음수·NaN·무한대 대기 시간은 거절한다. 종료 중인 controller에 `resume`, 새 실행, 실제 합성을 요청해도 다시 호출을 시작하지 않는다. 강제 종료·전원 손실·SIGKILL까지 정상 정리가 보장된다는 뜻은 아니다.

## 아키텍처 판단

**유지할 것:** 상태를 바꾸는 controller 하나, 원장 상태와 사건의 같은 거래 기록, 공개 전 봉인 관문, 결과 수용과 자손 종료 확인의 구분, 계획을 기록한 뒤 같은 계획으로 실행하는 계약, 종료 미확인 시 자동 재호출하지 않는 정책이다. `app/state.py`는 상태를 다시 저장하는 관리자가 아니라 투영·판정 역할이다. 이 경계를 더 많은 서비스·플러그인 계층으로 나눌 근거는 이번 검토에서 찾지 못했다.

**늘리지 않은 것:** 외부 의존성, 새 실행 프레임워크, 상태 캐시, 범용 이벤트 버스, 새 영속 상태 테이블, 자동 재시도, 실제 모델 호출, 관측 없이 정책을 통과시키는 예외다. 추가 상태 `_closing`은 종료 중 새 작업을 금지하는 현재 프로세스의 수명 상태이며 원장의 실행 상태를 복제하지 않는다.

**남은 성장 경계:** `view()`는 전체 실행과 여러 사건 투영을 읽는다. 이번 인덱스로 무관한 종류의 행 탐색은 줄였지만, 긴 이력의 JSON 크기·반복 투영·큰 화면 비용을 해결한 것은 아니다. 이력이 크게 늘기 전 목록/상세 조회 분리와 페이지 단위 조회를 실제 부하 자료로 결정해야 한다. controller는 긴 파일이므로 다음 기능을 넣을 때 읽기 전용 화면 투영의 분리를 우선 검토하되, 같은 상태를 여러 곳에서 소유하도록 나누지는 않는다.

## 검증과 중간 실패 기록

기존 CI 설정과 assertion을 약화하지 않았다. 재현 테스트를 먼저 커밋하고, 수정 후 기존 전체 검사로 회귀를 확인했다.

- 합성 수정 `3e4cd53bf3b3030b34bea6360d5e55613531d69b`: [Actions 36049311577](https://github.com/inlight37-design/decision-model_lab/actions/runs/36049311577), Linux Python 3.12/3.13·Windows 모두 통과했다.
- 종료 통합 `cc16c628ba370ea140c28e6b3119e2b20e2aa99e`: [Actions 36051365141](https://github.com/inlight37-design/decision-model_lab/actions/runs/36051365141)에서 기존 HTTP 스레드 시작 실패 테스트가 회귀를 잡았다. CPython `ThreadingMixIn`이 시작 전에 목록에 넣은 미시작 스레드를 종료 시 join하려는 문제였다. 미시작·끝난 항목만 회수하고 실행 중인 handler는 보존하도록 수정했다. 이미 실행 중인 handler가 있는 경우의 추가 회귀 테스트도 넣었다.
- 추가 경계 테스트 `b0f24fb185258a193a02495391b4194312696481`: [Actions 36053253182](https://github.com/inlight37-design/decision-model_lab/actions/runs/36053253182)의 Windows 검사에서 이 세션이 추가한 SQLite 검사 연결의 미종료가 임시 파일 정리를 막았다. 거래 문맥과 연결 수명을 구분해 `closing()`으로 수정했다(`8c15cbe94731d45f7aac1c61a4faf86dc099ae62`). 이 실패를 제품 코드 결함이나 Windows 지원 불가로 바꾸어 보고하지 않는다.

새 테스트 파일은 합성 입력 무결성, 원장 복원·쿼리, controller/server 종료, 종료 경계다. **이 문서 커밋 시점에는 마지막 수정 뒤 최종 CI를 아직 확인하지 않았다. 최종 정확한 head의 결과는 PR #52에 갱신한다.** 이전 녹색 결과를 뒤의 수정까지 검증한 것으로 취급하지 않는다.
