**D1(다듬기).** 슈퍼바이저는 두 차례 모두 정해진 JSON 하나(`refined`·`changes`·`ask`)로 답했다. 1차례의 다듬은 질문에는 판단 기준의 예시 범주(검색 품질·비용·문서 특성·인프라)가 괄호로 들어갔다 — 지시문은 "답을 암시하지 않는다"를 요구하지만, 범주 목록은 팀원의 답을 그 틀로 끌 수 있는 경계선이다. 사람이 2차례에 "예시 목록은 빼 달라"고 쓰자 목록을 빼고 사람이 준 조건(문서 규모·불만·예산)만 넣었고, 바뀐 점에 그렇게 적었다. 2차례를 승인해 실행했다. 원장의 참여자 입력에는 승인한 문장만 있었다 — 원문·사람이 쓴 말은 들어 있지 않았다. 두 팀원 모두 "전면 전환보다 보완·하이브리드"로 결론 냈다(합의는 검증이 아니다). 독립 정족수 2/2 충족.

**C1(일반 팀원).** 팀원마다 다른 맡길 일과 가상 자료 파일 하나씩(Claude는 `a.md`만, Codex는 `b.md`만)을 줬다. Claude의 결과가 Codex가 도는 동안 먼저 화면에 보였고, 둘 다 끝나자 "모두 끝남"과 "결과 모아 판단"이 됐다. 두 답은 각자 받은 파일만 근거로 들었다 — 팀원별 자료 폴더와 들어맞지만 격리의 증명은 아니다. 메모와 함께 판단 완료했다.

## 확인하다 찾은 것

1. **작업의 "쓴 CLI 호출"이 다듬기 차례를 빼고 셌다.** D1 작업 카드가 2로 보였다(실제 4). 이 기록을 들인 PR에서 실행에 묶인 다듬기 차례를 더하게 고쳤다.
2. **Windows 쪽 다른 프로그램이 8765를 쥐고 있으면 앱 창이 그 프로그램을 연다.** WSL 안의 서버는 8765가 비었다고 보고 거기에 뜨지만, Windows의 `127.0.0.1:8765`는 그 프로그램에 닿는다. 이번에는 사용자의 다른 로컬 서버(인증 없는 안내 페이지)가 나왔다 — 페이지 하나를 읽었을 뿐 아무 요청도 보내지 않았다. 토큰은 주소의 `#` 뒤라 그 서버로 가지 않는다. 같은 PR에서 바탕 화면 아이콘(`start.ps1`)이 Windows에서 이미 쓰는 포트를 `--avoid-ports`로 넘기고 launcher가 그 포트를 건너뛰게 고쳤다. 모의 모드로 8765를 뺀 launcher가 8766에 떠 Windows에서 앱에 닿는 것을 확인했다(모델 호출 없음). 아이콘으로 여는 흐름 전체는 사용자가 다음에 열 때 확인된다.

- 다듬기의 답 누설을 여러 질문에서 본 것 — 한 질문, 한 슈퍼바이저 모델뿐이다.
- 사용자가 직접 써 본 소감(인계 3절의 사용자 몫).
