## 판단에 적용한 현재 결정

기준은 [AGENTS](../../../AGENTS.md), [현재 인계](../../../NEXT-SESSION.md), [협업 규칙](../../COLLABORATION.md)다. 과거 검토의 권고보다 현재 코드와 이후 사용자 결정을 우선한다.

- 여러 제품에서 좋은 부품을 배우되 한 제품 전체를 기반으로 바꾸지 않는다.
- 공식 구독 CLI와 현재 WSL 실행 경계, provider별 호출 예산, 한 원장 소유자와 한 writer, 독립 초안·미합의 보존을 유지한다.
- 자동 기억은 같은 작업·같은 원장의 공개 이력을 일반 팀원과 상위 역할에 적용한다. 격리 초안에는 적용하지 않는다.
- 실제 역할별 실행·공개 조회·입력 고정·호출 기록이 분리된 현재 구현을 먼저 인정한다. 전면 재작성, 미구현을 가정한 새 프레임워크, 이미 있는 hash/CAS/종료 방어의 재지적을 피한다.
- 이번 요청은 분석 문서 작성이다. 제품 구현·의존성 변경·사용자 PC 환경 변경은 하지 않는다. 별도 검토 브랜치와 PR로 결과를 제안한다. 병합은 저장소의 기존 담당 규칙을 따른다.

## 읽기와 증거의 기준

1. 실제 `app/`·`core/`의 호출 경로와 관련 시험을 기준 SHA에서 추적한다.
2. [현재 구조](../../../app/ARCHITECTURE.md), [기능 지도](../../FEATURES.md), [참고 지도](../../REFERENCE-MAP.md), [일반 팀원 검토 설계](../../architecture/general-team-review/README.md)를 코드와 대조한다.
3. 10월 4일 개편 준비서와 기능 후보 목록은 그 날짜의 설계 기록이다. 이후 구현된 항목을 미구현 과제로 다시 세지 않는다.
4. 외부 프로젝트는 저장소가 수집한 출처·판본에서 출발한다. 직접 다시 읽은 upstream 코드·공식 문서와 기존 연구 문서만 확인한 항목을 구별한다.
5. 확정한 문제는 파일·함수·줄 범위와 고정 SHA 링크, 가능한 경우 모델 없는 재현을 붙인다. 설계 개선·제품 선택·미확인 가설은 결함과 구별한다.
6. 오프라인 통과는 모델 품질·사실성·실제 CLI의 현재 가용성·사용자 PC 성능을 입증하지 않는다. 합의와 원문 인용 일치도 사실 검증으로 해석하지 않는다.

## 분담과 보존

실행 수명·회계, 입력·기억·결과 판, 화면·워크플로우, 기억 계열 외부 기능, 운영 계열 외부 기능을 병렬로 읽는다. 총괄 검토에서 서로의 전제와 코드 경로를 맞추고 우선순위를 통합한다. 이는 이 문서 작성 과정의 분담이며 프로젝트 앱에서 모델을 실행하는 실험이 아니다.

이 기준 파일을 먼저 커밋하고 원격에 보존한다. 이후 실제 발견이 정리될 때 분석 문서, 외부 기능 매핑, 최종 검증·인계를 순차 커밋한다. 최종 판은 이 폴더의 README에서 읽는다.
