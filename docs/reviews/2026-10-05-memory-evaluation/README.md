# 자동 기억 선택·발췌 평가 — 2026-10-05

기준은 조회 개선 PR #169의 `f3e365f07748c3fea5432754439ccd87c1a5f23c`. 클라우드 임시 원장만 사용했고 실제 사용자 기록·PC·모델 호출은 없다. 카드 #170의 작업이며 [고정 사례](../../../tests/fixtures/memory_cases.json), [이전](before.json), [이후](after.json)의 corpus hash를 대조할 수 있다.

## 먼저 재현한 누락

한국어 조사·띄어쓰기, 판단 메모의 금지/부정, 지적에만 있는 반대 근거, 긴 질문/메모 뒤의 지적, 긴 첫 지적 뒤의 두 번째 지적, 상반된 판단, 봉인 제외, 손상 답 제외, UTF-8/이스케이프 상한을 평가했다. 별도로 최근 후보 밖의 과거, 동의어, 답 본문에만 있는 표현을 한계 사례로 뒀다.

| 구분 | 이전 | 이후 |
|---|---|---|
| 지원 대상으로 고정한 사례 | 10개 중 6개 충족 | 10개 충족 |
| 고친 누락 | 메모의 부정·지적만의 표현을 놓침; 긴 질문/메모와 첫 지적이 뒤 반례를 밀어냄 | 메모·수용된 지적도 점수에 반영; 섹션/지적 사이 공간 분배 |
| 알려진 한계 사례 | 3개 모두 누락 | 그대로 누락하며 범위와 이유를 명시 |

`python tools/evaluate_memory.py --check`는 지원 사례를 검사하고 알려진 한계는 별도로 보고한다. 이후 성공률은 이 작은 고정 합성 corpus 안의 기록/표식 포함 여부이며, 검색 일반화 성능·의미 이해·모델 답 품질을 측정하지 않는다. 별도 held-out corpus나 사용자 실측은 없다.

## 구현 판단

- 최근 후보 상한을 늘려 누락을 숨기지 않았다. 질문·판단 메모·검토 지적의 어휘를 비교하고 후보 안에서 드문 표현과 완전한 단어에 가중치를 줬다. 일치가 없으면 최근 기록 대체를 명시한다. 부정을 해석하거나 찬성 답만 고르지 않는다.
- 질문·판단·지적·수정·답의 공간을 나누고 지적들 사이에도 분배한다. 미해결/조건부 처분을 앞에 두며 남는 공간은 재분배한다. 발췌는 원문 조각이고 모델 요약은 없다.
- 검토/수정 출처, 섹션별 생략 바이트, 후보 범위 밖·미선택 수를 pack hash 안에 넣고 전달문 전체 상한을 유지한다. 원본 JSON 문맥은 별도 canonical source hash로 결속한다.
- 기존 frozen pack·입력·승인 기록을 다시 선택하거나 새 policy로 덮어쓰지 않는다. 새 정책으로 미리보기 입력이 달라지면 기존 확인 hash가 시작을 거절한다. 격리 초안/교차검토/수정의 기억 제외는 유지한다.

## 검증과 남은 범위

기억 역할 범위·재시작 고정·손상 거절·선택 이유/누락 hash·UTF-8 상한, 수정/재검토 이력, 공개 조회 회귀를 실행했다. UI에는 일치한 위치, 후보 범위, 잘린 섹션을 표시한다. CLI adapter·모델·유료 API를 바꾸지 않았다. 최신 PR CI는 PR Checks를 기준으로 한다.

오래된 후보 밖 기록·동의어·답 본문만의 표현은 전체 공개 검색/출처로 확인해야 한다. 긴 지적 자체의 뒤쪽 부정도 잘릴 수 있으며 누락량이 0이 아닌 섹션을 완전한 근거로 읽지 않는다. 반례가 꼭 모두 전달된다는 보장이나 semantic agreement 판정은 추가하지 않았다.
