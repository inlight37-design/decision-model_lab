## 정정: 리뷰 본문의 WM-07 답변

README의 질문 2 표에서 WM-07 행은 간결성·책임 분리를 논하고 있다. 이는 WM-07의 실제 주제인 **잔류 입출력 스레드·fd와 미정리 상한**에 답하지 못한 편집 오류다. 해당 행의 답변은 다음으로 정정한다. 날짜 기록 원문은 덮어쓰지 않고 검토 목록에서 이 정정을 연결한다.

**WM-07 — 부분 동의.** `core/runner.py`의 `_execute()`는 정리 대기 뒤 살아 있는 reader·writer를 `_LINGERING`에 넣고, `lingering()`은 종료된 스레드를 제거한 뒤 남은 수를 반환한다. `tests/test_core_runner.py::test_a_descendant_holding_the_pipes_does_not_hang_the_return`은 격리 없는 POSIX 자손이 파이프를 쥐고 있을 때 잔류가 드러나고, 시험이 만든 자손을 끝내면 0으로 내려가는 것을 검사한다. 이 시험의 성공을 위 CI 원문에서도 확인했다.

`app/controller.py`의 `unsettled()`는 UNKNOWN 참여자 수와 `runner.lingering()`을 합하며, `pump()`는 시작 전에 그 값과 상한을 비교한다. 따라서 잔류를 감추지 않고 새 작업을 억제하는 구현은 있다. 이는 서로 다른 단위(시도 수와 스레드 수)를 더한 **보수적인 admission 지표**이며 정확한 미정리 시도 수·fd 수·OS 자원 상한과 같지 않다. 진행 중인 시도가 끝나며 잔류가 늘 수 있으므로 이 임계값을 "언제나 넘지 않는 하드 상한"으로 설명해서도 안 된다. 여러 controller의 소유권·재시작 정합성은 A1-03·05의 별도 문제다. 비차단 I/O로 전면 재작성하지 않은 선택에는 동의하되, 이 지표만으로 장시간·동시성·메모리/CPU 상한이 검증됐다고 보지 않는다.

이 정정은 기존 A1-01–09의 심각도나 실제 호출 전 보강 권고를 철회하는 것이 아니다.

## 다음 구현자가 우선 닫을 관문

1. **봉인 투영:** controller 소유의 고정 상태 코드와 필드 허용 목록으로 공개 전 응답을 제한한다. 원문 진단 표식이 응답 어디에도 없는지 검사한다.
2. **결과 수용:** 해당 시도의 입력 전송 계약, 비어 있지 않은 초안, 성공·전체 자손 종료, 알려진 모델 불일치의 처리를 연결한다.
3. **상태 전이:** 원장 단위 단일 소유권, attempt/세대에 묶인 조건부 완료, 완료 초안의 멱등 복구, 현재 구성에 묶인 축소 승인을 둔다. UNKNOWN을 자동 재호출하지 않는다.
4. **마운트 계획:** 자동 시스템 연결까지 포함한 유효 계획에 never와 충돌 검사를 적용한다. Codex의 RW 설정 아래 RO 실행 버전 연결은 의도된 예외로 보존한다.

기존 작은 모듈 구조를 유지하면서 이 경계의 회귀 시험을 먼저 넣는다. 별도 workflow 엔진·두 번째 격리 백엔드·전면 UI 전환은 이 결함의 선행 해결책이 아니다. 실제 모델 호출은 여기서 하지 않았고, 후속 승인에서도 provider별 최대 시작 횟수·실패 포함 예산·중단 조건을 먼저 고정해야 한다.

## PR 마무리와 한계

재개 시 기존 브랜치에는 리뷰와 증거가 있었지만 PR과 인계 연결은 없었다. 이번 재개 작업은 같은 브랜치에 체크포인트와 이 검증·정정을 덧붙이고, 명백한 AGENTS 현재 상태 오류와 NEXT 3절·검토 목록 연결을 마무리한다. 제품 실행 코드와 과거 작성자의 RESPONSE는 변경하지 않는다. 병합하지 않는다.

최종 head의 CI는 PR의 Checks에서 별도로 확인한다. 위 과거 재현 실행의 녹색을 새 head의 녹색으로 대신하지 않는다. 사용자 WSL의 실제 모델·토큰 갱신, Windows 실행, 브라우저 렌더링/공격, 장시간 부하, 실제 전원 차단, 최신 약관 해석은 이 재개 검증으로 확인하지 않았다.
