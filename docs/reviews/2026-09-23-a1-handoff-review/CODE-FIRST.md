# 코드·시험을 먼저 읽고 남긴 잠정 판단

기준: `4bbd034b33649f0ae570b37eecc17d3176669420` · ChatGPT · 2026-09-23.

요청서의 순서에 따라 AGENTS, 협업 규칙, 사용자 확정 사항, 이전 WM-01–WM-07, 현재 core/app 코드와 관련 시험을 먼저 읽었다. NEXT-SESSION의 사용자 확정 사항을 찾는 과정에서 1절 일부(Q 표 포함)도 읽었으므로 완전한 맹검이라고 주장하지 않는다. 아직 이번 작성자의 RESPONSE, app README, K 표·다음 계획, 디자인 문서와 보관 인계를 대조하지 않았다. 아래는 **실행 재현 전의 코드상 가설**이며 최종 판정은 이 폴더의 README에 남긴다.

- WM 입력 전달 추적, 명령 인자에서 환경 값 제거, 단일 격리 실행 진입점, 빈 PATH 거절, 파서 타입·깊이 경계는 실제로 구현됐다. 이전 지적을 그대로 재사용하지 않는다.
- 봉인 투영은 usage/duration/reported_models만 제외한다. CLI에서 나온 terminal_reason/error.message가 Outcome.detail을 거쳐 공개 전 API와 화면으로 나온다. 내용이 든 실패 문구가 누출될 수 있는지 합성 표식으로 시험한다.
- A1은 stdin이 없는 결과(None)를 complete와 함께 받으며, 빈 CLI 답과 알려진 모델 불일치도 수용한다. 일반 어댑터의 과거 호환성과 A1의 고정 stdin 계약을 구별해야 한다.
- server.serve는 포트 bind보다 먼저 journal 회복과 토큰 파일 교체를 한다. 같은 데이터로 두 번째 시작에 실패해도 첫 실행에 영향을 줄 수 있다. _finish는 현재 상태·attempt 소유권을 검사하지 않아 오래된 완료가 UNKNOWN을 덮을 가능성이 있다.
- 최종 draft 저장과 공개 단계 전환은 다른 transaction이다. 재시작은 RUNNING만 UNKNOWN으로 바꾸며 완료된 draft의 공개 재평가와 queued 시작은 하지 않는다. 충돌/중단 경계에서 멈추는지 시험한다.
- 축소 승인은 구성과 연결되지 않은 boolean이다. 이탈 전에 승인한 값이 나중에 다른 구성에 적용될 수 있다.
- WM-04의 충돌 검사는 work가 RO를 품는 방향만 막는다. work가 RO 입력 아래에 있으면 마지막 RW bind가 입력 일부를 다시 쓰기 가능하게 만들 수 있다. never 검사에는 자동 /usr·/etc 연결도 포함되지 않는다. 실제 bwrap으로 확인한다.
- 원본 앱 참여는 사용자가 확정한 요구다. 이를 제거하자고 권하지 않는다. 독립성 미확인 참여자를 어떤 정족수에 넣을지는 표시·정책 문제와 분리한다.
- AGENTS에는 여전히 controller/app이 없다는 문장이 있다. 명백한 현재 상태 오류이므로 리뷰 PR에서 해당 원문을 정정할 후보이다.

## 재현 범위

별도 웹 컨테이너에는 bwrap과 repository checkout이 없다. 로컬에서는 재현 스크립트 문법만 확인했다. 실제 시험은 검토 브랜치의 기존 GitHub Actions에서, 원본 코드의 Git blob SHA를 확인한 후 실행하도록 준비한다. 모델·실제 인증·사용자 PC는 사용하지 않는다. CI 실행용 임시 unittest 연결 파일은 최종 PR에서 제거하고, 독립 실행 스크립트와 결과만 보존한다.
