그 뒤 다른 Claude 세션이 [PR #76](https://github.com/inlight37-design/decision-model_lab/pull/76)으로 검토 전문·추가 대조·재현 코드·결과를 main `01cedd3c05dc043465d4476aab2b1a8f547574e9`에 들였다. 최신 `NEXT-SESSION.md` 3절에도 검토와 다음 순서가 반영돼 있다. ChatGPT는 #74·#76을 병합하지 않았다.

이 마지막 인계는 **그 main의 모든 기존 파일을 그대로 보존**한다. 다른 세션이 줄인 인계·규칙·검토 색인·CI 설정을 되돌리지 않는다. 중복된 검토 전문 사본과 요약 색인을 다시 추가하지 않고, 기존 결과에 이 완료 기록만 보탠다. 새 코드·설치·설정·기존 관측·원장 변경은 없다. PR #75를 main에 병합하지 않는다.

## 검증과 재현 경로

직접 사용한 환경은 GitHub 연결 도구와 별도 Linux 웹 컨테이너(Python 3.13.5)다. 사용자 PC의 Windows·WSL·로그인·실제 CLI를 새로 확인하지 않았다. 추가 모델/구독 CLI 호출은 0이다. 전체 로컬 clone은 DNS 실패로 중단됐으므로 전체 로컬 시험 통과를 주장하지 않는다.

`probe.py`의 Git blob `13d6e17ef4123916f93ef1c91f89ff11eacf8629`와 `probe-results.json`의 `7ab71d83c336ae7d63ffaeab5238abb0f09ba763`은 실제 실행해 원격에 올린 것과 #76이 들인 파일이 같다. 원본 셸과 무해한 명령 대역에서 버전 조회 실패 뒤 latest 선택/종료 0, 검토한 설치 파일 A 대신 승인 재실행에서 새 파일 B 실행을 재현했다. Python의 인증 표시·버전 비교·Unicode/SQLite 경계도 재현했다. 같은 스크립트의 마지막 재실행 결과가 처음 JSON과 같았고 Python 컴파일 검사·원본 셸의 `bash -n`은 종료 0이었다. 실제 설치·네트워크 요청·모델 호출은 하지 않았다.

재현 스크립트는 최초 설치 원문의 해시를 검사하므로 **최신 main을 `--root .`로 주면 중단하는 것이 맞다.** 기준판의 별도 checkout을 입력으로 사용한다. 아래 첫 명령은 지정한 경로가 이미 있으면 중단하도록 두며, 기존 worktree를 지우거나 덮어쓰지 않는다.

```sh
git worktree add --detach ../dml-review-source-2f76a1a 2f76a1a6fdd6b4ca8edf5111460f7ae806c8977b
python docs/reviews/2026-09-25-review/probe.py --root ../dml-review-source-2f76a1a
```

위 checkout 방식 자체를 이 세션의 웹 컨테이너에서 실행한 것은 아니다. 이 세션은 정확한 blob을 확인한 원문 사본으로 재현했다. 원본 파일을 저장소에 중복 추가하거나 새 판에서 해시 검사만 꺼서 옛 실험인 것처럼 실행하지 않는다. `probe-results.json`의 `checkpoint_next`는 최초 중간 저장 때의 재개 메모이지 현재 미완료 목록이 아니다.

처음 제출한 head `a70c7b1`의 CI는 보존한 옛 문서가 삭제된 Windows 파일을 상대 링크로 가리켜 실패했다. `c48c0188`에서 그 링크 한 줄을 기준판 URL로 바꿨고, #76도 원문의 설치 소스 링크를 기준판으로 고정했다. 마지막에는 #76의 수정본을 보존했다. **최종 CI 판정은 PR #75의 정확한 제출 head와 Checks/완료 댓글이 기준**이며, 이전 head의 결과를 새 head의 통과로 쓰지 않는다. CI 성공은 설치 결함 해결이나 실제 PC 통과의 증거가 아니다.

## 최신 사용자 결정과 최초 검토의 구분

최초 L1 제안은 당시 코드의 ‘실행마다 합성 한 번, 참여자 provider만 합성자’ 제약을 전제로 했다. 최신 인계 2절 23번에는 사용자가 그 제약을 없애기로 정한 것이 기록됐다. 그 결정을 되돌리지 않는다. 구현 이후에는 고정된 공개 초안에 여러 합성자를 비교하는 설계가 가능해질 수 있으므로, 최초 검토를 영구 제약으로 읽지 않는다. 상한·동시 하나·종료 미확인 규칙은 최신 결정대로 보존한다. 실험을 시작하기 전 구현 상태와 배정·분모·호출 상한을 다시 확인한다.

검토는 #70/설치 경계를 먼저 권했고, 최신 인계는 사용자가 고른 정리 순서를 명시한다. 후속 세션은 최신 사용자 결정과 그 순서를 따른다. 설치 완료의 과도한 성공 표시, #70의 본문·메타데이터 종결 처리, #71의 로컬 환경 등록이라는 핵심 검토 내용은 그대로다. 기록된 제안과 사용자 확정을 섞지 않는다.
