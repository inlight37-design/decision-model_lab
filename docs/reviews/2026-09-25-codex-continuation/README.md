## 확인과 수정

1. **이전 병합은 정상이다(관측).** 시작 시 #85·#86·#87·#88은 merged, 열린 PR과 main에 들어가지 않은 원격 브랜치는 없었다. main의 `offline-checks` [실행 36136615196](https://github.com/inlight37-design/decision-model_lab/actions/runs/36136615196)은 success였다.
2. **카드 #72가 현 구현보다 낡았다(관측·정정).** 실행당 합성 한 번·참여 provider 제한은 이미 없어졌고, `app.run --synthesize codex,claude-code`가 같은 공개 초안으로 두 합성자를 차례로 부른다. 원본 카드에서 고쳤다. 과거 D 후속 결과는 당시 사실이므로 고치지 않는다.
3. **로컬 Windows 검사가 실제로 실패했다(재현·수정).** `shutil.which("bash")`가 WindowsApps의 WSL 실행기를 찾는데, `test_check_setup.py`가 Windows 경로를 Linux bash에 넘겼다. Windows 시스템 폴더 접두사만 제외하는 방식으로는 이 경로를 걸러내지 못한다. 경로 대신 원래 LF 바이트를 stdin에 넣어 `bash -n`으로 검사한다. 문자열 모드 stdin은 Windows에서 CRLF로 바뀌는 것도 재현되어 바이너리 입력을 쓴다. 정상 스크립트 통과뿐 아니라 의도적으로 잘못된 `if then` 입력 거절도 확인했다. 설치 동작 자체는 바꾸지 않았다.
4. **실제 실행을 이어갈 준비가 되어 있었다(관측).** 기존 manifest의 로컬 등록, Codex 0.156.1·Claude Code 2.1.280, 두 현재 계획의 strict 준비 조회를 확인했다. 새 등록이나 재관측을 꾸며 넣지 않았다. 이어서 [L1 사전 등록](../../experiments/2026-09-25-l1/README.md)대로 진행했다. 결과는 그 폴더의 기록이 기준이다.
