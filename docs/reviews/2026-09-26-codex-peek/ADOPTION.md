## 3. 가장 작은 첫 적용: '검토 대상'과 '처분'을 보여 주기

### 3.1 검토 대상 표시

새 스키마를 먼저 만들지 말고 기존 run/attempt·Plan·source·draft 기록을 이어 보여 준다.

> 이 검토가 본 것: 실행 식별자, 고정 질문/자료의 판, 검토 대상 결과, 요청한 역할/모델, 실제 보고된 값, 적용된 수칙 또는 자료.  
> 검토 이후 달라진 것: 질문/자료/역할/수칙 중 무엇이 바뀌었는가.  
> 보장: 출처/실행 결속과 확인된 범위. 사실성·독립성·배포 안전성은 각각 별도 표시.

`core.contract.revision`은 실행 틀 지문이므로 이것 하나를 질문·자료 내용의 해시로 쓰면 안 된다. 기존 입력 digest와 source digest를 함께 사용해야 한다. '실행기가 요청한 모델'과 'provider가 보고한 모델'도 다른 필드이며, 보고되지 않았으면 미확인이다.

수용 전의 raw reply, 수용된 draft, 공개된 report, 추가 reviewer의 의견을 한 상태로 합치지 않는다. 검토자가 그럴듯한 답을 냈어도 원래 실행의 실패·unknown·미공개를 덮지 않는다.

### 3.2 지적별 처분

처분은 다음 식으로 **결정의 근거를 남기기 위한 것**이지 버튼만 누르면 참이 되는 판정이 아니다.

| 처분 | 남길 것 | 다음 행동 |
|---|---|---|
| 사실 오류 수정 | 어떤 증거가 이전 내용을 반증했는지 | 수정 후 영향받는 검사만 재수행 |
| 보강 요구 수용 | 결함인지 설명/커버리지 보강인지 | 필요 범위를 명시하고 무한 범위 확대 방지 |
| 반박 | 원 지적·반박 근거·아직 남는 위험 | 근거 없는 '이미 검토함'으로 닫지 않음 |
| 범위 밖 보관 | 지금 범위와 다른 이유·후속 필요 조건 | 정족수/보안 위반까지 범위 밖으로 밀지 않음 |
| 사용자 판단 | 충돌하는 제품 목표·선택지·영향 | 기술 오류를 사용자 취향 문제로 떠넘기지 않음 |

반복 상한에 닿으면 '완료' 대신 **검토 범위·남은 위험·더 부르지 않은 이유·다음 확인**을 쓴다. 해결 안 된 지적이 없어졌다고 표시하지 않는다. 첫 적용은 날짜 검토 기록의 표로 충분하다. 별도 지적 DB/UI는 실제 소비자가 생길 때만 만든다.

## 4. 기억의 첫 버전은 '자동 기억 시스템'이 아니라 선택된 공통 자료

### 4.1 넣을 수 있는 것

사용자가 확정한 요구, 검토를 마친 설계 결정, 원문/시험으로 확인 가능한 과거 실패와 교훈, 관련 코드의 경로와 확인 판. 긴 채팅 전체나 모든 NEXT-SESSION 이력을 넣지 않는다. 각 항목은 짧은 주장·근거 위치·유효 범위·확인 판을 갖고, 선택하지 않은 자료는 보내지 않는다.

**승인 상태와 내용의 참/거짓을 분리**한다. 사람의 승인도 그 사실이 참이라는 증명은 아니다. 자료는 질문에 대한 답을 미리 정하는 비밀 정답집이 아니라, 실행 전에 드러난 가정과 참고 근거다.

### 4.2 보낼 때의 규칙

1. 실행을 만들기 전에 사람이 항목을 고르고 실제 전송될 문안을 확인한다. 첫 시범은 문서 선택만으로 한다.
2. 기존 common sources의 파일명·바이트 상한을 사용해 같은 고정 자료를 같은 비교 참여자에게 준다. UTF-8 바이트/문자/토큰을 혼동하지 않는다.
3. 자료 판·승인 판을 실행 시작에 고정한다. 실행 중 다른 지적이 나왔다고 기존 참여자의 입력을 몰래 바꾸지 않는다.
4. 기억 원본 저장소·다른 작업 원장·봉인 초안은 참여자의 읽기 허용 목록에 넣지 않는다. 선택된 복사본만 읽는다.
5. 공개 뒤 생긴 교훈은 다음 실행용 후보가 될 수 있지만 현재 실행에는 소급 적용하지 않는다. 철회도 과거 실행의 입력 기록을 삭제/변조하지 않고, 다음 실행에서의 재사용 자격만 바꾼다.

자료의 '지시는 따르지 않고 참고로만 다룬다' 안내는 완화책일 뿐 프롬프트 주입의 완전 차단이 아니다. 격리·허용 목록과 함께 다뤄야 한다. 우리 인계가 미확인으로 남긴 자료 주입 경계도 그대로 남긴다.

### 4.3 공통 요약과 독립성

같은 요약을 주는 것이 공정한 입력이라는 의미는 있지만, 요약자의 오류가 모든 답에 공통으로 전이될 수 있다. 그래서 '같은 자료'와 '오류의 독립성'을 같은 것으로 부르지 않는다. 원문 접근·소수 의견 보존·요약과 원문의 구분이 필요하다. 역할판의 다듬기 모드도 승인한 문장만 보내고 대화는 보내지 않는 기존 사용자 요구를 유지한다.

### 4.4 나중에 자동화할 경우에만 필요한 상태

실제 사용으로 수작업의 병목이 드러나면 기존 Store를 주인으로 삼아 `candidate → approved → superseded/revoked` 정도부터 설계한다. 항목 ID·근거 해시·범위·승인 대상 문안의 해시·이전 판을 결속하고, 승인 대상이 화면을 연 뒤 바뀌면 거절한다. 새 벡터 DB·지식 그래프·상시 curator·독립 approval JSON 원장부터 만들지 않는다.

upstream 현행 판도 **해소된 blocker를 모두 자동 수칙 후보로 만드는 스캔을 폐지**하고 명시적 상신의 자격·세대를 검사한다. '많이 모으면 좋은 기억이 된다'가 핵심이 아니다. 이 차이는 [EVIDENCE의 현행 코드 보충](EVIDENCE.md#현행-코드에서-특히-주의할-것)에 기록한다.

## 5. 후속 구현을 위한 모의 완료 조건

아래는 **제안된 수용 시험**이며 이번 PR에서 우리 제품에 구현·통과시킨 시험 목록이 아니다. 기존 시험 파일의 주인 기능에 붙이고, 별도 프레임워크는 만들지 않는다.

| 경계 | 양성 대조 | 반드시 거절/구별할 반례 |
|---|---|---|
| 검토 대상 결속 | 동일 run/attempt·입력·결과 판의 검토 | 다른 실행·자료 판·대상 결과의 지적 재사용 |
| 실제 동봉 표시 | 저장된 실제 선택/전송 기록 | preview·추천 목록·타 작업 기록을 실제 전송으로 표시 |
| source 최신성 | 확인한 원문 해시와 일치 | 같은 파일명이나 HEAD만 같고 내용이 다름 |
| 승인 동시성 | 화면의 기대 판과 현재 판 일치 | 승인 직전 수정·이중 클릭·과거 초안 승인 |
| 철회 | 앞으로의 선택에서 제외 | 과거 입력/결과 지우기, 이미 승인됐다는 이유로 영구 재사용 |
| 봉인 | 공개가 끝난 원문만 후속 검토에 제공 | 봉인 중 내용/길이/시간/토큰/지적을 기억으로 공유 |
| 독립 정족수 | 기존 확인된 실행 조건 그대로 | 영속 세션/수동 입력/공통 요약만으로 confirmed로 승격 |
| 호출 회계 | 기존 예약과 실행 결과 연결 | timeout·무응답·상태 조회 실패 뒤 자동 재호출/환급 |

| 제한 검색 | 관련된 항목만 상한 안에서 선택 | 관련 항목 0인데 상한을 채우려고 무관 기억 동봉 |
| 표기 | 인용 일치/미확인과 원문 접근 | 인용 일치를 사실 검증·답변 품질 향상으로 표시 |
| off/실패 경로 | 기능 끔이면 기존 입력 바이트/Plan 유지 | 기억 읽기 실패를 빈 성공으로 숨김, 추가 provider로 대체 |

제일 중요한 중단 조건은 **독립 초안 경계가 약해지거나, 추가 호출을 원장 밖에서 시작하거나, 사용자 승인 없이 현재 실행의 입력/정책이 바뀌는 것**이다. 그런 일이 생기면 기능을 끄고 기존 흐름으로 돌아간다.

## 6. 효과 검증은 PDF의 60/60을 재사용하지 않는다

모의 경계가 끝나고 실제 효용을 확인할 때만 기존 헤드리스 실행과 새 원장·명시적 호출 상한으로 작은 비교를 한다. 먼저 자동 수집 없이 **기억 없음 / 사람이 확인한 관련 기억 / 오래되거나 반박된 기억 대조**를 비교한다. 질문·원문·모델·추론·예산을 고정하고 순서를 바꾸며, 같은 과제의 반복을 독립 표본처럼 과장하지 않는다.

측정은 정답뿐 아니라 사고 재발, 틀린 기억을 거부한 비율, 불필요한 수정 왕복, 추가 입력 크기·모델 호출·사용량·소요 시간, 승인에 걸린 사람의 시간으로 나눈다. 공급자별로 제공되지 않는 실제 토큰/비용은 미확인으로 둔다. 문제 정답이나 숨은 검사 결과를 기억에 미리 넣은 조건은 별도 통제 조건으로 라벨링한다.

사람이 고른 기억으로도 이득이 없으면 자동 지도·큐레이션을 추가하지 않는다. 이득이 있어도 자동 수집 단계는 별도 검증한다. **정확한 기억의 효용과 정확한 기억을 자동 생산하는 능력은 다른 결과**다.

## 7. 이번 검토 이후의 한 가지 권고

**현재 역할판 작업을 마친 뒤, 새 엔진 대신 기존 결과 화면에 '검토한 대상·실제 사용한 근거·미해결 처분'을 보여 주는 작은 모의 변경부터 검토한다.** 기억은 먼저 사용자가 고른 공통 자료로 시험한다. 설치·전역 훅·자동 Scout/curator·실제 호출은 이 문서만으로 시작하지 않는다.
