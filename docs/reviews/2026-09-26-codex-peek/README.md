# codex-peek / Codex Bridge 해체분석과 적용 검토

2026-09-26 · ChatGPT · [PR #102](https://github.com/inlight37-design/decision-model_lab/pull/102) · **소스·자료 분석 및 제한된 오프라인 재현 완료. 제품 도입·설치·실제 모델 검증은 하지 않음.**

## 결론

**쓸 만한 부분은 많다. 다만 제품 전체를 설치하거나 엔진을 가져오기보다, 검증·기억·승인에 관한 작은 설계를 기존 controller와 원장에 적용하는 것이 맞다.**

Codex Bridge는 한 프로젝트의 구현·검증·정찰·기억을 장기적으로 연결한다. 우리 앱의 중심은 독립 초안·봉인·공개·비교와 선택적 합성이다. 따라서 영속 검증 세션이나 공유 홈의 훅을 그대로 붙이면 편의와 맞바꿔 독립성·예산 경계를 흐릴 수 있다. 사용자 요구인 '한 제품을 기반으로 채택하지 않는다'와 기존 역할판 개발 순서를 유지한다.

| 판단 | 가져올 부분 | 우리에게 맞추는 방법 |
|---|---|---|
| 우선 참고 | **검증 대상과 실제 결과를 묶는 영수증** | 기존 Plan·입력·자료·결과의 기록을 이어 표시. 새 실행 엔진은 만들지 않음 |

## 특히 중요한 발견

**설치하면 현재 세션에도 영향을 줄 수 있다.** 설치기는 기본 사용자 홈의 운영 사본과 Claude 설정의 훅을 바꾸고 확장 설치를 시도한다. 백업·원자적 파일 교체는 있지만 전체 설치가 하나의 롤백 가능한 거래는 아니다. 이 세션에서는 설치 명령을 실행하지 않았다.

**proof는 정답 증명이 아니다.** 검증 호출을 어떤 세션·작업·판과 연결했는지 확인하는 장치다. v1과 durable v2의 결속 수준도 다르다. 파일·줄·식별자나 발송 발췌에 대한 인용 검사 역시 설명의 사실성까지 보증하지 않는다.

**현행 기억 권위 흐름은 무조건 자동 승격이 아니다.** 해소된 blocker 전체를 자동 수칙 후보로 만드는 스캔은 폐지돼 있다. 명시적 상신·원문/세대/askId 결속과 사용자 승인을 구분한다. 이 차이를 놓치면 '대화가 쌓일수록 자동으로 올바른 규칙이 생긴다'고 잘못 이해하게 된다.

**직접 호출 가드는 격리기가 아니다.** 실제 명령을 실행하지 않는 대역 시험에서 특정 표식 문자열이 포함되면 직접 호출 탐지를 면제하는 국소 반례와, 잘못된 JSON 입력의 fail-open을 확인했다. 운영 환경 침해나 모든 게이트 우회를 재현한 것은 아니다. 우리 shell-free 실행기와 격리 경계를 유지해야 한다.

## 벤치 숫자의 해석

사용자 첨부 PDF는 Warm 첫 구현 `60/60`·사고 재발 `0/60`을 제시하면서, **정확한 기억이 이미 주어진 통제 조건이며 v0.1.103 전체 제품 성능이 아니라고 명시**한다. 같은 자료의 Real Lite는 자동 포착만으로 기억 이점이 확인되지 않았고, F6는 한 사고 유형에서의 end-to-end 확인이다(PDF 1–5쪽).

따라서 '좋은 기억이 있을 때 도움이 된다'와 '좋은 기억을 제품이 자동으로 만든다', '우리 과제에서도 이득이 있다'를 따로 검증해야 한다. 이 검토는 원시 벤치 trace 전체를 재판정하거나 모델 실험을 반복하지 않았다.

## 검증과 다음 판단

오프라인 probe에서 기본 차단·면제 반례·파싱 실패·실제 영수증 선택·세대 정렬·철회/복권·관련성 없는 기억 제외·proof 형식을 확인했다. 배포 JS의 구문 분석도 했다. **예상한 한계가 재현된 것을 제품의 안전성 합격으로 세지 않는다.** 전체 upstream 시험, 실제 설치·모델·사용자 PC·벤치 재현은 미수행이다. 검증 상세는 [EVIDENCE](EVIDENCE.md), 이 PR의 정확한 head별 저장소 검사는 PR Checks와 본문을 기준으로 한다.

중간 결과는 범위 → 해체분석 → 적용안 → 근거/재현의 순서로 즉시 GitHub에 커밋했다. 다음 작업자는 **현재 역할판 PR을 먼저 확인한 뒤, 기존 결과 화면에 검토 대상·실제 근거·미해결 처분을 표시하는 작은 모의 변경**부터 검토한다. 이 문서를 전역 설치나 자동 모델 호출의 승인으로 해석하지 않는다.
