# 2026-09-27 — 결과 모으기(D4)의 실제 CLI 확인과 이 PC의 자원 사용

작성: claude 세션(Claude Opus 5.5), 사용자 PC `DESKTOP-T0UDE01`의 WSL `Ubuntu-24.04`(`main-pc-wsl`). main `ba1a5b1`(D4 병합 뒤)의 코드를 실제 서버로 띄웠다. 모델 호출은 인계 2절 22의 승인 범위이고, 상한은 [카드 #137](https://github.com/inlight37-design/decision-model_lab/issues/137)에 적은 그대로다. 방법은 [D2·D3 확인](../2026-09-27-d2-d3-live/README.md)과 같다. 사용자가 "CPU·GPU를 과하게 쓰지 않는지 보면서 하라"고 해서, 실행 동안 이 PC의 자원도 함께 쟀다.

이 기록은 **한 번의 관측**이다. 품질·일반적 신뢰성의 증명이 아니다. 답 원문은 옮기지 않았고 아래는 요약이다.

## 결과

쓴 호출 3/3(Claude 2, Codex 1). 끝난 뒤 종료 미확인 0이었고, 서버는 정상 종료(종료 코드 0)했으며 포트가 닫힌 것을 확인했다. 모든 호출의 자손 종료를 확인했다. Claude는 요청한 모델을 그대로 보고했다(Codex는 모델을 보고하지 않음, K32). 원장은 스키마 13이다.

| 호출 | provider | 걸린 시간 | 결과 |
|---|---|---|---|
| 일반 팀원(검색 실패 기록) | Claude | 14.3초 | 받음 |
| 일반 팀원(견적) | Codex | 13.8초 | 받음 |
| 결과 모으기 | Claude | 44.7초 | 형식 통과 |

**받은 것.** 모으기 지시문에는 목표, 팀원마다 맡긴 일, 결과 원문이 들어갔다. 경계 줄은 이번 표식이 붙은 두 쌍뿐이었다. 자료 원문에만 있는 줄(파일 제목 줄, "하루 1회 기본")은 들어가지 않았다. 지시문에 보인 자료의 숫자와 파일 이름은 모두 팀원 결과가 인용한 것이다.

**모음.**
- 주장 11개, 인용 15개가 모두 원문과 글자 그대로 일치했다. 원문에 없는 추가 주장은 0개다.
- 겹침·어긋남 2개, 빈 곳 5개, 다음 할 일 5개를 적었다.
- 두 팀원이 결론성 판단을 "자료 밖 판단"으로 스스로 표시한 점도 겹침으로 짚었다.
- 화면에는 "원문 인용 있음"과 "원문 일치" 배지, 사실 검증 안 함 표시, 남은 버튼 "(2/2)"가 보였다.
- 모음이 나온 뒤 작업은 "내 차례"였고, 작업의 쓴 호출 수는 3이었다.

**인용 일치가 사실 확인이 아님을 보여 준 사례.**
- 가상 자료는 "결과 없음 180건 중 절반은 동의어 문제, 나머지는 오래된 문서만 걸림"이라고 적었다.
- Claude 팀원은 그 나머지를 "결과는 나오지만 낡은 문서만 매칭되는 문제"로 풀어 썼다. "결과 없음"과 어긋나는 해석이다.
- 모으기는 이 문장을 그대로 인용해 주장으로 올렸고, 인용 검사는 "원문 일치"였다. 모으기는 자료를 받지 않으므로 이 어긋남을 알 수 없다.
- 이 흐름에서 이런 오류를 잡는 것은 사람의 판단이나, 앞으로의 교차검토(E1, [카드 #140](https://github.com/inlight37-design/decision-model_lab/issues/140))다.

## 이 PC의 자원 사용

2초마다 쟀다. Windows 쪽은 전체 CPU, 남은 메모리, WSL 전체의 CPU(`VmmemWSL`), GPU 3D 사용률이다. WSL 쪽은 CLI·격리·서버 프로세스의 CPU와 메모리다. 이 PC는 논리 코어 16개, 메모리 61.7 GB다. 측정하는 동안 다른 프로그램이 GPU를 거의 다 쓰고 있었으므로, GPU는 그 프로그램 몫과 나머지로 나눠 적는다.

| 구간 | 전체 CPU 평균(최대) | WSL CPU 평균(최대) | 남은 메모리 최소 | GPU — 그 밖의 프로그램 몫 최대 |
|---|---|---|---|---|
| 시작 전 | 16.6% (34.7%) | 0.6% (9.8%) | 32,800 MB | 1.3% |
| 팀원 두 명이 답하는 동안 | 16.5% (26.4%) | 0.8% (3.7%) | 32,191 MB | 1.7% |
| 결과 모으기 동안 | 16.8% (26.5%) | 0.4% (4.2%) | 32,036 MB | 2.5% |
| 끝난 뒤 | 17.6% (24.3%) | 0.1% (0.3%) | 32,260 MB | 1.8% |

- **GPU는 쓰지 않는다.** 모델 계산은 공급자 서버에서 한다. 이 PC에서 도는 것은 요청을 보내고 받는 CLI와 격리(bubblewrap)뿐이다. 측정 중 GPU의 "그 밖" 몫은 1~2.5% 사이에서 움직였고, 호출과 맞물린 변화는 보이지 않았다.
- **CPU도 거의 늘지 않는다.** 전체 CPU 평균은 호출 전후와 같은 16~18%였다. WSL 전체는 최대 4.2%(16코어 기준)였다.
  - 팀원 두 명이 동시에 돌 때 CLI 프로세스(6개)는 코어 하나 기준 최대 27%(순간)를 썼고, 메모리는 합계 최대 185 MB였다.
- **측정의 한계.**
  - 결과 모으기 동안 WSL 프로세스별 기록은 Claude CLI 프로세스를 이름으로 잡지 못했다. 그 구간은 WSL 전체 값으로만 본다.
  - 2초 간격이라 더 짧은 순간값은 놓친다.
  - 긴 자료([1 MiB 실험](../../experiments/2026-09-25-1mib-sources/RESULTS.md))나 더 많은 팀원에서는 재지 않았다.

## 보지 않은 것

- 모으기의 형식 실패·종료 미확인 경로는 모의·합성 시험만 했다.
- 팀원이 실패한 실행의 모으기("결과 없음")도 모의·합성 시험만 했다.
- 모으기 두 번째 호출은 하지 않았다(상한 3을 다 씀).
- 모음의 품질 비교(사람이 모은 것 대비)는 하지 않았다.
