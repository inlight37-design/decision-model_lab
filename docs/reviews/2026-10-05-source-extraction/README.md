# PDF·URL 자료 추출과 순차 구현의 마지막 연결

2026-10-05 · codex · 클라우드 컨테이너·GitHub. 사용자 PC와 실제 모델 CLI는 관측하지 않았다. 모델 호출 없음. 사용자 요청의 기반 점검·통합 → 템플릿 → 수정·재검토 → 자료 추출을 순서대로 구현했다. 이 변경은 수정 PR #165의 `8753eea5428b4815bf48c305d40cb9f144a19051` 위에 쌓았으며, 그 head의 Linux/Windows CI 성공을 확인했다. 기반 PR #161은 사용자 순서 요청에 포함된 통합을 수행했다. 나머지 구현 PR의 base는 main이고 스택 순서는 각 PR에 적었다.

PDF는 설치된 Poppler로 선택한 쪽의 글을 읽고 공개 URL은 인증·쿠키·스크립트 없이 텍스트 응답을 읽는다. URL은 모든 redirect에서 공개 IP를 검사해 그 주소에 연결하고 TLS hostname 검증을 유지한다. 환경 프록시에는 검증한 IP로 CONNECT하며 차단을 우회하지 않는다. 클라우드의 기존 프록시를 통해 example.com을 실제 읽었다. 이 관측은 모든 사이트나 다른 프록시의 호환성을 뜻하지 않는다.

사용자는 추출한 글·선택한 쪽/줄·누락·원본/변환/선택 해시를 미리 보고 사본을 넣는다. `DECISION-SOURCE/1` 글은 기존 자료·템플릿에 그대로 보존된다. 원본 바이너리와 HTTP 응답은 보관하지 않는다. 자료 목록은 제한된 header만 읽으며, 사본 읽기/파일 받기는 전체 저장 해시를 확인한다. 추출 자료가 있는 원문 보고는 `/6`이고 일반 자료의 `/5`는 유지한다. 통합 검토에서 합성 입력의 `/5` 전용 검사도 찾아 두 형식을 받도록 고쳤다. 수정 이력은 원래 초안을 대체하지 않는다.

검사 범위:

- 실제 Poppler로 만든 PDF fixture의 쪽 선택·제외 범위·빈 스캔본 실패. Linux CI는 Poppler 설치를 명시하고 이 검사를 필수로 한다. 설치하지 않은 플랫폼의 skip은 관측 실패와 구분한다.
- HTML의 제외 요소·선택 줄·인코딩·빈/과대 자료·변조·도구 미설치와 동시 추출 제한.
- 내부/예약/혼합 DNS 주소·재지정·프록시 연결·TLS hostname·압축/불완전/과대 응답 경계. multicast가 `is_global`만으로 제외되지 않는 표준 라이브러리 동작을 검사에서 찾아 별도 거절했다.
- 추출 출처의 템플릿→미리보기→확인→격리/일반 실행→검색→보고/모의 합성 연결과 기존 텍스트 계약.
- 실제 Chromium의 PDF 쪽 선택·공개 URL→미리보기→첨부→입력 확인→실행→저장 사본 조회/다운로드, 모바일 가로 넘침·page error 없음. 템플릿 화면 흐름도 재검증했다.
- 로컬 전체 검사는 기존 자손 회수 테스트 실패(`unknown != exited`)와 플랫폼 skip 외 새 실패 없음. 이 검사를 완화하지 않았다. 후속 합성·추출·화면/문서 검사를 통과했다. 최종 Linux/Windows head CI는 PR에 기록한다.

OCR, 이미지 의미, 동적 웹, 로그인, 원본의 진위, 일반적인 변환 정확도와 모델 품질 효과는 검증하지 않았다. 원본 파일은 따로 보관해야 한다. Poppler의 사용자 PC 설치·보안 격리를 확인한 것으로 읽지 않는다. 날짜별 연구는 보존하고 현재 기능·책임·후속 우선순위는 문서 지도와 FEATURES/ARCHITECTURE/NEXT-SESSION에 연결했다.
