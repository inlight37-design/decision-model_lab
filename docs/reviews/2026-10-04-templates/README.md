# 기반 연결 확인과 팀·작업 템플릿

2026-10-04 · codex · 클라우드·GitHub. 기준 `c6a0b686663eb59e0d0f4b89a97bf034323fa1c5`, [카드 #162](https://github.com/inlight37-design/decision-model_lab/issues/162), [PR #163](https://github.com/inlight37-design/decision-model_lab/pull/163). 실제 PC·구독 CLI는 새로 관측하지 않았고 모델 호출은 없었다.

## 순서와 결정

사용자가 기반 점검·통합 → 템플릿 → 수정·재검토 → 자료 추출의 제안에 “순서대로 진행해줘”라고 지시했다. PR #161의 정확한 head CI와 작업 생성/입력 확인/공개/교차검토/처분/판단/검색/다음 실행 기억 연결을 합성 실행기로 확인한 뒤, 그 순서에 포함된 PR #161을 병합했다. 이는 이 요청의 병합 지시이며 다른 세션의 상시 권한을 바꾸지 않는다. PC 사본의 pull·실제 CLI 검증은 수행하지 않았다.

템플릿은 설정의 사본이다. 실행 ID·승인·제안 사용권·호출 예산·고정 기억을 재사용하지 않는다. 역할·현재 모델 binding과 입력 형식은 불러올 때도 검사한다. 다듬기 모드는 기억하지만 승인 차례는 새로 만든다. 자료는 이름·본문 사본으로 보관하고 전체 payload hash 및 자료별 hash로 확인한다.

저장은 기존 원장의 별도 표를 사용했다. launcher가 호출 상한 때문에 다른 원장을 고를 수 있으므로, 파일 내보내기/가져오기도 제공한다. 자동 원장 간 동기화나 전역 기억으로 확대하지 않는다. 파일에는 질문·자료 본문이 포함되며 화면에서 이를 안내한다. 가져오기는 새 템플릿 ID를 만들고 새 원장의 상한을 바꾸지 않는다.

## 적용과 확인

- TemplateService가 저장/목록/검사/복원/삭제/파일 이동을 담당한다. 새 실행은 기존 InputBuilder·WorkService와 화면의 새 확인 단계를 이용한다.
- schema 15 이전은 기존 Store의 잠금·거래·자동 backup 경로를 따른다. 이전 실행과 상한 보존을 검사했다. 구형 코드는 새 버전을 거절하므로 코드만 내리는 복귀는 지원하지 않는다.
- 새 시험은 저장본 불변성, 재시작, 현재 모델 변경, transient 승인 필드 거절, 일반 분담, 다듬기 재승인, hash 변조, 삭제, 다른 원장 파일 복사, HTTP 인증, 연속 작업 흐름을 확인한다.
- Chromium에서 저장→불러오기→자료 복원→미리보기 무효화→새 확인→실행을 확인했다. 좁은 화면의 넘침과 pageerror도 확인했다. glass 창 뒤 글자가 비치는 가독성 문제는 기존 blur 토큰을 적용했다. 임시 서버·브라우저는 종료했다.
- 로컬 전체 회귀에서 기존 cloud 자식 프로세스 종료 검사의 `unknown != exited` 실패는 남았다. 관련 계약을 약화하지 않았다. 최종 head의 Linux/Windows CI는 PR에서 확인한다.

사용 시간 절감·모델 품질은 실측하지 않았다. 현재 동작·사용법은 [FEATURES](../../FEATURES.md)와 [앱 안내](../../../app/README.md), 책임 경계는 [현재 구조](../../../app/ARCHITECTURE.md)에 둔다. 후속 수정·재검토와 자료 추출은 이 기록의 완료 범위가 아니다.
