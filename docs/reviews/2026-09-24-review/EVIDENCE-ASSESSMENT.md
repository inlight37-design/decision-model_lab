## 관측에서 확정할 수 있는 범위

- profile run1/run2에서 인증 파일 존재와 기본 구성 open 성공을 대조군으로 확보했고 profile 두 방식 모두 open 실패했다. 단독 sandbox의 K46 방어 증거로 유효하다.
- offline exec는 정상 profile에서 네트워크 연결 시도 단계, 없는 profile에서 명시적 undefined profile 오류를 보였다. 이것은 exec 모델 명령의 deny 적용 증거가 아니다.
- 큰 stdin 호출은 94,777바이트 전송과 토큰 증가를 보여 준다. 끝부분의 독립 표식이 없으므로 모든 바이트가 CLI/모델 입력까지 온 것을 증명하지 않는다. 보고된 토큰 증가는 보조 증거다.
- 관측 장부의 여섯 시작 중 두 P3는 인자 오류로 모델 답/사용량이 없다. 실패도 승인 횟수에 세는 정책은 유지하되, 모델 응답과 실행 시작 수를 같은 이름으로 부르지 않는 것이 정확하다.

## 확인 중인 새 결함 후보

- K46: 인증 파일 부재도 통과할 수 있고, 여러 명령의 rc를 dict로 합쳐 마지막 값이 앞의 성공 읽기를 덮는다. 명령의 동일성·수·필수 키·종료 원인을 검증하지 않는다.
- P3: `not answered`만으로 expected refusal을 판정하여 시간 초과·무관한 실행 실패를 통과시킬 수 있다. 관측 판정에 자손 전체 종료 수용 조건도 없다. 실제 controller의 관문과는 별개다.
- 승인 상한: 검사와 시작 예약 사이 원자성이 없어 동시 관측 호출은 상한을 초과할 수 있다.
- 실행 허가: 미래 관측 날짜, 근거 없는 observed, 양쪽 버전 None의 처리를 추가로 확인한다.
- 세션 요약: 짧은 본문과 상한 밖 본문을 빼며 잘림 표시가 없어 문맥의 부재를 입증할 수 없다. K46 질문 자체의 skill/plugin/MCP 단어도 구분해야 한다.
