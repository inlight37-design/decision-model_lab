## 3. 이번에 재현한 추가 오류

### R1. 선택적인 사용량 정보가 정상 답변까지 중단시킴 — 원격 미반영

**위치:** [core/quota.py](../../../core/quota.py)의 `claude_limit`, `quota_projection`.

JSON에는 들어갈 수 있지만 float 범위를 넘는 정수(`10 ** 400`와 음수)를 `math.isfinite`에 먼저 주면 `OverflowError`가 난다. 기존 코드는 그 뒤에 범위를 검사했다. Claude에서는 정상 답과 함께 온 선택적 계정 사건 하나가 답변 해석 전체를 중단시켰다. Codex는 모양 거절인 `ValueError` 대신 예상 밖 예외가 됐다.

**로컬 해법:** 타입 검사 뒤 사용 비율의 허용 범위를 먼저 검사하고, 그 범위에 든 값에만 유한수 검사를 한다. 허용 범위·불리언 거절·NaN/무한대 거절은 유지하며 포괄적인 예외 삼키기를 추가하지 않는다. Claude의 잘못된 사건은 미확인으로 두되 정상 답을 보존한다.

**시험:** [test_runtime_boundaries.py](../../../tests/test_runtime_boundaries.py)의 `OptionalMetadataTests`. Claude의 평면·창별 사건에서 양/음의 큰 정수, Codex 양/음의 큰 정수를 검사한다. 로컬 수정본은 성공했지만 이 원격 브랜치의 파서는 아직 이전 코드다. 따라서 이 회귀는 원격에서 여전히 실패하는 것이 맞다.

### R2. 다른 경로로 복원하면 고정 질문과 실제 자료 폴더가 달라짐 — 원격 수정

**위치:** [app/controller.py](../../../app/controller.py)의 `create_run`, `_source_dir`.

대기 중인 자료 포함 실행을 `work_root`만 바꾸어 재개하면, 새 폴더를 입력으로 연결하면서 질문에는 옛 폴더 경로를 보냈다. 파일 해시만 검사해서는 이를 잡지 못해 잘못된 입력으로 호출할 수 있었다. 자료 표를 복원 과정에서 내용·크기·해시까지 함께 바꾼 경우에도 원래 질문의 목록과 달라진 것을 잡지 못했다.

**해법:** 자료 목록 문구를 만드는 작은 순수 함수 `_source_footer`를 생성과 사전 검사에서 공유한다. 지금 목록·폴더로 만든 문구가 고정 질문과 다르면 사본 작성·실행 계획·호출 예약 전에 거절한다. 같은 경로로 재개하면 질문과 입력 digest를 그대로 유지한다. 초안과 실제 합성이 기존 `_source_dir`를 같이 쓰므로 별도 우회 경로를 만들지 않았다.

이는 복원 무결성 검사다. 공격자가 원장 전체를 조작할 수 없는 권한 경계나 시도 도중 바꿔치기(K14)를 증명하지 않는다. 기존 스키마·실행 판·CLI 권한은 바꾸지 않았다.

**시험:** 같은 파일의 `SourceResumeTests`. 다른 경로 거절, 같은 경로 재개의 양성 대조, 자료 표와 고정 질문 불일치를 검증했다.

## 5. 아키텍처 판단

**지금 단계에서는 작은 단일 프로세스 구조를 유지하는 것이 타당하다.** 기존 핵심은 무작정 덧댄 구조가 아니라 실행·저장·판정을 분리하고 경계에서 보수적으로 거절하는 구조다. 다만 controller와 조회 비용에는 정리할 여지가 있다.

### 유지할 부분

`core`는 실행·환경·격리·계획·허가와 순수 정책을, `app`은 controller·원장·화면을 소유한다. 한 원장에는 한 writer만 있고 예약·시작 사건은 거래 안에서 함께 저장된다. 실행 계획은 한 번 만들고 기록한 계획 그대로 실행하며, 허가는 시작 직전에 다시 계산한다. 공개 보고는 허용된 화면 투영만 받아 봉인 저장소의 우회 독자가 되지 않는다.

#46처럼 **같은 상태 투영을 자리·복구·화면이 함께 쓰는 수정**은 좋은 방향이다. R2도 목록 생성과 검사를 한 함수로 묶었으며 두 번째 상태 저장소를 만들지 않았다. 이 범위에 새 오케스트레이터, 메시지 큐, SDK, 서비스 분할을 넣을 근거는 없다.

### 남은 구조적 비용

controller는 일정 관리·자료 I/O·화면 투영·계정 사건 조회까지 맡아 책임이 넓다. 다음 분리는 순수 투영이나 자료 사전 검사의 추출부터 하되, 거래·호출 예약·공개 승인 주인은 controller 하나로 유지해야 한다. 파일을 나누는 것 자체가 안전성을 높이지는 않는다.

자리·미종료·예산·각 실행의 화면을 만들며 사건을 반복 조회한다. 긴 원장에서의 폴링 비용은 이번에 측정하지 않았다. 먼저 원장 크기별 조회 수·지연을 재고, 필요한 경우에만 쿼리 통합·인덱스를 적용한다. 전역 캐시나 별도 가변 회계를 추가하면 복구 때 원장과 어긋날 수 있다. 제한된 자료 I/O가 controller lock 안에서 수행되는 비용도 이 측정에 포함한다.

시스템 Python과 설치된 검사 의존성을 사용하고 비관리자 사용자로 실행했다. root 실행에서 “root 소유가 아닌 가짜 bwrap” 시험이 실제 root 소유가 되어 실패했던 환경 가정은 비관리자 실행으로 분리했다. 격리 코드를 약화하지 않았다. 변이 시험 도중 같은 길이·같은 초의 파일 수정이 Python 캐시에 남았던 문제는 해당 저장소의 생성 bytecode만 지우고 재검사했다. 최종 소스 해시는 수정본과 다시 일치했다.
