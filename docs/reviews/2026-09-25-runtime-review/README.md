`app/state.py`의 순수 사건 투영과 기존 controller/원장을 사용한다. 새 스케줄러·큐·DB 표·외부 의존성은 만들지 않는다. 옛 코드가 한 실행을 여러 번 합성한 원장도 모든 미종료 시도를 따로 센다. 사용자 확인은 특정 시도에만 적용되며 자리만 반환하고 호출 예산·실행 가능 횟수를 복원하지 않는다.

기존 사건 목록 시험은 `LIMIT 12`와 payload 비노출을 유지한다. 별도로 필요한 합성 lifecycle 조회는 합성 사건 네 종류로 제한되었는지 검사한다. 전체 SELECT 개수가 언제나 하나라는 옛 가정만 바꿨다.

웹 컨테이너의 작업본에서 합성·HTTP·Node 화면·자료 시험을 통과했다. 최초 전체 시험은 컨테이너 Python의 외부 spreadsheet 초기화 hook이 자식 실행·stderr·시간 제한에 간섭해 실패했다. 저장소가 쓰는 시간 제한이나 격리 규칙을 약하게 하지 않고, 같은 Python 버전의 `/usr/bin/python3`와 설치된 schema 의존성 경로로 재검사해 전체 시험을 통과했다. 이 컨테이너에는 bubblewrap이 없어 해당 경로는 건너뜀이며, 실제 Windows·WSL 검증으로 주장하지 않는다.
