## 검토 중 추가로 고친 결함

- 기존 실행 ID가 초 단위 시각과 UUID 앞자리만 써서, 빠르게 실행을 만들면 충돌했다. CI에서 재현되어 UUID 전체를 사용하고 같은 접두사의 두 UUID로 회귀 시험했다.
- 예전 원장에 공개 단계가 없으면 drafting으로 기본 처리하던 새 migration을 거절하도록 고쳤다. 누락·오류 시 스키마 변경과 데이터 변경을 모두 롤백하고 잠금을 해제한다.
- 원문 보고가 초안의 저장 해시를 무시하고 재계산하던 문제를 고쳤다. 저장된 해시와 다르면 내보내지 않는다.
- 모의 합성의 같은 줄 반복이 참조 배열을 키우던 문제를 막았다. 같은 참여자의 같은 문장은 대표 위치만 남기고 생략 수를 표시한다. 긴 줄/표시 한도로 발췌가 없으면 빈 완료 카드 대신 `unavailable`이다.

## 검증 범위

- Windows 및 WSL에서 전체 `python -m unittest discover -s tests -v`. WSL은 `DML_REQUIRE_BWRAP=1`로 실제 bubblewrap 경로를 요구한다. Windows의 Linux 전용 skip과 WSL의 Windows 레지스트리 skip은 별도이며 성공으로 세지 않는다.
- 소스 가림·허가·격리 반례, 취소/늦은 답/재시작/예산, 상태 경합, migration 롤백, 저장 해시, 합성의 인증·봉인·축소 승인·중복 요청·영속성·실패/원문 보존·표시 상한을 시험했다.
- 실제 localhost API에서 합성 문자열로 실행 생성 → 수동 초안 → 공개 → 모의 합성 → 결정 보고 저장을 확인했다. 사용자 기존 journal 대신 별도 시험 폴더를 썼다.
- Node의 `vm.Script`로 화면 JavaScript를 파싱하고, 작은 DOM 대역에서 두 배치의 순서·반례 보존·문자열의 script 요소 비생성을 확인했다. **실제 브라우저 시각 검증은 하지 못했다.** 연결된 browser/app 목록이 비었고 Edge 제어도 사용할 수 없었다. CSS 배치·390px·브라우저 다운로드 조작의 성공을 주장하지 않는다.
- 인코딩·디자인 토큰·계약·근거 원장·compileall 검사. CI의 정확한 head 결과는 각 PR에 연결한다. 첫 Linux CI는 바뀐 init 공개 형식과 더 강한 가림을 옛 시험이 기대한 탓에 실패하여 시험을 수정했다. 가림을 약하게 되돌리지 않았다.

`a1-draft-report/2`는 모의 결과와 분리되는 원문 전용 내보내기이므로 합성 상태를 `not_included`로 표시한다. `a1-decision-report/1`은 원문 보고와 `a1-mock-synthesis/1`을 묶는다. 모든 발췌 주장은 `unresolved`, 카드는 `qualified`, 사실 검사는 `not_performed`다. 같은 문장의 반복이나 참여자의 동의는 진실·독립성 증명이 아니다.
