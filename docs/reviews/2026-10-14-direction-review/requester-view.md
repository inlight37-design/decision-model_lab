# 요청한 세션의 먼저 쓴 판단 (2026-10-14)

두 검토자의 답이 오기 전에, 검토를 요청한 claude 세션(주 PC Windows 쪽)이 같은 질문에 먼저 적은 판단이다. 검토 답을 본 뒤에는 고치지 않는다. 답과의 비교는 [README](README.md)에 있다.

## 숫자 (2026-10-14, 저장소 기준)

- 2026-09-21 이후 merge가 아닌 commit 603개 가운데 문서만 바꾼 것이 347개, 앱·core·도구 코드를 바꾼 것이 184개다. 병합한 PR은 154개다.
- 추적하는 마크다운은 288개, 약 3.96 MB다.
- 세션이 시작할 때 읽는 규칙·인계(AGENTS.md, NEXT-SESSION.md, 협업 규칙)만 약 60 KB다.
- 인계 3절에 따르면 사용자는 앱을 아직 실제로 써 보지 않았다.
- 실제 실행은 관측 기록 문(K1)에 막혀 있고, 합성이 품질을 올린다는 근거는 아직 없다(A10).

## 판단

1. **목표에서 벗어났다.** 사용자가 말한 목표는 "토큰 낭비 없이 편하게 부리고, 내 작업이 편해지는 것"이다. 그런데 저장소는 여러 모델의 blind 비교를 엄격하게 하는 연구 도구 쪽으로 자랐다. 3주 동안 사용자가 앱을 쓰지 않았다는 것이 가장 큰 신호다.
2. **토큰이 가장 많이 새는 곳은 앱 안의 모델 호출이 아니라 개발 세션이다.** 앱 호출은 원장당 Codex 5·Claude 5로 묶여 있다. 반면 세션마다 큰 규칙·인계를 읽고, 문서와 검토를 주고받고, 같은 것을 여러 번 검증한다. 문서만 바꾼 commit이 절반을 넘는다.
3. **결정 D는 맞다.** 가장 큰 막힘을 푼다. A–C는 사용자 작업을 돕는 쪽이지만, 이 저장소의 무거운 규칙 안에서 만들면 느리다. 공식 기능(백그라운드 세션, `claude agents --json`, 예약 작업)과 작은 스크립트로 먼저 해 보는 편이 빠르다.
4. **다음 2–4주는 새 연구·규칙을 멈추고 "실제로 쓰이는가"만 본다.**
   - 일상 모드를 열고, 사용자의 실제 작업 하나에 하루 한 번 쓰이게 한다.
   - 여러 세션·GPU 작업을 한 화면에서 읽기 전용으로 보여 준다.
   - 작업마다 쓴 사용량을 숫자로 보여 준다. 세션 기록의 사용량 칸과 Codex 한도 조회는 모델을 부르지 않고도 읽을 수 있다.
5. **남길 것:** 원장, 호출 상한, 종료 확인, 봉인·공개 규칙, 원문 대조. **줄일 것:** 인계·규칙 문서의 크기, 검토 왕복, 관측 의식(엄격 비교에만).
