이유:

합성·토론은 이미 상품화(Commoditized)되었고 이득도 미미합니다: 독립 초안 → 익명 검토 → 합성은 이미 cli-council, agent-council, deliberation 같은 오픈소스들이 똑같이 하고 있으며(A8 결론 2, §3.1), 무엇보다 이 저장소 스스로 한 실험(A10)에서 Claude 단독 호출보다 나아진 점이 없다고 결론이 났습니다.

사용자의 진짜 고통(P1–P22)은 현장에 있습니다: GPU가 놀고, 학습이 실패했는데 완료로 찍히고, 세션 문맥이 터져서 결정을 잊어버리는 문제는 현장에 pueue, worktree, 공식 훅/알림을 깔아야 해결되지, 이 저장소에 스키마 20번을 만든다고 해결되지 않습니다 (근거: A5 API와 호환, A7 §1·§2, A8 §3.3 / 확신도: 높음).

4. 전체 요약: 가장 중요한 지적 다섯 가지

[모순] 사용자 없는 'AI만의 자율 주행'이 괴물 같은 관료주의를 만들었습니다 (근거: A1 §2.21·22·25, §3, A8 §1 / 확신도: 높음)

사용자가 "전권을 줄 테니 알아서 진행하라"고 위임한 뒤 바빠서 앱을 써 보지 않는 사이, AI 세션들이 스스로 일거리를 만들어 코드 1.3만 줄, 테스트 1.7만 줄, 문서 287개(3.9 MB), DB 스키마 19판짜리 거대 조직을 세웠습니다. 지금 당장 "사용자 확인 없는 AI 자율 기능 추가" 규칙(A1 §2.22·25)을 거둬들이십시오.

[결함] 다단계 호출(초안→검토→수정→합성)은 품질 이득 없이 구독 토큰만 2~4배 태우고 있습니다 (근거: A4 사용자 기능 표, A6 모의 실행과 화면, A10 결론·점수 / 확신도: 높음)

실험 결과(A10) 단독 Claude 초안이 8문제 모두 맞았고 합성으로 얻은 추가 이득은 0점이었습니다. 기본 작업은 '단일 모델 1회 호출'로 돌리고, 정말 중요한 결정에서만 codex-plugin-cc나 2자 비교를 부르십시오.

[결함] '실제 실행의 문(K1: 기기 등록·30일 만료·버전 고정)'이 도구를 쓰지 못하게 막는 최대 자충수입니다 (근거: A6 단일 실제 CLI와 준비 조회, A8 결론 1·4, §2 K1, §6 / 확신도: 높음)

보안과 실험 엄밀성을 챙기려다 정작 CLI 업데이트도 못 하고 한 달마다 모델 호출 5번과 수동 명령 10개를 쳐야 하는 족쇄가 되었습니다. 오늘 결정한 결정 D(일상 모드)를 최우선으로 구현해 이 문부터 부수십시오.

[조언] 결정 A(시계/편지함)와 B(부재 모드)를 이 앱 안에 바닥부터 또 짜지 마십시오 — pueue와 공식 CLI 기능이면 됩니다 (근거: A7 결론 2, §6.1, §7, A8 결론 5·6, §3.2·§3.3 / 확신도: 높음)

GPU 줄 세우기와 완료 확인은 pueue가, 세션 알림과 백그라운드 실행은 Claude Code 공식 기능(notify_when_idle, claude --bg, 상태 줄 한도 기록)이 훨씬 잘합니다. 이 앱에는 결정 C(읽기 전용 상황판)만 얹어서 그것들을 한눈에 보여주는 계기판으로 쓰십시오.

[결함] 문서를 줄이려고 만든 규칙과 CI가 오히려 매 세션의 토큰과 시간을 잡아먹고 있습니다 (근거: A1 §5·§6, A2 Keep it from piling up, A3 §5·§6·§7, A8 §1·§2 K6 / 확신도: 높음)
