````markdown
# decision-model_lab 방향 검토 요청 (2026-10-14)

당신은 이 프로젝트를 처음 보는 외부 검토자입니다. 듣기 좋은 말 없이 냉정하게 평가해 주세요. 같은 질문을 다른 AI 하나에도 따로 보냈고, 서로의 답은 보여 주지 않습니다.

## 사용자가 바라는 것

사용자는 한국어를 쓰는 개인 한 명입니다. Windows PC 한 대와 WSL에서 구독형 AI만 씁니다(API 종량 과금은 쓰지 않음). 오늘 이렇게 말했습니다.

> "우리가 하려는 게 결국 토큰 낭비 없이 오케스트레이션을 편하게 하면서 내가 사용하는 작업을 편하게 하고 싶다 이건데, 잘 따라가고 있는 건지 모르겠음"

목표를 셋으로 나누면 이렇습니다.
1. 토큰, 곧 구독 사용량을 낭비하지 않는다.
2. 여러 AI(Claude Code, Codex, ChatGPT, Gemini 등)를 부리는 일이 편하다.
3. 사용자의 실제 작업이 편해진다. 실제 작업은 다른 비공개 프로젝트(로컬 GPU로 이미지 생성과 모델 학습)를 여러 AI 세션으로 운영하는 일입니다. 그때 겪는 불편 P1–P22는 A7에 있습니다.

## 이 프로젝트

- 공개 GitHub 저장소 inlight37-design/decision-model_lab, 기준 commit dcb7593. 첨부 A1–A10은 그 commit의 파일입니다.
- 2026-09-21에 시작했습니다. 처음에는 여러 모델의 독립 답 → 교차검토 → 합성으로 판단 품질을 높이는 연구·설계(v0.2–v0.4)였습니다. 지금은 controller 앱(원장, 역할판, 실제 CLI 실행)과 많은 문서·규칙·시험이 있습니다.
- A7과 A8은 이 저장소의 Claude 세션이 오늘 쓴 제안입니다. 그대로 믿지 말고 비판해 주세요.
- 사용자는 오늘 아래 네 결정을 추천안대로 하기로 했습니다. 아직 구현 전입니다.
  - A: 이 앱에 시계와 보낸 편지함을 들인다. PC 작업 관제 범위만이고, 격리 실행에는 계속 금지한다(A7 §7).
  - B: 부재 모드. 승인 기록이 있을 때만 켜지고 기본은 꺼져 있다. 승인마다 상한과 끝나는 시각이 있다(A7 §7).
  - C: 상황판이 이 PC의 다른 작업을 읽는다. 읽을 경로는 설정 파일 목록으로 고정하고 인증 파일은 열지 않는다(A7 §7).
  - D: 일상 모드를 연다. 관측 기록이 없어도 모델 없는 점검만 통과하면 실제로 실행한다. 결과는 "문맥 미확인"으로 표시하고 독립 정족수에 세지 않는다. 엄격 비교는 지금처럼 관측 기록이 있어야 한다(A8 §6).
