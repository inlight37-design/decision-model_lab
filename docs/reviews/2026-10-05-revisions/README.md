# 수정 답과 재검토 구현 확인

2026-10-05 · codex · 클라우드 컨테이너와 GitHub. 사용자 PC·실제 공급자 CLI·구독 인증은 관측하지 않았고 모델을 부르지 않았다. 사용자 요청의 기반 점검·통합 → 템플릿 → 수정·재검토 → 자료 추출 순서를 따른다. 템플릿 PR #163의 `68dc7bb3e0b9fd482a56c0cb2af02f67bd54c23c` 위에 구현했다.

공개된 격리 초안에 대한 지적·처분·원본/이전 판 hash를 고정한 뒤, 사용자가 입력을 확인하고 원래 CLI 작성자에게 새 판을 요청한다. 원래 초안과 정족수는 바뀌지 않는다. 다른 원래 CLI 팀원이 재검토해야 다음 판을 만들 수 있다. 실패도 수정/재검토 상한에 포함하며 자동 반복하지 않는다. 기존 호출 원장의 예약·종료 미확인·재시작 복구를 그대로 사용한다.

수정 전후, 지적별 대응, 새 지적과 재검토를 화면·공개 검색·호출 및 사용량·후속 기억·별도 `decision-revision-history/1` export에 연결했다. 기존 합성은 원래 초안을 사용한다. 기억 본문은 상한 때문에 잘릴 수 있고 판별 출처 ID를 함께 남긴다. schema 15 원장의 템플릿·예산을 보존하며 schema 16으로 백업 후 이행한다.

합성 실행기로 성공 경로, 오래된 확인, 실패/unknown 뒤 원본 유지, 예산 소진, 재시작 후 비재호출, 재검토 상한, 검색·기억·hash 변조·HTTP를 확인했다. 실제 Chromium에서 입력 확인→수정→전후 비교→다른 팀원 재검토→JSON 저장을 수행했고 모바일 가로 넘침과 page error는 없었다. 전체 로컬 검사는 기존 `test_children_left_behind_are_counted_and_ended` 실패(`unknown != exited`)와 플랫폼 격리 skip 외 새 실패가 없었다. 컨테이너의 자손 회수 관측을 성공으로 바꾸거나 해당 검사를 완화하지 않았다. 최종 head의 Linux/Windows CI 결과는 PR에 기록한다.

실제 답변 개선·재검토 정확도·비용 절감은 측정하지 않았다. 모델의 반영/해결 판단과 인용 일치는 사실 검증이 아니다. 다음 단계는 PDF/URL 추출·미리보기·출처/누락 기록이다.
