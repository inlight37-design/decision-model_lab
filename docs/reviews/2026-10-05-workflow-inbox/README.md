## 채택한 범위와 이유

OP04/05/10/11의 준비 상태·명세·유효판·앱 내부 수신함을 현재 command/query 경계에 붙였다. 목표·완료 기준과 선행 작업을 먼저 저장하면 사용자는 무엇을 기다리는지와 어떤 결과를 판단할지 볼 수 있다. 개별 실행 기능은 기존 입력 확인·호출 상한·봉인·검토를 그대로 사용한다. 새 scheduler, 자동 단계 실행, 원격 카드 동기화, 알림 발송/읽음 저장, 전역 command receipt/outbox는 필요하지 않아 넣지 않았다.

schema 17의 선택적 `task_plans`만 추가한다. 저장할 때 예상 revision, 참조 존재, 자기 참조/순환, 진행/종료 미확정 상태를 검사하고 새 판을 사건에 남긴다. 실행 전 원장 backup과 구버전 거절은 기존 이행 계약을 유지한다.

## 준비·완료의 의미

- 선행 작업의 **현재 계획에 속한 실행들**이 사람의 판단 완료 상태여야 하며, 어느 판이든 진행/미확정 호출이 있으면 완료로 세지 않는다. 계획 없는 기존 작업은 기존 전체 타임라인 기준을 유지한다.
- 계획 편집은 과거 답/취소/판단/소비를 지우지 않는다. 새 계획은 새 실행을 요구한다. 종료가 확인된 실패/취소 뒤에는 새 계획으로 다시 준비할 수 있고, unknown은 먼저 확인해야 한다.
- 입력 미리보기와 실행 생성 거래에서 계획/선행 결과를 다시 확인한다. role_config에 계획과 근거 실행 ID·결과 판을 고정하므로 다른 창의 편집이나 새 선행 실행이 오래된 확인으로 시작되는 것을 막는다. 다듬기·분담 제안도 선행 관문을 통과한다.
- 이미 생성한 실행은 선행 상태가 나중에 바뀌어도 자동 취소하거나 다시 부르지 않는다. 질문 초안은 목표·완료 기준으로 채우며 사람이 고칠 수 있다. 선행 답 본문은 자동 전달하지 않는다.
- ‘사람 판단 완료’는 사실 검증이 아니다. typed 단계도 모델 결과를 새 검증 성공으로 승격하지 않는다. 수신함을 열거나 읽는 것은 실행/문제 해결 사건이 아니다.

## 검증

계획 생성/편집·중복 참조·누락·순환·stale revision의 원자적 거절, 선행 완료/재열림/취소/새 계획, 오래된 입력 확인과 준비→쓰기 사이 변경, 봉인 비노출, 연결 전 다듬기/분담 unknown의 홈 행동·선행 차단·종료 확인, 진행 중 분담의 완료 해제, planning 호출의 선행 우회 거절, schema 16 backup→17·재시작·기존 입력 동등성을 합성 실행기로 확인했다.

Chromium에서 계획 생성 → 후속 계획/선행 선택 → 시작 비활성 → 선행 실행/판단 완료 → 후속 입력 미리보기/계획 판·근거 표시 → 실행을 확인했다. 빠른 화면 이동과 모바일 화면, page error/가로 넘침도 확인했다. Node는 실제 화면 함수와 늦은 응답/새 선택의 소유권을 검증한다.

로컬 전체 suite에는 기존 컨테이너 `test_children_left_behind_are_counted_and_ended`의 `unknown != exited` 실패가 남았다. 새 실패를 정상으로 취급하거나 skip하지 않았고 관련 변경 뒤의 회귀를 재실행했다. 최신 PR의 Linux/Windows CI는 PR Checks를 기준으로 한다. 별도 AI 교차검토는 하지 않았다.

## 통합 부하와 남은 일

[작업 흐름 포함 측정](queries.json)은 앞 조회 기록과 같은 임시 합성 원장·명령이다. 실행 1,000개의 overview는 102.11 ms, 1,233,390 bytes, 특정 작업 검색은 2.09 ms였다. 앞 조회만의 판보다 단계·수신함 정보가 더해져 응답이 늘었다. 전체 상세 snapshot은 26,370,259 bytes이고, 전체 본문 검색은 여전히 선형이다. 이 fixture에는 실제 사용자 원장과 대형 계획/수정/합성 이력 분포가 없다.

다음에는 사용자가 쓰는 흐름과 더 큰 작업/계획 분포로 관측한다. 목록/타임라인 페이지화, 더 넓은 기억 평가, 일반 팀원 검토는 그 결과로 우선순위를 정한다. CLI adapter·추론 강도·격리 계약은 바꾸지 않았으며 사용자 PC의 재관측은 해당 PC에서 별도로 한다.
