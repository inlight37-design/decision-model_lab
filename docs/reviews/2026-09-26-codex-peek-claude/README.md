## 1. 결론

| 질문 | 판정 |
|---|---|
| 배울 가치 | **높다.** 가장 값진 것은 기능이 아니라, 저자가 약 석 달 동안 겪고 되돌린 실패 기록이다. |
| 통째 도입·설치 | **하지 않는다.** 설치하면 사용자 전역 Claude 설정에 훅이 들어간다. 그중 하나가 `codex exec` 직접 호출을 막는다. Codex 훅은 DML 참여자 실행까지 건드릴 수 있다(5절 첫 줄). |
| 지금 넣을 것 | 작은 것 넷(3절). 모두 모델 호출 없음, 크기 S다. |
| 나중에 넣을 것 | 역할판 B·C·D·E 단계 카드의 **완료 조건 몇 줄**로 흡수한다(4절). 설계 문서를 먼저 만들지 않는다. |

DML은 실행 관리의 기본기가 이미 codex-peek보다 단단하다(2절). 그래서 가져올 것은 부품이 아니다. "이렇게 하면 이렇게 망가진다"는 기록, 몇 줄짜리 규칙, 작은 방어다.

codex-peek의 구조:

- 브릿지는 `codex exec`(새 세션)와 `codex exec resume <id>`(이어 쓰기)를 자식 프로세스로 부른다. 질문은 stdin으로 넣고, 답은 `-o` 파일로 받는다(`bridge/codex-bridge.js:2774-2806`).
- Claude Code Stop 훅이 "파일을 바꿨는데 검증 증명이 없으면" 턴 종료를 막는다. 이 2트랙은 기본 꺼짐이다(`contract-lib.js:1764-1769`).
- 그 위에 정찰(3트랙), 기억·수칙서, Project MAP, VS Code 대시보드가 얹혀 있다.
- Codex app-server는 검증에 쓰지 않고 훅 신뢰 조회에만 쓴다(`src/extension.ts:9445-9469`). 그래서 HP-10(App Server 비교)의 참고 구현은 아니다.

### 게시글·문서의 말과 코드의 차이

| 말 | 코드 |
|---|---|
| "커스텀 프롬프트는 압축 시에만 반응" | 사용자 규칙은 기본값에서 **매 턴 전문 주입**된다(`tests/claude-directive-delivery.test.js:89`). 세션 1회 + 압축 때 재전송하는 것은 하네스 정적 지시다. |
| "검증 건너뜀 방지" | 증명 파일에는 판정이 없다(`codex-bridge.js:418-452`). 기록 시점은 판정을 읽기(4847) 전(4829)이다. Stop 훅은 증명이 신선한지만 본다(`verify-guard.js:96-101, 284-288`). 그래서 **검증 결과가 실패여도 턴이 끝날 수 있다.** 저자도 "실수 방지일 뿐"이라고 적었다(`docs/VERIFY-GOVERNANCE.md:57-62`). |
| "Codex 직접 호출 차단"(README) | 명령에 `codex-bridge` 글자만 있으면 통과한다(`bridge/codex-guard.js:20-26`). 차단 동작을 확인하는 시험이 없다. |
| "훅 4개"(README·SECURITY·PRIVACY) | 설치되는 훅은 6개다(`install.js:101-108`). |
| "로컬에서만 동작"(SECURITY) | DeepSeek 경로는 외부 API로 `fetch`한다(`bridge/deepseek-bridge.js:82`). |
| "규모에 따라 2트랙/3트랙" | 자동 선택이 아니다. 대시보드 스위치이고 기본은 꺼짐이다. |
| 60/60·0/60 벤치 | 러너·시나리오·원자료가 저장소에 없다. 문서에는 다른 숫자("228회", `docs/MEMORY-AUTHORITY-DESIGN.md:139`)가 있다. |

### 벤치마크 읽는 법

1. **재현할 수 없다.** 벤치 파일이 main 작업트리에도 이력에도 없다.
2. **헤드라인은 Warm 조건에서 나왔다.** Warm은 "정확한 기억이 이미 주어진" 조건이다(게시글 하단 각주). 재발 방지 규칙을 미리 주고 재발 0을 잰 셈이라 동어반복 위험이 크다.
3. **구간이 과하게 좁다.** 60회를 독립 표본으로 계산했다. 시나리오 단위(12개)로 보면 "0건"의 95% 상한은 약 6%가 아니라 약 24%다(Wilson 0/12).
4. **두 지표가 사실상 같은 사건이다.** "첫 구현 완결"과 "사고 재발"은 같은 실패를 앞뒤로 센 것에 가깝다(순정 조건에서 실패 33 = 재발 33).
5. **검증만 붙인 조건(2트랙)은 순정과 차이가 없었다**(48.3% vs 44.1%, 구간이 크게 겹침). 이점은 기억을 미리 준 조건에서만 나왔다.

"추가 호출이 품질을 올린다"는 근거는 codex-peek 자신의 벤치에도 없다. 합성·교차검토를 기본 꺼짐으로 두고 같은 예산 대조군으로 재려는 v0.4 D17 방향이 맞다. 비교 실험에서 가져올 것은 세 가지다. 제외 규칙을 모든 조건에 대칭으로 적용하고, 과제를 집계 단위로 삼고, 구간을 함께 적는다.

갤러리 댓글의 캐시 질문: codex-peek의 캐시 이득은 검증 세션을 resume로 재사용한 부산물이다. DML 참여자는 blind 때문에 매번 새 세션이라 같은 이득을 기대할 수 없다([역할판 검토](../2026-09-26-role-board-review/README.md) RB-08과 같은 결론).

## 2. DML이 이미 더 단단한 곳 (바꾸지 않는다)

| 항목 | codex-peek | DML |
|---|---|---|
| 호출 종료 | 본 검증 경로는 `child.kill()`·spawnSync timeout뿐이고 프로세스 트리 종료가 없다 | runner가 자손 전체 종료를 확인한다(`tree_confirmed_empty`) |
| 결과 판정 | exit 0 + 답 파일이 비어 있지 않음 | [`core/adapters.py`](../../../core/adapters.py) `interpret`: turn.completed, 실패 이벤트, stderr 거절 표식, 잘림, stdin 전달 완결 |
| 상태 저장 | 파일 잠금 여러 층, 죽은 잠금은 사람이 `--confirm`으로 정리. 잠금 회수 설계를 반복해서 고치다 철회했다 | SQLite `BEGIN IMMEDIATE`, 조건부 UPDATE, 재시작 때 running→unknown |
| 참여자 문맥 | 정찰 codex 호출이 사용자 `CODEX_HOME`(MCP 포함)을 그대로 쓴다 | `--ignore-user-config`, 연결 앱·플러그인 끔, 프로젝트 문서 0, 전역 AGENTS.md 거절, Claude `--restricted --safe-mode` |
| 예산 | 0자 실패는 회차를 환급한다 | 예약은 환불하지 않는다 |
| 검토 불변식 | 기본 프로필에서 기계 판독이 꺼진다 | [`tools/check_frontier_protocol.py`](../../../tools/check_frontier_protocol.py)가 자기 검토·봉인 전 검토·라운드 상한·투표 승격을 CI에서 검사한다 |

## 3. 지금 넣을 것

### N1. Codex 참여자에 사용자 훅이 끼어들지 못하게 한다

- **왜:** codex-peek는 자기 Codex 훅이 `codex exec --ephemeral` 실행에서도 발화해 프롬프트를 막았다고 적었다(`bridge/contract-lib.js:1958-1963`). DML Codex 참여자는 인증 때문에 실제 사용자 홈을 쓰는데, `hooks.json`은 보지 않는다(core·app·tools에서 `git grep hooks.json` 0건). `--ignore-user-config`가 훅까지 막는지는 확인되지 않았다.
- **무엇을:** [`core/adapters.py`](../../../core/adapters.py) `codex_global_instructions`의 거절 대상에 `~/.codex/hooks.json`을 더한다. 파일이 있으면 실행 전에 거절한다(호출 0). 크기 0 예외는 두지 않는다. 그런 관측이 없다.
- **언제:** 2026-10-26 재관측 직전 PR. 참여자 argv가 바뀌지 않으므로 판(revision)도 그대로다.
- **나중:** 참여자 표면 조회에 `hooks/list`를 더하는 일은 모델 없이 한 번 확인한 뒤로 미룬다.

### N2. 개발 교차검토 절차를 협업 규칙에 몇 줄로 고정한다

- **왜:** [카드 시범](../../experiments/2026-09-25-card-pilot/README.md)에서 실제 사건이 났다. #58은 로그인 셸이 아니라 `codex`를 못 찾았고, 전체 시험의 종료 상태를 tail로 걸러 놓쳤다. #66은 추론 강도가 기본값 none이라 "지적 없음"이 약한 근거가 됐다. codex-peek도 끊긴 호출을 다시 보내 같은 검증이 3중으로 돌았고, 명령 글자만 보던 판정을 폐기했다.
- **무엇을:** [협업 규칙](../../COLLABORATION.md) 교차검토 부분에 다음을 넣는다.
  - 추론 강도를 반드시 적는다. 강도가 none이거나 기록이 없는 "지적 없음"은 완료 근거가 아니다.
  - 종료 코드와 결과 파일을 파이프 없이 직접 본다.
  - 끊겨도 같은 요청을 다시 보내지 않는다. 결과 파일·프로세스부터 확인한다.
  - 검토한 커밋 SHA를 PR에 남긴다. head가 바뀌면 그 검토는 낡은 것이다.
  - 로그인 셸 주의는 SETUP 링크만 건다.
- **조건:** 7절 5번대로 같은 양을 뺀다.
- **하지 않는 것:** 검토 도구는 "절차를 따르고도 같은 실수가 두 번째로 기록될 때" 만든다. 만들면 성공 판정은 `core.adapters.interpret`를 그대로 쓴다. codex-peek의 exit 0 + 답 있음 판정은 DML보다 약하다.

### N3. 작업 상태 판정의 기본값을 "사람 몫"으로 — PR #101(카드 #99) 위에서

- **이미 된 것:** [PR #101](https://github.com/inlight37-design/decision-model_lab/pull/101)의 `app/roles.py` `task_projection`이 옛 `runStatus`의 순서 틈 두 가지를 이미 막는다.
  - 모델이 도는 동안 '붙여넣기 대기'가 가려지던 틈.
  - 합성이 종료 미확인이어도 '공개됨'으로 보이던 틈.
- **남은 것 두 가지:**
  - 마지막 `else`가 `working`이라, **목록에 없는 상태가 자동 진행으로 보인다.** codex-peek 원칙(`src/extension.ts:694-732`, 미지 사유 = 사람 몫)대로 '확인 필요'(my_turn)로 바꾼다.
  - 재시작 뒤 멈춘(paused) queued가 '작업 중'으로 보인다.
- **추가 확인:** 옛 `runStatus`(`app/static/index.html`)는 #101 뒤에도 남는다. 같은 판정을 두 곳에 두지 않는지 확인한다.

### N4. 로컬 검사를 한 명령으로 — 다음에 인계 6절이나 CI를 고칠 때

- **왜:** #58의 tail 사건. [SETUP](../../SETUP.md)에 경고가 있지만 사람이 기억해야만 지켜진다(7절 3번).
- **무엇을:** 인계 6절의 검사를 단계마다 실행해 종료 코드를 모으는 명령 하나를 둔다.
  - 하나라도 실패하면 0이 아닌 코드로 끝나고, 요약 한 줄을 쓴다.
  - 인계 6절 목록은 이 한 줄로 줄여 문서 예산을 돌려받는다.
- **하지 않는 것:** codex-peek식 Stop 훅·영수증 파일은 넣지 않는다.

## 4. 해당 단계가 올 때 완료 조건으로 흡수할 것

### B(실제 모델 선택)

- 허용 목록 밖 (adapter, model)은 `plan()`에서 거절한다. 호출 0이고, 다른 모델로 조용히 바꾸지 않는다(O14).
  - codex-peek 교훈: 과금 담당을 **골랐다는 것을 곧 자동 실행 동의로 기록하지 않는다.** 호출 직전에 다시 대조한다(`bridge/map-enrich.js:1755-1759`).
- 추론 강도는 요청값과 보고값을 따로 둔다. 보고가 없으면 "미보고"로 둔다.
- 재시도·합성을 포함한 **모든** 실제 호출 경로가 모델·강도를 싣는지 시험한다.
  - codex-peek 사고: 재확인 호출 하나가 인자를 빠뜨려 기본 모델로 조용히 강등됐다(`codex-bridge.js:1893-1894`).

### C(일반 팀원·담당별 자료)

- 시도 시작 사건에 그 역할이 받은 자료 목록을 싣는다(이름·sha256·바이트·종류: 원문/지도/AI 요약/기존 답). AI 요약만 받은 결과를 원자료 독립 검토로 올리지 않는 기계적 근거다(RB-02).
  - codex-peek 원리: 보낸 발췌 안의 인용만 근거로 인정한다(`bridge/map-enrich.js:1829-1850`).
- 결정론 자료 지도: 모델 없이 md 제목·줄 위치·크기·해시만 만들고, "참고 — 경계 아님"으로 표시한다.
- 새 입력 경로는 인증 값 모양(sk-, AIza, gh*_, github_pat_, JWT, PRIVATE KEY 머리)이면 저장·전송 전에 거절한다. bearer는 과매칭이라 뺀다.

### D(상위 모델·다듬기)

- 승인 멱등: 제안 행을 조건부 전이로 승인하고, 두 번째 승인은 기존 run_id를 돌려준다. 별도 actions 표는 필요 없다.
- 상위 모델의 사용자 질문은 사건(제안/응답)으로만 한다. **기계 상태가 사용자 질문을 자동으로 만들지 않는다.** codex-peek는 이 방향을 두 번 채택했다가 두 번 되돌렸다.
- 다시 물을 때 직전 거절 이유는 닫힌 분류 코드로만 싣는다. 모델 원문을 재주입하지 않는다(`bridge/enrich-calls.js:34-53`).
- 자동 연쇄가 생기면 그때 승인 단위 절대 마감과 작업 단위 호출 미리보기를 본다.

### E(공개 뒤 교차검토)·build_review

- **검토를 받았다는 기록은 완료가 아니다.** 완료는 판정 통과 또는 마감 기록이다.
- 판독 불가 검토를 "지적 0"으로 보이지 않는다. 판정 줄과 지적 목록이 어긋나면 보류로 둔다.
- 지적마다 처분 한 줄: 수용 / 근거 있는 반박(파일:줄·시험) / 다음 카드 / 사용자 판단. 반박 재료(범위·완료 조건)는 반박하는 쪽 화면에 함께 둔다.
  - 근거: codex-peek 실측에서 처분 706행 중 반박은 1행이었다(`docs/REJUDGE-AUTHORITY-DESIGN.md:21`, 저자 문서 주장).
- 회차 상한은 기본 1(D13)이다. 상한에 닿았는데 마지막 판정이 통과가 아니면 '완료'가 아니다.
- 검토자 권한 제한은 코드가 계산할 수 있는 사실(라운드 유형·인용 여부)에만 건다. "범위 밖이면 스스로 낮춰라"는 구조는 1,057건 중 0건 작동했다(같은 문서 :22).
- 상태 이름은 새로 만들지 않는다. `check_frontier_protocol`·contracts v0.2의 기존 어휘를 쓴다.

## 5. 가져오지 말 것

| 항목 | 이유 |
|---|---|
| **codex-peek 설치** | `install.js`가 사용자 전역 `~/.claude/settings.json`에 훅 6개를 넣는다(`install.js:41, 101-108`). 그중 `codex-guard`가 `codex exec ...` 직접 호출을 막아 사용자의 Codex 위임 방식이 막힌다(`codex-guard.js:22-26`). Codex 훅은 ephemeral exec에서도 발화한다(N1). |

| 매 턴 계약·규칙 주입 | 참여자에게는 문맥 통제 위반이라 재관측이 필요하다. 개발 세션에는 AGENTS·CLAUDE·카드에 이은 네 번째 사본이 된다. |
| 수칙서·기억 승격·정리 담당·수칙 선별 LLM | 자동 상신으로 수칙서가 74항이 돼 선별이 잠겼고 0항으로 비웠다(`docs/RULEBOOK-SIMPLIFICATION-DESIGN.md:13-27`). "개발용 기억을 참여자에 연결하지 않는다"와도 충돌한다. |
| Project MAP·자동 의미 보강 | MAP 계열만 코드 약 1.6만 줄, 시험 약 1.3만 줄이고 설계 검증이 단계마다 8~22왕복이었다. 보강 LLM이 스스로 확신도를 올릴 수 있다. |
| 3트랙 LLM 정찰·플랜 게이트 | 작업마다 LLM 호출이 는다. 근거는 자기 저장소 소급 측정뿐이고, 그 측정기에도 결함이 있었다. |

| 내구 job worker·파일 잠금 층, 0자 실패 환급 | 사람이 정리해야 하는 정지 상태가 늘어난다. DML은 controller + SQLite, 환불 없음으로 이미 해결했다. |
| 근거 재확인 호출·읽기 흔적 추정 | 원 세션에 되물어야 하는데 DML은 세션을 남기지 않는다. 저자도 "원리상 완결 불가"로 결론 냈다. |
| DeepSeek API 경로 | 구독 CLI 원칙과 충돌하고 키를 평문 저장한다. |
| 표시 경로의 부수효과, CLI 비공개 세션 파일 파싱 | 화면 갱신이 쓰기·프로세스 기동·LLM 재점검을 일으킨다. 봉인 중 '생성 중' 추정은 봉인 원칙에 어긋난다. |

## 6. 교훈 (codex-peek 실패 기록)

1. **실행 영수증은 통과가 아니다.** "받았다"와 "통과했다"를 한 파일에 담으면 섞인다.
2. **"성공 응답을 받았다"로 판정한다.** 첫 판은 명령 글자만 보고 echo도 통과시켰다.
3. **권한 제한은 판정받는 쪽의 자기신고에 걸면 작동하지 않는다.**
4. **수용이 가장 싼 경로면 반박이 사라진다.**
5. **지원 환경을 선언하지 않으면 검토가 폭주한다.** "희귀 경합도 blocker" 한 조항으로 11라운드가 돌았고, 그중 일부는 앞 라운드가 요구한 방어 코드의 결함이었다.
6. **교훈을 규칙으로 자동 상신하면 규칙이 폭주한다.** 규칙 자격은 이력이 아니라 성격이다. DML의 규칙 추가 다섯 질문이 옳고, 빼기 경로가 더 필요하다.
7. **fail-closed도 실측으로 보정한다.**
8. **파일로 죽음에 안전한 잠금을 새로 발명하지 않는다.**
9. **같은 규칙을 두 벌 두면 조용히 갈라진다.** 인용 검사는 한 곳에 둔다.
10. **인계 문서는 크기 상한이 없으면 멈춘다.** 저자의 HANDOFF.md는 5주 만에 약 196KB가 되어 갱신이 끊겼다.
11. **반례마다 규칙을 덧대면 과잉 방어가 된다.** 가져올 때는 "규칙 한 문장 + 순수 함수 + 시험"으로 줄인다.
12. **측정 조건을 실사용 조건과 맞춘다.** 저자의 A/B 측정기는 한동안 기억이 빈 채로 재고 있었다.

## 7. 남은 사용자 판단

- **권고가 있는 사용자 판단 항목은 세션이 권고대로 진행하고 보고만 해도 되는지.** 인계 3절 표에 권고가 붙은 판단이 여럿 쌓여 있다. codex-peek 결정 장부의 원칙("기본값이 있으면 세션이 닫고 보고한다")을 가져온 제안이다. 사용자가 답하기 전에는 인계에 반영하지 않는다.
