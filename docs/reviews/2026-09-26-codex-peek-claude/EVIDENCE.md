# 근거 — codex-peek 독립 해체분석 (claude)

[README](README.md)의 방법과 근거를 둔다. 줄 번호는 codex-peek `eb7cec1da0b13d2765eaab770c58d177024f423e`, DML `435ba02f50d287f62dce7512a0ceae9b9c2f164b` 기준이다.

## 1. 방법

- **읽기:** 두 저장소를 읽기 전용으로 clone했다. 쓰기·checkout·npm install·모델 CLI 호출은 금지했다.
- **흐름:** 한 세션이 여러 하위 에이전트를 나눠 돌렸다.
  1. **정독 13갈래**
     - codex-peek 10갈래: 브릿지·호출 경로, 검증 거버넌스, 계약 라이브러리, 기억·권위·정리 담당, 정찰·범위, Project MAP, 자동 보강·자기치유, 확장 UI, 시험·CI·릴리스·이력, 게시글 주장·벤치
     - DML 3갈래: 현재 코드, 원칙·계획, 과거 외부 도구 평가
  2. **적용안 5관점:** 제품 오케스트레이션, 근거·검증 무결성, 저장소 개발 과정, 경제성·화면, 레드팀(가져오면 안 되는 것). 후보 49개를 병합해 32개가 됐다.
  3. **후보마다 3관점 반박 검증.** 기본 자세는 반박이다.
     - 원천: codex-peek 코드가 설명대로인가
     - 적합: DML에 이미 있는가, 사용자 확정 사항·금지 사항과 충돌하는가
     - 가치: DML에서 실제로 되풀이된 문제를 푸는가, 더 단순한 대안은 없는가
     - 셋 중 둘이 버림이면 탈락이다.
  4. **누락 점검:** 한 번 돌려 후보 4개(X01–X04)를 더했고, 같은 3관점으로 검증했다.
  5. **리더 대조:** 결과를 종합하기 전에 핵심 주장을 원본 코드에서 다시 대조했다(2절).
- **검증 결과:** 탈락은 1개(C24)였다. 나머지도 세 관점 대부분이 "범위를 줄여 수정"이었다. README는 줄인 형태만 싣는다. 검증 원문(후보별 정정 사항)은 분량 때문에 세션 로컬 기록에만 있다.
- **독립성:** `chatgpt/codex-peek-review-20260926`(PR #102)와 PR #103의 내용은 열지 않았다. 경로 충돌을 피하려고 바뀐 파일 이름만 봤다.

## 4. 검증에서 드러난 초안의 사실 오류 (다시 꺼낼 때 주의)

- **"DML에 검토 모드가 없다"는 앱·core 기준으로만 맞다.** 검토 역할·자기 검토 거절·라운드 상한·봉인 뒤 검토는 이미 `tools/check_frontier_protocol.py`와 contracts v0.2에 있다. E 단계는 이 어휘를 쓴다.
- **"작업 상태 한 줄이 없다"는 틀렸다.** 옛 `runStatus`가 있고, PR #101이 `task_projection`을 더한다.
- **`--ephemeral --sandbox read-only`는 codex-peek 정찰 경로의 인자다.** 검증 경로는 `exec resume`이라 이 인자가 없다. DML 개발 검토에 쓸 권한 인자는 `core.adapters.codex_permissions`를 따라야 한다(K46: 옛 `--sandbox`와 권한 profile을 함께 주지 않는다).
- **codex-peek의 회차 상한·입장 심사·지적 장부는 모두 조건부다.** 기본 설정(integrity 프로필, 상한 무제한)에서는 꺼져 있다. "codex-peek가 이렇게 막는다"는 서술은 opt-in 조건을 함께 적어야 한다.
- **codex-peek 정리 담당은 "다른 회사 세션"이 아니다.** 구현자 대화 맥락 없이 장부만 읽는 별도 실행이고, 기본 폴백은 같은 회사(Claude CLI)다.
