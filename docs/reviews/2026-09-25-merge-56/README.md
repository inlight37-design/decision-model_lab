## 3. 정정 — N1: Projects는 내 PC에서도 스레드를 돌릴 수 있다

#56은 원문 조사의 "스레드는 클라우드 또는 원격 연결한 내 PC"가 현재 문서와 맞지 않는다고 적었다([출처 대조](../2026-09-25-workflow-evaluation/EVIDENCE.md)의 원문 대조 표, [README](../2026-09-25-workflow-evaluation/README.md) 1절·4절 표). 이 세션이 읽은 영어 원문([Projects](https://code.claude.com/docs/en/claude-projects))은 다르다.

- 스레드는 보통 클라우드 세션이지만, 내 컴퓨터에만 있는 것이 필요한 작업은 Remote Control로 그 스레드를 내 컴퓨터에서 돌리게 할 수 있다.
- 내 PC에서 사용자가 직접 시작한 세션은 프로젝트에 넣을 수 없다. 프로젝트가 내 PC에 닿는 길은 Remote Control로 스레드를 거기서 돌리는 것 하나다.
- 조건: 작업할 폴더를 Remote Control로 연결한다(데스크톱 앱 설정에서 켜거나, 그 폴더에서 `claude remote-control`을 띄워 둔다). 그 기기는 Claude Code 2.1.280 이상이어야 하고, claude.ai의 신뢰 기기 요구 설정이 켜져 있으면 안 된다.

#56이 읽은 번체 중국어판에는 이 문장들이 없다. 번역판이 옛 판이었다 — #56이 스스로 적어 둔 "번역판 시차 가능성"이 실제로 일어났다. 그러므로 원문 조사의 "원격 연결 스레드"는 맞았다. #56의 "로컬 세션은 편입할 수 없다"는 그 자체로 맞지만, 이를 "우리 PC 작업에는 쓸 수 없다"로 넓힌 부분이 틀렸다. 문맥이 넘친 스레드의 조건부 이어가기(R05의 다른 부분)는 영어판에서도 같다.

남는 것: 이 계정에 Projects가 열렸는지, WSL에서 Remote Control이 되는지는 모른다. aux-pc-wsl의 기록된 설치판(2.1.280)은 버전 조건에 맞지만 Remote Control을 켜 보지는 않았다. Projects는 Claude만 쓰므로 Codex 작업을 조정하지 못한다는 원문의 한계는 그대로다. 날짜가 붙은 #56 문서는 고치지 않고 [검토 색인](../README.md)에 적었다.

## 4. 보탠 주의

- **N2 — App Server는 실험 기능이다.** 같은 공식 문서가 app-server 명령과 WebSocket 전송을 실험 기능으로, 운영용 작업에는 지원하지 않는다고 적는다. 작업 자동화나 CI에는 Codex SDK를 쓰라고 한다. 우리는 새 SDK를 더하지 않으므로(인계 4절), 수퍼바이저가 Codex에 일을 보내는 통로는 지금처럼 `codex exec`가 현실적이다(인계 2절 12). #56의 "exec 우선 유지" 권고를 더 강하게 뒷받침한다. 이 앱은 app-server를 모델 없는 계정 조회에만 쓴다.
- **N3 — Vibe Kanban은 서비스 종료를 알렸다.** 원본 README 맨 위에 적혀 있다. 2026-04-10 발표에 따르면 오픈소스는 공동체 유지로 남고 원격 서비스는 30일 뒤 닫혔다. #56의 P1 표처럼 화면 동선의 참고로만 쓰고 설치 후보로 보지 않는다.
- **N4 — Symphony 소개 글은 이 세션에서 열리지 않았다(403).** 참조 구현이며 제품으로 계속 유지하지 않는다는 점, 첫 판이 tmux 안의 Codex 세션이었다는 점은 2차 보도로만 확인했다. 홍보 수치는 근거로 쓰지 않는다(#56과 같다). 명세(R08)는 직접 읽었다.

## 5. N5 — 원문과의 차이는 표보다 작다

#56 README 1절 표의 "원문의 표현" 몇 줄은 원문보다 세게 옮겨졌다.

| #56이 옮긴 원문 | 원문 조사가 실제로 한 말 |
|---|---|
| 자동 요약에 맡기므로 새 세션 인계 기능은 필요 없다 | "차면 자동으로 새 세션에 넘기는" 기능을 따로 만들 필요가 없다. 세션이 바뀌어도 살아야 할 것은 카드에 남겨 새 세션이 이어받는다(5절·8절) |
| 작업 하나 = 세션 하나 = PR 하나 | 같은 줄에 "넘치면 카드에 중간 상태를 적고 새 세션이 이어받는다". 세션마다 새 PR을 만들라는 뜻은 없다 |
| 명세·계획·코드를 매번 각각 검토한다 | "한 번씩" — 끝없는 검토를 막는 멈춤 규칙이었다 |
| 파일에 저장하므로 컨텍스트를 아낀다 | 7절이 이미 "항상 읽는 부분은 짧게, 지난 이력은 링크로 두고 필요할 때만"을 권했다 |

그래서 두 문서는 다음 걸음 — 작은 카드 시범, 구현자 한 명, 도구 설치 없음 — 에서 같다. #56이 새로 더한 것은 (1) AI 판단과 실행 관리 프로그램의 분리, (2) 작업·시도·세션 번호의 분리와 안전한 인계 순서, (3) 자동 실행을 만들 때의 모델 없는 시험 목록, (4) Beads 저장 구조와 Projects 조건부 이어가기의 확인, (5) 위험도에 따른 검토 깊이다. (2)·(3)은 자동 실행을 만들 때 필요하다. 수동 시범에는 인계 전 커밋·push, 짧은 체크포인트, 같은 작업을 두 세션이 잡지 않는 것만 있으면 된다.
