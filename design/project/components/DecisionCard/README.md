# DecisionCard

첫 화면. 한 번의 협업 실행 결과를 **결정 하나** 단위로 보여준다.

## 왜 주장 목록이 아니라 결정인가

claim × evidence 전체를 펼치고 싶은 유혹이 크지만, 그렇게 만든 인터페이스의 사용자 실험 결과가 있다. PaperTrail(CHI 2026)은 신뢰를 유의하게 낮추는 데는 성공했으나(p=.015) **사용성 평가가 유의하게 나빠졌고(p=.026)**, 정작 사용자가 결과물을 고치는 양은 달라지지 않았다(p=.313). 저자들은 시간 압박 아래 인터페이스가 "어수선해진다"고 적었다.

즉 **근거를 다 보여주는 것과 사람이 더 나은 판단을 하는 것은 다른 일이다.** 그래서 이 카드는 세 층으로 나눈다.

| 층 | 내용 | 상태 |
|---|---|---|
| 1 | 검토 중인 결정 · 현재 권고 · **뒤집을 조건** | 항상 펼침 |
| 2 | 근거 요약과 미해결 항목 · 다음 검사 | 항상 보이되 요약만 |
| 3 | 주장별 대조표 · 참여자 원문 · 검사 기록 | 눌렀을 때 |

1층에 결론만 두는 것이 아니다. **결정을 바꿀 수 있는 것**을 1층에 두고 바꾸지 않는 것을 내린다. 중요한 미해결 반례는 언제나 1층으로 올라온다.

## 규칙

- **"뒤집을 조건"은 생략할 수 없는 슬롯이다.** 채울 수 없으면 그 결정은 아직 카드가 될 수 없다. 빈 채로 렌더링하지 않는다.
- **coverage 막대는 비율이지 점수가 아니다.** 네 disposition의 구성만 보여준다. 하나의 품질 점수로 합치지 않는다.
- **`unresolved`가 있으면 카드 상태는 `qualified`다.** `REVIEW_READY`로 라벨링할 수 없다. checker의 report gate와 같은 규칙이다.
- **합성이 없는 결과도 유효한 카드다.** 합성 호출이 실패했거나 예산이 부족하면 이미 모인 원문과 반례를 그대로 보여준다. 다만 "합성 완료"로 표시하지 않는다.
- **모델 이름을 제목에 넣지 않는다.** 누가 말했는지보다 어느 판단이 어떤 근거에 기대는지가 앞이다. 참여자는 3층에서 확인한다.

## 소비자가 제공하는 것

`{ question, recommendation, overturnedBy[], coverage, unresolved[], nextChecks[], status }`.
카드는 disposition을 스스로 계산하지 않는다 — controller의 report를 표시할 뿐이다.
