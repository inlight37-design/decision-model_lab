# BudgetMeter

외부 호출 예산의 **소진량**을 보여주는 막대. 진척도가 아니다.

## 진척도가 아닌 이유

진행률 막대는 "곧 끝난다"를 암시한다. 여기서 막대가 차오른다는 것은 **남은 시도가 줄어든다**는 뜻이다. 7칸 중 5칸이 찼다면 좋은 신호가 아니라 예산의 71%를 썼다는 뜻이고, 그 중 실패한 호출도 포함된다.

그래서 초록으로 채우지 않는다. 중립색으로 채우고 상한 근처에서만 경고색으로 바뀐다.

## 규칙

- **실패·거절·timeout도 칸을 차지한다.** checker가 `len(calls)`로 세므로 화면도 같게 센다. 실패한 시도를 빼고 보여주면 예산이 실제보다 많아 보인다.
- **`unknown`은 별도 칸이다.** 종료가 확인되지 않은 호출은 성공도 실패도 아니다. 파선 칸으로 그리고 소비를 0으로 적지 않는다.
- **내부 turn은 여기 없다.** 이 막대는 **외부 invocation 수**다. native 하네스 한 실행 안의 model/tool turn은 별도로 관측하며 같은 막대에 섞지 않는다. 7 invocations가 7 model turns를 뜻하지 않는다.
- **planner와 extractor도 센다.** 별도 LLM 호출로 계획하거나 주장을 추출했다면 그것도 칸이다. 7-call 계획에 planner를 더하면 8-call 계획이다.
- **cash와 quota를 합치지 않는다.** 추가 청구(원)와 구독 한도 소모는 단위가 다르다. 한 숫자로 합쳐 가짜 가격을 만들지 않는다.

## 소비자가 제공하는 것

`{ used, cap, breakdown: { succeeded, failed, unknown }, rounds: { used, cap } }`. 관측하지 못한 사용량은 `null`로 오며 컴포넌트가 `0`으로 바꾸지 않는다.
