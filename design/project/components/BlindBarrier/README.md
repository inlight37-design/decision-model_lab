# BlindBarrier

초기 독립 답변 단계에서 참여자별 제출 상태만 보여주는 줄. **내용은 그리지 않는다.**

다른 어떤 에이전트 도구에도 없는 화면이다. 병렬 실행기는 실행 중인 출력을 실시간으로 나란히 보여주는 것이 목적이지만, 여기서는 그것이 정확히 금지된다 — 전원이 제출하기 전에 한 답이 보이면 blind가 아니다.

## 규칙

- **닫혀 있는 동안 내용을 흐리게 처리하지 않는다.** 블러 처리한 텍스트는 복사할 수 있고 스크린샷에 남는다. 아예 렌더링하지 않는다.
- **제출 여부와 실행 상태만 보여준다.** 길이, 토큰 수, 미리보기 한 줄, 어느 것도 새어 나가면 안 된다. 답변의 길이조차 단서다.
- **공개 시점은 controller가 정한다.** 화면에 "지금 열기" 버튼을 두지 않는다. 정족수가 찼을 때 controller가 상태를 바꾸고 화면은 그것을 따른다.
- **실패한 참여자를 조용히 빼지 않는다.** 3인 구성에서 1인이 실패하면 "2인 완료"가 아니라 "요청한 3인 구성이 완료되지 않음"으로 표시한다.
- **오염 경로를 함께 표시한다.** 공유 memory, project instruction, 검색 캐시처럼 완전히 통제하지 못한 영향이 있으면 그 참여자에 표시한다. `--bare` 류의 플래그로 문맥을 비웠는데 그 대가로 구독 경로를 벗어났다면 그것도 여기 표시한다(F25).

## 소비자가 제공하는 것

참여자별 `{ id, provider, state, contamination[] }`. 초안 본문은 이 컴포넌트에 전달조차 하지 않는다 — 전달하지 않는 것이 가장 확실한 차단이다.
